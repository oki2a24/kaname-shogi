# ShogiHome接続手順書

この文書は、このリポジトリの `kaname-shogi` をShogiHomeのUSIエンジンとして登録・選択し、依頼された一局を行うための手順です。登録先、アプリの版、画面上の設定は毎回確認してください。過去の設定値を現在も有効だとみなさず、画面上の表示を優先します。

ShogiHomeの画面名は版によって変わることがあります。各項目に公式資料へのリンクを添えています。公式資料の説明と画面が異なる場合は操作を止め、表示中の版と画面を確認してください。

## このエンジンが扱える開始局面

現在の `kaname-shogi` はUSIの `position startpos moves <1手以上>` だけを扱います。`position startpos` 単独、`position sfen ...`、駒落ちや平手初期局面以外から始まる棋譜には対応していません。詳しい現在仕様は[USIエンジンの一手応答](knowledge/usi-engine-response.md)を参照してください。

- 新規の平手対局では、人間が先手、`kaname-shogi` が後手になる条件で始めます。初手前の局面をエンジンへ渡す必要がある条件では開始しません。
- KIFからの再開は、平手初期局面からの指し手履歴があり、対象手が1手以上進んだ棋譜に限ります。盤面だけをSFENで指定する棋譜、駒落ち、平手初期局面以外を開始位置にする棋譜は開始しません。
- 依頼された局面がこの範囲外なら、未対応の条件を説明して停止します。エンジンの対応拡張が必要な場合は、コード変更の理由と別計画を提示して明示承認を待ちます。

## この手順で守ること

- ユーザーが依頼した接続・対局だけを行います。「接続確認」だけの依頼では対局を始めません。対局を依頼された場合も、依頼された一局だけを対象にします。
- 先後、開始局面、持ち時間、対局数など、依頼から特定できない条件は開始前に確認します。
- ShogiHomeのエンジン登録、Ponder、ログ出力はアプリに残る設定です。Codexがこれらを変更する必要がある場合は、変更前の値と具体的な変更内容を示してユーザーの明示承認を得ます。ログ採取は依頼された場合に限ります。
- 開いている棋譜に未保存の変更がある場合は、先に保存先を確認します。別名保存で保全できるまで棋譜を読み替えたり閉じたりしません。
- ShogiHomeのプロンプト欄へUSIコマンドを手入力しません。通信はログで、稼働状態は監視画面で確認します。

## 開始前の確認

1. ShogiHomeの版と利用するアプリ画面を確認します。手順書に書かれたメニュー名が画面と異なる場合は、推測で操作せず止まります。
2. 依頼内容を確認します。
   - 接続確認だけか、対局を行うのか
   - 平手の新規対局か、KIFの指定局面から再開するのか
   - 先後、持ち時間・秒読み、対局数
   - USIログ採取が必要か
3. 既存の対局・エンジンセッションが動いていないかを確認します。稼働中のセッションがある場合は止めたり置き換えたりせず、対象を確認します。
4. 棋譜に未保存の変更がある場合は、ユーザーの確認を得て保存します。元の棋譜を残したい場合は「名前を付けて保存」でコピーを作ります。

## エンジンの登録と設定

### 起動ファイルを確認する

このリポジトリにある起動ランチャーは `kaname-shogi-usi` です。macOS/Linuxではスクリプトのシバンと実行権限が必要です。ShogiHome公式の[スクリプト・インタプリタ型エンジンの注意](https://github.com/sunfish-shogi/shogihome/wiki/%E3%82%B7%E3%82%A7%E3%83%AB%E3%82%B9%E3%82%AF%E3%83%AA%E3%83%97%E3%83%88%E3%82%84%E3%82%A4%E3%83%B3%E3%82%BF%E3%83%97%E3%83%AA%E3%82%BF%E5%9E%8B%E8%A8%80%E8%AA%9E%E3%81%A7%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%B3%E3%82%92%E5%AE%9F%E8%A1%8C%E3%81%97%E3%81%9F%E3%81%84%E6%96%B9%E3%81%B8)を参照してください。

登録先は、現在使うチェックアウト内の実ファイルにします。2026-10-04に確認した登録パスは次のとおりです。

```text
/Users/oki2a24/kaname-shogi/kaname-shogi-usi
```

このパスは当時の環境で確認した値です。ブランチや作業場所が変わった後も有効とは限りません。ShogiHomeの登録画面に表示された実際のパスが現在のチェックアウトと一致するか確認してください。アーカイブ済みworktreeや削除済みディレクトリを指す場合は使用しません。

### ShogiHomeに登録する

1. 既存の棋譜・設定を確認してから、右上の「エンジン設定」を開きます。
2. 登録済み一覧の起動ファイルを確認します。現在のランチャーと一致するエンジンがある場合は、その登録を使います。
3. 未登録、または別のチェックアウトを指している場合は、変更の許可を得てから「追加」を押し、現在のチェックアウトにある `kaname-shogi-usi` を選択します。
4. エンジン設定で利用用途に「対局」を含めます。
5. 「設定」を開き、`USI_Ponder` がOFFであることを確認します。現在のエンジンは `go ponder` に対応していません。ONの場合はそのまま対局を始めず、設定変更の許可を得ます。
6. 登録内容を確認し、「保存して閉じる」を押します。登録に成功したことと、一覧の起動ファイルが意図したパスであることを画面で確かめます。

エンジン設定画面の開き方、追加、用途、保存については、ShogiHome公式の[エンジン登録手順](https://github.com/sunfish-shogi/shogihome/wiki/%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%B3%E7%99%BB%E9%8C%B2%E6%89%8B%E9%A0%86)を参照してください。公式資料では追加しただけでは保存されず、「保存して閉じる」が必要と説明されています。

## 通常の対局

1. 未保存の棋譜がないことと、既存のエンジンセッションが動いていないことを確認します。
2. ユーザーが指定した先後・局面・時間設定・対局数を確認します。複数局や連続対局は依頼に含まれる場合だけ選びます。
3. 画面右上のエンジン機能メニューから「対局」→「ローカル対局」を選びます。ShogiHome公式の[エンジンを使う機能の操作方法](https://github.com/sunfish-shogi/shogihome/wiki/%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%B3%E3%82%92%E4%BD%BF%E3%81%86%E6%A9%9F%E8%83%BD%E3%81%AE%E6%93%8D%E4%BD%9C%E6%96%B9%E6%B3%95)は、通常の対局では「ローカル対局」を選ぶよう案内しています。
4. 対局条件と選択エンジンを確認します。先手・後手の表示、盤面、持ち時間、Ponder OFFを開始前に読み合わせます。
5. 開始後は盤面、時計、エンジンの応答を確認します。開始局面や時計が依頼と違う、エンジンが起動しない、想定外の操作が起きた場合は、直ちに追加操作せず「停止して確認する条件」に従います。
6. 終局後、結果と盤面を確認します。必要なら依頼された棋譜だけを保存し、依頼された対局が終了したことを報告します。追加の一局は始めません。

## KIFの指定局面から再開する

KIFを開いただけでは、棋譜の最終手が開始局面に選択されているとは限りません。以下の選択手順は、macOS版ShogiHome 1.28.1で37手のKIFを扱った際の観察です。画面表示と対象手を毎回確かめてください。

1. 現在の棋譜が未保存なら、元の棋譜を別名保存して保全します。
2. ファイルメニューからKIFを読み込みます。公式の[基本的な操作方法](https://github.com/sunfish-shogi/shogihome/wiki/%E5%9F%BA%E6%9C%AC%E7%9A%84%E3%81%AA%E6%93%8D%E4%BD%9C%E6%96%B9%E6%B3%95)では、ファイルメニューから棋譜を読み込み・保存できると説明されています。
3. 棋譜一覧でユーザー指定の対象手を明示的に選択します。対象手が「37手目」のように指定されていれば、その行が選択表示になったことを確認します。
4. 盤面が選択した手の後の局面と一致するか、次に指す側が依頼内容と一致するか確認します。
5. 「現在の局面」から始める操作を選びます。ボタン・メニュー名が異なる場合や、画面上の局面が対象手と一致しない場合は開始せず確認します。
6. 開始直後に、棋譜カーソル・盤面・手番・時計を再確認します。時計が予期せず動いたり、局面が違ったりした場合はその試行を対象の対局として扱わず、停止して状況を確認します。

2026-10-04の37手局面では、37手目を選ばず開始した試行で人間側の時計が動いたため中断しました。棋譜に戻って対象手を明示選択し、盤面を確認してから「現在の局面」を選び直すと、意図した位置で対局を開始できました。この一例を全バージョンの画面操作の保証とは扱いません。

## USIログを採取する場合

ログ採取はユーザーが依頼した場合に限ります。ShogiHome公式Wikiによると、アプリログ・CSAログ・USIログは初期状態で無効で、それぞれ別ファイルに出力されます。設定を有効にした後はアプリの再起動が必要です。アプリを起動するたびに新しいログファイルが作られ、最初のログが出るまではファイルが作られない場合があります。

### 採取前

1. USI、CSA、アプリログそれぞれの現在値を記録します。ログ設定に変更がある場合は、変更前の値と必要なログ種別をユーザーに示し、明示承認を得ます。
2. 他の未保存棋譜・稼働中セッションがないことを確認し、調査対象を一局または指定の接続確認に絞ります。
3. 必要な場合だけUSIログを有効にし、設定を保存してShogiHomeを再起動します。再起動後に設定値を確認します。

### 採取・確認

1. 承認された範囲の接続または対局だけを行います。
2. USIログを通信の主証拠として読みます。監視画面は稼働中セッション・現在状態の補助確認に使います。ログの保存先を開くには、公式資料にある「各種フォルダ」→「ログ」を使えます。macOSでの標準保存先は `~/Library/Logs/{app name}/` です。
3. プロンプト機能では履歴を表示できますが、手入力したコマンドが予期しない動作を招く可能性があります。コマンドは送信せず、ログと表示だけを読みます。

### 設定を戻す

1. 調査が終わったら、ログ設定を採取前に記録した値へ戻します。
2. 設定を保存してShogiHomeを再起動します。
3. 再起動後、各ログ設定が開始前の値に戻ったこと、調査対象のエンジンセッションが終了したことを確認します。
4. 確認したログの保存場所、採取した範囲、復帰した設定値を報告します。ログファイルを共有・削除・外部送信する場合は、その操作について別途許可を得ます。

公式の[開発者向け機能の使い方](https://github.com/sunfish-shogi/shogihome/wiki/%E9%96%8B%E7%99%BA%E8%80%85%E5%90%91%E3%81%91%E6%A9%9F%E8%83%BD%E3%81%AE%E4%BD%BF%E3%81%84%E6%96%B9)には、ログの既定値、アプリ再起動、保存先、監視画面、プロンプトについて説明があります。画面上のログ設定名やメニューはアプリの版に合わせて確認してください。

### 37手局面で観察された通信の例

2026-10-04、ShogiHome 1.28.1で、37手局面を選んで開始した一局では、エンジンが `bestmove resign` を返し、その後ShogiHomeが `gameover lose` を送り、さらに別の終了コマンドとして `quit` を送りました。エンジンの手番で自動投了したこの一例の記録です。`gameover lose` と `quit` は別のコマンドであり、この順序を他の局面・対局・終局理由の必須要件とはしません。

## 停止して確認する条件

次の場合は操作を続けず、状態と画面をユーザーへ報告します。

- 起動ランチャーのパスが現在のチェックアウトと一致しない、ファイルがない、または起動できない
- `USI_Ponder` がONで、設定変更がまだ承認されていない
- 依頼された先後・時間設定・対局数・開始局面を特定できない
- KIFの対象手を明示できない、または選択手・盤面・手番が一致しない
- 時計が予期せず動く、画面表示と想定結果が食い違う、エンジンが停止しない
- ログ採取を依頼されていて、必要な設定変更の承認がない、または開始前の値を確認できない場合（ログ不要なら通常手順を続けます）
- 手動コマンド、強制終了、設定変更など、承認済み手順の範囲を超える操作が必要になった

ShogiHomeの監視機能では実行中のUSIセッションと最新状態を確認できます。画面上で対局が終了していてもセッションが残る場合があるため、稼働セッションがなくなったことを見てから終了を報告します。プロンプトへの手動入力や強制終了が必要に見える場合は、実行前に具体的な理由・対象を説明して承認を待ちます。
