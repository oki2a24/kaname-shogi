# リポジトリ基盤整理ロードマップ

作成日：2026-09-27

## 目的

CLIで弱くても対局でき、明示的な保存・読込もできるという最初の目標を達成した時点で、次の機能追加の前にリポジトリの土台を整理する。人間が現在地と利用方法を読み取りやすく、AIが確定仕様・経緯・作業規律を誤解なく参照しやすい文書構成を目指す。同時に、プログラムコードとユニットテストの責務・依存・規模を点検し、必要な改善だけを小テーマに分けて実施する。

これは一回で大規模に書き換える作業ではない。各テーマを別セッションで一つずつ扱い、調査・設計・承認・実装・検証・レビューの境界を守る。

## 全体ロードマップ

- [x] **テーマ1：文書構成の棚卸しと入口設計**
  - 対象：README、`docs/learning/`、`docs/knowledge/`、`docs/plans/`、`docs/resume.md`、引き継ぎ文書。
  - GREEN：各文書種別の役割・読み手・入口・更新契機を棚卸しし、重複・古さ・見つけにくさを根拠付きで記録する。改善候補を小さく分け、実施対象は本人の承認後に決める。コード・テストは変更しない。
  - 規律：`brainstorming`、必要なら一次資料確認、設計書承認。実装を行う場合だけ`writing-plans`とTDDを使う。
  - 完了：2026-09-27。設計仕様は [文書構成の棚卸しと入口設計](plans/2026-09-27-repository-document-navigation-design.md)、確認問題・回答・検証は [第43回学習記録](learning/43-document-structure-audit.md) を参照する。コードとテストは変更せず、設計書と学習記録の承認、最後の理解確認まで完了した。

- [ ] **テーマ2：文書ナビゲーションの最小改善**（実装・レビュー完了、main取り込み待ち）
  - 前提：テーマ1の設計合意。
  - GREEN：承認された入口・索引・リンク・再開案内だけを更新し、READMEから現在の使い方・学習記録・確定知識・次テーマへ迷わず到達できる。内容の意味を変えず、リンク検査と差分レビューを行う。
  - 規律：設計・計画承認後に、必要最小限の文書変更、独立レビュー、Gitコミット。
  - 開始：2026-09-27。実装手順と検証方法は [文書ナビゲーションの最小改善 実装計画](plans/2026-09-27-repository-document-navigation.md) を参照する。
  - 実装：2026-09-27。人間向けのREADMEと [文書索引](README.md) を整理し、[第44回学習記録](learning/44-document-navigation.md) に検証とレビューを記録した。初回レビューのCritical 1件とMinor 1件を修正し、再レビューはCritical・Important・Minorすべて0件。main取り込み、取り込み先検証、最後の理解確認は未完了である。

- [ ] **テーマ3：コードとユニットテストの構造レビュー**
  - 対象：`kaname_shogi/` と `tests/` の責務、公開インターフェース、テスト分類、重複、内部実装への依存。
  - GREEN：モジュールとテストの対応表、保守上の懸念、変更不要の根拠、必要なら候補となる小リファクタリングを記録する。振る舞いは変更しない。
  - 規律：調査と設計を分け、リファクタリングは承認済みの別テーマにしない限り行わない。

- [ ] **テーマ4以降：承認済みの小さなリファクタリング**
  - 対象：テーマ3で必要性が確認された箇所だけ。一回につき一つの責務境界、または一つのテスト構造を扱う。
  - GREEN：公開動作を変えず、失敗する回帰テストまたは既存テストで保護し、最小変更、全検証、独立レビュー、main取り込みを完了する。
  - 規律：`test-driven-development`、`requesting-code-review`、`verification-before-completion`。

## 今回は扱わないこと

SFEN、USI、探索、評価関数、将棋規則の追加、自動保存、JSON形式の変更は、基盤整理の結果にかかわらず別テーマとして扱う。基盤整理を理由に、未選定の機能を先取りしない。

## 進行の確認方法

各テーマの開始時に、この文書の対象チェックボックスを「進行中」とし、完了時に検証結果・設計書・学習記録への参照を追記する。次のテーマへ進むのは、前テーマの学習記録、レビュー、検証、main取り込み、理解確認がそろった後である。
