### 時計と対局管理の承認済み範囲

- コンピュータ側だけ計時する。人間側の時計は将来候補。コンピュータ同士は同じ初期条件から先後独立した残り時間を持つ。
- 対局前に整数の分・秒で入力し、同時0を拒否。空入力は持ち時間10分＋秒読み30秒。本人が選んだ暫定既定値であり、実測に基づく最適値・将棋共通の標準としない。
- 既存の設定ローダーと予算計算操作を使い、JSON設定を一回読み、実行中保持する。現行のresponse_margin_ms=2000は設定の現在値で、2秒を新しい固定ルールとして複製しない。人間同士に予算JSONの読込を要求しない。
- 計時原点はコンピュータ手番処理の開始、予算準備・探索用局面取得の前。終点は探索返却直後。表示・指し手適用とその再検査は計時に含めない。USIのgo読取り原点と役割は対応するが、通信やGUIのイベント順まで同一ではない。
- 残り持ち時間は整数nsを保持し、予算へだけ整数msで渡す。1ms未満を切り捨てると0msとして既存式の秒読み分岐へ入る点を隠さない。予算値の単調減少を保証するという説明はしない。対局時計は保持nsで別判定する。
- 探索の通常停止では既存の合法手を使って続行する。探索予算の上限超過だけでは時間切れ負けにしない。探索返却後、非抑制なら消費時間が開始時残り持ち時間＋秒読み以上で時間切れ負けとし、返された手を適用しない。時間切れ判定は投了・着手より前、抑制は投了・時間切れへ変換しない。詳細は設計の表を使う。
- 秒読みは手ごとに元の設定値を使い、使い残しを持ち越さない。残り5秒＋秒読み30秒から20秒使った後は、次手は持ち時間0秒＋秒読み30秒。
- Ctrl+Cは現行CLIと同じ対局終了。USIのstopと同じ操作にはしない。単一処理の強制中断、探索中の別入力・定期表示、スレッドや送信同期の新設は含まない。人間手番の既存詰み判定は維持する。

### 時計つき保存と承認された再利用境界

時計設定と先後残り時間を一ファイルで保持する外側形式`kaname-shogi-cli-session-v1`を設計した。`game_record`には既存v1棋譜全体、`clock`には初期時間・秒読みmsと先後残りnsを置く。途中の制御・探索結果・絶対時刻は保存しない。既存保存窓口の時点は変えず、コンピュータ同士の探索中保存・自動保存・終局後保存対話を追加しない。

既存の棋譜変換・合法手再生を複製しないため、GameRecordのv1辞書変換・検証再生をファイルI/Oから利用できる公開操作へ分ける追加範囲も全体提示時に明示し、本人の「yes」により承認された。候補名は`to_payload`（辞書を返す操作）・`from_payload`（辞書を検証し棋譜を作る操作）。既存save/loadの契約・v1構造は維持する。共有探索・USIの公開API拡張が承認されたという意味ではない。

新形式の読込は棋譜と時計を全検証してから置き換える。不正な時計情報やI/O失敗では元の双方を保持する。時計情報のない旧v1棋譜は、コンピュータが参加する場合、そのCLI起動時に選んだ初期条件を使い、その旨を表示する。不正な新形式を時計なし旧形式へ変換しない。保存中・閉じている間の時間を減らさない。読込で現在の対局モード・方式は切り替えない。細部の状態・範囲・人間同士での保持は承認済み設計を参照する。
