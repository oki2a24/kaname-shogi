# 第14回実装の設計：持ち駒を打つ基本操作

作成日：2026-09-22

## 目的と範囲

手番側の持ち駒を1枚減らし、空いている盤上のマスへその側の駒として置く。占有マスへの打ちは拒否する。

今回は二歩、行き所のない歩・香・桂、打ち歩詰め、成り、王手・詰み・合法手判定、CLI入力、手数・履歴を扱わない。日本将棋連盟が定める打ち場所の制限のうち、占有マスへの打ちだけを小さく実装する。[日本将棋連盟「駒の動かし方」](https://www.shogi.or.jp/knowledge/shogi/02.php)

## 状態と責務

### `Hand.remove`

`Hand.remove(piece_type)` は、指定した玉以外の基本駒種の枚数を1枚減らす**操作**である。`Hand` は持ち駒の枚数という**データ**の責務にとどめ、盤面・先後・手番は知らない。

- 指定駒種が1枚以上なら、その駒種だけを1枚減らして `None` を返す。
- 指定駒種が0枚、または玉なら `ValueError` を送出し、全ての枚数を変えない。

### `apply_drop`

`apply_drop(position, piece_type, destination)` は、持ち駒を打って局面を一手進める**操作**である。

- `position` は盤面・手番・双方の持ち駒を持つ可変の局面。
- `piece_type` は打つ基本駒種を表す**データ**。
- `destination` は打ち先の筋・段を表す `Square` という**値**。

成功時は、現在の `position.side_to_move` に対応する `Hand` から `piece_type` を1枚減らす。同じ側を所有者とする `Piece(piece_type, side_to_move)` を、空の `destination` へ置く。その後、手番を反対側へ交代する。

盤上移動の `apply_move` は出発マスと移動先候補を扱うため、出発マスのない駒打ちを混ぜない。`apply_drop` を別関数にして、盤上移動と持ち駒からの配置を区別する。

## 失敗時の契約

次の場合は `ValueError` とし、盤面81マス、`side_to_move`、先手・後手双方の全持ち駒枚数を変更しない。

1. 手番側の指定駒種が0枚。
2. `destination` に先手または後手の駒がある。
3. 玉を指定する。

`ValueError` は、引数が型として正しくても、その局面で打てないという無効な指定を表す。既存の `move_piece`、`apply_move`、`Hand.add` と同じ例外にそろえる。CLIやGUIで失敗の種類を使い分ける段階では、専用例外を改めて検討する。

## テスト方針

- 先手・後手それぞれが持ち歩を空の５五へ打つと、その側の持ち駒だけが1枚減り、その側の歩が置かれ、手番が交代することを確認する。
- 持ち駒が0枚、先手駒があるマス、後手駒があるマス、玉の指定を拒否することを確認する。
- 全ての失敗で、盤面・手番・双方の全基本駒種の持ち駒枚数が不変であることを確認する。
- 既存の移動・駒取りテストが維持されることを確認する。
