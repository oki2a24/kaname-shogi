# 空マスへの移動適用の設計

## 目的

候補生成とは別に、盤面上の駒を空いている到着マスへ移す最小の操作を追加する。今回の対象は、出発マスを空にし、到着マスへ同じ駒を置くことだけとする。

## 対象範囲

- 空の出発マスを拒否する。
- 駒のある到着マスを拒否する。
- 出発マスと到着マスが同じ場合を拒否する。
- 検証に成功した場合だけ盤面を変更する。
- 移動方向、候補生成結果、手番、駒取り、持ち駒、成り、王手、合法手判定、詰みは扱わない。

## 用語と責務

- `Square` は筋・段を表す不変の値であり、移動操作ではない。
- `Piece` は駒種と所有者を表す不変の値である。
- `Board` は各マスの駒または空を保持する可変の盤面データである。
- `Position` は `Board` と `side_to_move` を持つ局面である。今回は受け取らず、手番を変更しない。
- `move_piece` は盤面を変更する操作であり、候補生成関数とは責務を分ける。

## 公開インターフェース

```python
def move_piece(board: Board, source: Square, destination: Square) -> None:
    """空いている到着マスへ駒を移動し、盤面を変更する。"""
```

検証をすべて先に行い、成功後に次の2操作を行う。

1. `board.set_piece(source, None)`
2. `board.set_piece(destination, piece)`

不正な入力では `ValueError` を送出し、盤面を変更しない。関数は移動方向を検証しないため、移動先候補の確認は呼び出し側または別の責務とする。

## 判断理由

既存の `Board` は可変な盤として設計され、`set_piece` も配置を変更する操作であるため、今回は `Board` 単位の可変方式を採用する。移動適用を独立関数にすることで、将来、評価・探索で局面を分岐させる必要が生じたときに、不変な盤面または局面を返す方式へ見直しやすくする。

## 確認方法

- 空の盤面で駒を移動し、出発マスが空、到着マスに同じ駒があることを確認する。
- 先後の駒をそれぞれ移動し、`Piece` の値が保持されることを確認する。
- 空の出発マス、占有された到着マス、同一マスを拒否することを確認する。
- 不正入力の前後で81マスすべてが一致することを確認する。
- `Position.side_to_move` を直接変更しないことを、既存の責務分離として確認する。

## 将来の課題

評価・探索を実装する段階で、可変な `Board` を直接変更する方式を、不変な盤面または局面を返す方式へ見直す。
