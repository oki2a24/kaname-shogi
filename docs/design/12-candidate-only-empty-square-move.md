# 第12回実装の設計：移動先候補に合う空マスへだけ移動できること

作成日：2026-09-22

## 目的と範囲

`apply_move(position, source, destination)` が、手番と出発駒の所有者が一致する
だけでなく、出発駒の既存の移動先候補に `destination` が含まれる場合だけ、
空マスへの移動と手番交代を適用するようにする。

今回は候補に含まれる相手駒のマスへの駒取り、持ち駒、成り・不成、王手、
王手放置を避ける合法手判定、詰み、CLI入力、評価、探索を扱わない。

## 状態と責務

- `Position` は可変の盤面 `Board` と、次に指す側 `side_to_move` を持つ局面である。
- `PieceType` は玉・飛車・角・金・銀・桂・香・歩の駒種を表すデータである。
- 各 `*_move_candidates(board, source)` は駒種別の移動先候補を求める操作であり、
  盤面を変更しない。相手駒のマスを候補に含み得る。
- 新しい非公開ヘルパーは、盤上の出発駒の `PieceType` に対応する既存候補関数を選び、
  その候補リストを返す。
- `apply_move` は局面規則として所有者・手番と候補を照合し、成功時だけ盤面移動と
  手番交代を行う。
- `move_piece` は候補照合も手番も知らない、空マスへの盤面移動だけを担当する。

非公開ヘルパーに選択を集めるのは、`apply_move` に8種類の候補計算の詳細を並べず、
公開APIを増やさずに全駒種を扱うためである。候補関数を共通化したり、候補外の詳細な
理由を型で表したりすることは、今回の範囲を超えるため行わない。

## `apply_move` の処理順

1. `source` の駒を読む。
2. 駒があり、その所有者と `position.side_to_move` が異なる場合は `ValueError` を送出する。
3. 駒がある場合、非公開ヘルパーで既存の候補リストを求める。`destination` が含まれない
   場合は `ValueError` を送出する。
4. `move_piece(position.board, source, destination)` を呼ぶ。空出発・占有到着・同一マスは
   既存契約どおり `ValueError` となる。相手駒の候補マスも、今回は占有到着としてここで拒否する。
5. `move_piece` が成功した場合だけ、先手と後手の手番を交代する。

手番・所有者・候補の拒否は盤面変更前に行う。`move_piece` の拒否も変更前の検証であるため、
どの失敗経路でも盤面と手番を変更しない。

## テスト方針

- 全8駒種について、既存候補に含まれる空マスへの `apply_move` が盤面を移し、手番を交代することを確認する。
- 先手歩５五→５六のような候補外の空マスを `ValueError` で拒否し、盤面全81マスと手番が不変であることを確認する。
- 既存の空出発、占有到着、同一マス、所有者不一致の拒否契約を維持する。
- 既存の後手歩の成功テストは、後手の前方である５六を到着マスにして候補照合後も成功することを確認する。
- 対象テストを実装前に実行し、候補外を受け入れてしまうという振る舞い上の失敗を確認してから最小実装を加える。

## 未解決事項

候補に相手駒のマスが含まれる事実と、今回の移動適用ではそのマスを拒否することは、
意図的に併存する。駒取りと持ち駒を学ぶ回で、相手駒を盤面から除き、所有者を変更して
局面に保持する規則を別途設計する。
