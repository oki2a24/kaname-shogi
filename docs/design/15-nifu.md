# 第15回実装の設計：二歩

作成日：2026-09-22

## 目的と範囲

持ち歩を打つとき、打ち先と同じ筋に手番側の未成の歩があれば二歩として拒否する。二歩以外の打ち場所制限を混ぜず、既存の駒打ち操作に小さく追加する。

規則の根拠は、日本将棋連盟が説明する「同じ筋に歩がある時に、もう一枚歩を打つことはできない」という二歩である。同連盟は、と金と同じ筋に歩を打つことは二歩ではないとも説明している。[日本将棋連盟「反則について」](https://www.shogi.or.jp/knowledge/shogi/05.php)

## 状態と責務

### `_has_unpromoted_pawn_on_file`

`_has_unpromoted_pawn_on_file(board, side, file)` は、指定した側の未成の歩が指定筋にあるかを返す非公開の**判定操作**である。

- `board` は調べる配置という可変のデータだが、この操作は変更しない。
- `side` は調べる先手・後手を表す値である。
- `file` は調べる筋を表す1〜9の整数である。公開APIではなく、`apply_drop` が `destination.file` を渡す。
- 1段から9段までを調べ、`PieceType.PAWN` かつ指定側の `Piece` が1枚でもあれば `True`、なければ `False` を返す。

盤面の読み取りと局面変更を分けるため、`apply_drop` 本体に走査を埋め込まない。現在は成り状態が未実装なので、`PieceType.PAWN` を未成の歩とみなす。と金を盤上で表現できる段階で、この判定がと金を除外するよう見直す。

### `apply_drop`

`apply_drop(position, piece_type, destination)` は、既存の引数・戻り値を変えない局面操作である。玉、占有マス、持ち駒不足の既存規則に加え、歩を打つ場合の二歩を検証する。

1. 玉指定と占有マスを既存どおり拒否する。
2. `piece_type` が `PieceType.PAWN` のときだけ、手番側と `destination.file` を使って二歩を判定する。
3. 同じ筋に手番側の未成の歩があれば `ValueError` とする。
4. すべての検証を通過した後にだけ、持ち駒を1枚減らし、駒を配置し、手番を交代する。

これにより、二歩を拒否したときに `Hand.remove` が呼ばれず、盤面・先後双方の持ち駒・手番が不変となる。歩以外の駒打ちでは二歩の判定を行わない。

## 失敗時の契約

二歩となる歩打ちは `ValueError` とし、盤面81マス、`side_to_move`、先手・後手双方の全持ち駒枚数を変更しない。例外の種類は、既存の `apply_drop` が局面で打てない指定に用いる `ValueError` にそろえる。

## テスト方針

- 先手・後手それぞれで、同じ筋に自分の未成の歩があるときの持ち歩打ちを拒否する。
- 二歩の拒否後に、盤面・手番・先後双方の全持ち駒枚数が不変であることを確認する。
- 同じ筋に自分の未成の歩がなければ、既存どおり持ち歩を打てることを確認する。
- 歩以外の持ち駒は、同じ筋に自分の歩があっても二歩を理由に拒否しないことを確認する。
- 既存の全テストを実行する。

## 今回は扱わないこと

行き所のない歩・香・桂、打ち歩詰め、成り・不成、王手・詰み・合法手判定、CLI入力、手数・履歴は扱わない。
