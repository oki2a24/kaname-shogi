# 第13回実装の設計：駒取りと持ち駒の基礎

作成日：2026-09-22

## 目的と範囲

候補に含まれる相手駒のマスを `apply_move(position, source, destination)` の
到着先として受け付け、出発駒を到着先へ移し、取られた駒を指した側の持ち駒へ
加える。これにより、盤上の駒と、盤上にない持ち駒を局面内で区別して保持する。

今回は持ち駒を盤へ打つ操作、打ち場所の制限、成り・不成、成駒を取ったときの
元の駒種への戻し、王手・詰み・合法手判定、手数・履歴、CLI表示・入力、評価、探索を
扱わない。玉を取る操作も扱わず、到着先が相手の玉なら `ValueError` で拒否する。

## 状態と責務

### `Hand`

`Hand` は一方が保持する持ち駒の枚数を表す**可変のデータ**である。先手・後手の
情報、盤上の位置、手番は持たない。歩・香・桂・銀・金・角・飛の各 `PieceType` の
枚数を保持し、次の操作を公開する。

- `count(piece_type)`：指定した駒種の枚数を返す。まだ持っていなければ `0` を返す。
- `add(piece_type)`：指定した駒種を1枚増やす。

玉は持ち駒にならないため、`count` と `add` のどちらも `PieceType.KING` を
`ValueError` で拒否する。`Hand` が駒台という物理的な場所を表すのではなく、
駒台に置かれ得る持ち駒の種類と枚数を表すことを、docstringにも明記する。

`Hand` 自身に `Side` を持たせない。どちらの持ち駒かは局面が決めるため、
`Hand` を単独で枚数の操作として理解・テストできるようにする。

### `Position`

`Position` は既存の `board` と `side_to_move` に加えて、次の2つの `Hand` を持つ。

```text
Position
├─ board         盤上の81マス
├─ side_to_move  次に指す側
├─ sente_hand    先手が保持する持ち駒
└─ gote_hand     後手が保持する持ち駒
```

各 `Position` は独立した2個の `Hand` を生成する。`sente_hand` と `gote_hand` は
初期状態で全駒種0枚とし、異なる局面や先手・後手の間で内部の枚数を共有しない。
第三・第四引数には既定値を用いるため、既存の `Position(board, side_to_move)` の
呼び出しを変更しない。

局面はすでに可変であり、`apply_move` が盤面と手番をその場で変更しているため、
今回の `Hand` も可変にする。将来、探索で複数局面を同時に比較する段階では、
盤面・手番・持ち駒をまとめて不変な局面として返す設計を改めて検討する。

### `apply_move`

`apply_move` は局面を一手進める操作として、手番・所有者・候補照合の後に、
到着先の状態で処理を分ける。

1. 既存どおり出発駒、手番と所有者、移動先候補を照合する。
2. 到着先が空なら、既存の `move_piece` へ委譲する。
3. 到着先が相手駒なら、玉ではないことを確認する。出発駒を出発マスから除き、
   到着マスへ置き、取られた駒の `PieceType` を手番側の `Hand` へ1枚加える。
4. 成功した移動の後だけ、手番を交代する。

今回の `PieceType` は成り状態を持たないため、取られた駒種をそのまま `Hand` に加える。
成駒を取ったときに歩・香・桂・銀・角・飛へ戻す規則は、成りを追加する回で扱う。

盤面・手番・持ち駒を変更する前に、空出発、所有者不一致、候補外、同一マス、
自駒のある到着先、玉取りをすべて拒否する。したがって、失敗時に局面のどの部分も
変更しない。`move_piece` は空マスへの盤面移動専用として変更しない。

## 既存実装との比較と判断

既存の将棋ライブラリも、盤上の駒と持ち駒を別の状態として保持する。

- [python-shogi](https://github.com/gunyarakun/python-shogi/blob/master/shogi/__init__.py) は、
  `pieces_in_hand` を先手・後手それぞれの `Counter` として持ち、
  `add_piece_into_hand` で枚数を増やす。
- [cshogi](https://github.com/TadaoYamaoka/cshogi/blob/master/cshogi/_cshogi.pyx) は、
  盤上の81マスとは別に、両側・7種類の `pieces_in_hand` の枚数を保持する。

本プロジェクトでは、辞書を `Position` に直接置く代わりに、小さな `Hand` を作る。
`Hand` は短く将棋実装で通じる名称であり、日本語のdocstringで「一方の持ち駒」と
明示する。`PiecesInHand` は意味が直接的だが、公開メンバー名として冗長になる。
駒のリストで持つ方式は、枚数を知るたびに数える必要があるため採用しない。

## テスト方針

- 新しい `Hand` は7種類の枚数を0で返し、`add` 後はその駒種だけが1増えることを確認する。
- `Hand` が玉を受け付けず、失敗しても枚数を変更しないことを確認する。
- `Position` の先手・後手の `Hand` と、別々の `Position` の `Hand` が独立していることを確認する。
- 先手・後手それぞれについて、候補内の相手歩を取ると、出発マスが空、到着マスに
  移動した側の歩、指した側の持ち駒に歩1枚、相手側の持ち駒0枚、相手の手番になることを確認する。
- 相手の玉を到着先にした場合と、既存の候補外・所有者不一致・空出発・同一マス・
  自駒の到着先の場合に、盤面81マス、手番、双方の持ち駒が不変であることを確認する。
- 既存の空マスへの移動と候補生成のテストが維持されることを確認する。

## 未解決事項と将来の課題

- 持ち駒を盤へ打つ操作と、その場所の制限は別のテーマで扱う。
- 成り状態を追加した後は、取った成駒を基本駒種へ戻して持ち駒に加える。
- 王手・詰み・合法手判定を導入するとき、玉を取る代わりに王手と詰みを判定する。
- 可変の局面を直接変更する設計は、評価・探索を学ぶ段階で見直す。
