# 玉の移動先候補：設計

## 承認済みの対象範囲

`king_move_candidates(board, source)`を追加し、成る前の玉について移動先候補を返す。玉の周囲8方向への1マス移動、盤外、自駒、相手駒、盤面不変性を扱う。

王手、王手放置を避ける合法手判定、詰み、実際の移動、駒取り、持ち駒、成り、他の駒との処理共有は対象外とする。

## 入力と戻り値

- `board`：盤面のデータ。出発マスの駒の所有者を読む。
- `source`：玉がある出発マスの値。
- 戻り値：盤内かつ自駒でない到着先を含む、新しい`list[Square]`。
- 出発マスが空、または玉以外なら`ValueError`とする。候補なしと呼び出しの誤りを区別する。

## 方向と候補順

玉は先後に関係なく周囲8方向へ1マス進む。候補順は、盤面上で次の固定順とする。

1. 上：`(0, -1)`
2. 右上：`(-1, -1)`
3. 右：`(-1, 0)`
4. 右下：`(-1, +1)`
5. 下：`(0, +1)`
6. 左下：`(+1, +1)`
7. 左：`(+1, 0)`
8. 左上：`(+1, -1)`

ここでの「上・右」は盤面の筋・段に基づく固定順であり、玉の所有者によって反転しない。順序は再現性と読みやすさのためで、指し手の優先順位ではない。

## 候補判定

各方向の到着先について、まず筋・段が1〜9の盤内かを確認する。盤外なら除外する。盤内なら到着先の駒を調べ、自駒なら除外し、空マスまたは相手駒なら候補に追加する。

候補生成は盤面を変更しない。相手駒を取り除かず、出発マスの玉も動かさない。`Position.side_to_move`は受け取らず、手番で候補を制限しない。

## 処理共有

今回の学習範囲を保つため、8方向の計算と候補判定は玉専用の新しい関数内で完結させる。金・銀などの既存関数や、全駒共通の候補生成へ先行して抽象化しない。

## 確認方法

`tests/test_movegen.py`に次を追加する。

- 空マス・玉以外の出発点が`ValueError`になること
- 開いた盤面で先手・後手とも同じ8方向を固定順に返すこと
- 盤端・四隅で盤外候補を除外すること
- 自駒の到着先を除外し、相手駒の到着先を含めること
- 候補計算後に盤面と手番が変わらないこと
- 呼び出しごとに独立したリストを返すこと

## 設計判断

玉は金・銀と同じく1マス駒だが、先後による前方反転を持たない。今回の目的はこの違いを明確に理解することなので、既存関数との共通化は行わず、玉専用の8方向データと直接判定を採用する。
