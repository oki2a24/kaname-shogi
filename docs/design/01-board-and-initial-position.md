# 第1回実装の設計：盤・駒・手番・初期配置

## 状態と目的

2026-09-13に設計を承認。本文は実装前の仕様であり、実装済みであることを示すものではない。実装は別途進める。

起動すると平手の初期配置と「手番：先手」を表示して終了するCLIを作る。処理が必要な理由を説明できることを優先する。判断の経緯は[第4回の学習記録](../learning/04-first-implementation-design.md)に残す。

## 対象範囲

- 9×9の盤面、先手・後手、基本8種類の駒。
- 初期配置の40枚の生成と先手の手番設定。
- 筋・段、所有者、空マスを区別できるCLI表示。

入力操作、駒の移動判定、駒取り、持ち駒、成りの適用、王手・詰み・合法手判定、SFEN、USI、探索は対象外とする。手番の反転も今回は実装しない。

## 言語と実行環境

Pythonを採用し、型注釈を付ける。テストには標準の `unittest` を使う。外部パッケージは使わず、依存がないことはREADMEに明記する。空の `requirements.txt` は作らない。

Pythonの具体的な使用バージョンは、実装開始時に環境を確認し、動作確認したバージョンをREADMEに記録する。

## データ構造

| 名前 | 保持するもの・責務 | 変更の扱い |
| --- | --- | --- |
| `Square` | 筋 `file` と段 `rank`。各値は整数の1〜9 | `dataclass(frozen=True)` |
| `Side` | `SENTE` と `GOTE` | `Enum` |
| `PieceType` | `KING`、`ROOK`、`BISHOP`、`GOLD`、`SILVER`、`KNIGHT`、`LANCE`、`PAWN` | `Enum` |
| `Piece` | `piece_type` と所有者 `side` | `dataclass(frozen=True)` |
| `Board` | 9×9の二次元リスト。各マスは `Piece` または `None` | 可変 |
| `Position` | `board` と手番 `side_to_move` | 可変 |

`Board` は配置を、`Position` は盤面と手番を表す。`Piece` に成り状態はまだ持たせず、成りを扱う回に追加する。成りや所有者の変更が必要になった場合は、新しい `Piece` の値で表す方針とする。

`frozen=True` は属性の再代入を防ぐが、内包するリストを不変にする機能ではない。今回は局面全体の不変性を保証しない。型注釈も実行時の検証の代わりにはならない。

## 座標と盤面操作

第3回の理解を引き継ぎ、左下原点・0始まりを採用する。

```text
x = 9 - file
y = 9 - rank
参照先 = cells[y][x]
```

| マス | `(x, y)` |
| --- | --- |
| ９九（左下） | `(0, 0)` |
| １九（右下） | `(8, 0)` |
| ９一（左上） | `(0, 8)` |
| １一（右上） | `(8, 8)` |

変換は `Square.to_indices()` に集約する。`Board` の取得・配置操作は `Square` を受け取り、呼び出し側では内部リストを直接操作しない。配置操作は指定マスへの設定であり、将棋の合法手判定ではない。

`Square` の生成時に範囲外・非整数を `ValueError` で拒否する。Pythonでは整数の一種として扱われる真偽値も座標としては拒否する。負の添字による意図しない参照を防ぐ。

各盤面と各行は独立したリストとして作り、一つのマスの変更が別の行や別の盤面へ影響しないようにする。

## 初期配置の生成

`create_initial_position()` が空盤を作り、[第3回の配置表](../knowledge/03-initial-setup-and-coordinates.md#初期配置)に従って40枚を置き、手番を `Side.SENTE` に設定して `Position` を返す。

歩と最奥段には単純な繰り返しを使う。先手の角８八・飛２八、後手の飛８二・角２二は筋段を明記して配置する。各呼び出しで独立した盤面を返す。

## CLI表示と処理の流れ

```text
CLI起動 → create_initial_position() → render_position(position) → 標準出力
```

`render_position()` は文字列を返し、CLIの入口だけが出力する。表示は先手視点で筋9→1、段一→九の順に全81マスをたどる。内部座標は表示側で計算せず、`Square` を使って盤面を参照する。

- 先頭に「手番：先手」と凡例「+：先手、-：後手」を表示する。
- 先手の駒は `+歩`、後手の駒は `-歩` のように表す。空マスは `・`。
- 筋の見出しと各行の段を表示する。
- 今回の表示上の約束として先手の `KING` は「王」、後手は「玉」。内部の駒種は同じ。
- 色や端末制御には依存しない。

## 検証方針

| 対象 | 検証内容 |
| --- | --- |
| 座標 | 四隅、81マスの変換先の範囲と一意性、不正な座標の拒否 |
| 不変な値 | `Square` と `Piece` の属性再代入が拒否されること |
| 盤面 | 空盤81マス、配置と取得、別のマス・行・盤面への影響がないこと |
| 初期配置 | 独立した期待配置表と全81マスを照合し、空マスも確認 |
| 枚数と手番 | 各側20枚、歩各9枚、玉各1枚、合計40枚、手番が先手 |
| 表示 | 筋段の向き、所有者、空マス、手番を含む全文一致 |
| CLI | 実コマンドの正常終了と初期盤面の出力 |

期待配置表は生成関数から作らず、学習済みの配置表を基に用意する。実装と同じ誤りを期待値に複製しない。

## 将来の互換性

内部クラス名や配列順を既存エンジンと一致させることは、USI互換の条件ではない。内部の意味を明確に保ち、外部形式への変換を境界に集約する。

- `SENTE/GOTE` とSFENの手番 `b/w` を対応付ける。
- 筋段とUSI座標を対応付ける。例えば７六は `7f`。
- SFEN対応時には、盤面・手番に加えて持ち駒・手数を扱う。
- 成り状態を導入する際は、SFENの成り表記へ変換できるようにする。
- 人向けCLI表示とUSI通信出力は別の処理にする。

これらの変換器や将来のフィールドは今回実装しない。
