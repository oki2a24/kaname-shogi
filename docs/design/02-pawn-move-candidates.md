# 第2回実装の設計：歩の移動先候補

## 目的と承認

第6回で学んだ範囲の候補計算を実装する。2026-09-13に、以下のAPIとテスト方針を利用者が承認した。[学習記録](../learning/06-pawn-move-candidates.md)の盤外除外の方針を引き継ぐ。

## インターフェース

```python
pawn_move_candidates(board: Board, source: Square) -> list[Square]
```

`pawn` は歩、`move_candidates` は移動候補を意味する操作。`board` は調べる盤面、`source` は出発マス。戻り値は移動先のマスを0個または1個含む新しいリスト。

`Square` または `None` を返す案も考えたが、候補なしを空リストで表し、将来複数の移動先を扱う場合にも同じ形で読めるリストを採用する。今回は移動先のみを返し、指し手の型や成り情報を追加しない。

## 所有者と手番の扱い

出発マスの `Piece.side` から先後を読む。別の `Side` 引数を設けると、盤上の所有者と引数が食い違う状態が生じるため、情報源を一つにする。

利用者は「Square(7, 7)を渡し、そこにPieceがあれば、そのオブジェクトが先後を持つので引数は不要」と説明し、理解を確認した。

`Position.side_to_move` は次に指す側であり、駒の所有者とは別の情報。今回は手番で制限せず、先手番でも後手の歩を調べられる。関数にPosition全体を渡さず、Boardだけを渡す。

## 通常の結果と呼び出しの誤り

| 状況 | 結果 |
| --- | --- |
| 出発マスが空、または歩以外 | `ValueError` |
| 一歩前が盤外 | `[]` |
| 一歩前に自駒 | `[]` |
| 一歩前が空、または相手駒 | `[移動先のSquare]` |

出発マスの誤りを空リストと混同しない。Boardと検証済みSquare、および正しい列挙型を持つPieceを渡すことは呼び出し側の契約とし、任意の異常なPythonオブジェクトへの追加の型検証は設けない。

## 処理順

1. `board.piece_at(source)` で駒を読み、歩でなければ例外にする。
2. 所有者により先手は段−1、後手は段＋1を計算する。筋は変えない。
3. 段が1〜9でなければ空リストを返す。通常の盤外判定に例外捕捉は使わない。
4. 盤内の段で移動先の `Square` を生成する。
5. 移動先が同じ所有者の駒なら空リスト、それ以外なら移動先一つを返す。

## 範囲の境界

盤面・手番を変更しない。移動、駒取り、持ち駒、成り、王手、合法手確定、探索、USI/SFENは対象外。相手の玉のマスを含むことも玉取りを合法と認めるものではない。成りが必要な段への到達も、今回返すのは移動先のみであって不成の合法手ではない。

歩専用関数の採用は、全駒に専用関数を作る決定ではない。次の駒を学んだ際に共通点を見て、必要な処理だけ共有する。

テストを先に書き、未実装による失敗を確認し、最小実装後に全テストを実行する。

| 検証 | 具体例・目的 |
| --- | --- |
| 先後と筋の維持 | 先手７七→７六、後手７三→７四、１筋と９筋も確認 |
| 盤外 | 先手一段・後手九段は例外なしで空リスト |
| 盤内の端 | 先手二段→一段、後手八段→九段を除外しない |
| 占有 | 空・自駒・相手駒を先後両側で確認 |
| 不正な出発点 | 空と歩以外の全駒種をValueErrorにする |
| 盤面不変性 | 空・自駒・相手駒・盤外の各場合で、呼び出し前後の全81マスを比較 |
| 手番 | 同じ盤で手番を変えても同じ結果になり、呼び出しが手番を変えない |

盤外テストの最奥段の未成の歩は防御的な入力例であり、合法局面の例ではない。
