## 最終目標

前テーマのShogiHome実機確認では、時計付きの探索から一応答が返ることは観測できたが、探索中に通常停止を送って応答させる確認は成立しなかった。次のテーマでは、**通常停止を改めて確認するための条件だけ**を作成し、独立レビューして本人へ提示する。

条件案では、停止を送りたい対象の探索が実際に継続していることをどう確認するか、候補局面をどう選ぶか、時計・停止の操作手順、ログ上の成功/未達判定、有限の終了条件、異常時の中止と復帰、本人が結果を判断する材料、未検証事項を具体化する。狙いは通常停止の代表例を一回成立させて観測する条件であり、全局面の停止保証・時間内応答保証・棋力比較・係数最適化ではない。

今回の対象は条件作成・レビュー・提示まで。エンジン起動、ShogiHome等の実機操作、設定変更、ログ採取、計測、対局、コード/テスト/設定変更は始めない。条件案を提示した後は本人の明示承認を待ち、実施開始とmain取り込みはそれぞれ別承認とする。前テーマで得たG2実施承認を再試行へ流用しない。

### G2の実測結果と通常停止未達の理由

- 2026-10-13、ShogiHome 1.28.2でC1 SFENをTwoPlyMaterialに渡し、`go btime 0 wtime 0 byoyomi 8000` を送った。目標4500ms/上限6000msの条件で、`bestmove 6f5g+` が4.516秒後に一度返り、合法性と棋譜の５七角上成反映を確認した。
- ところが応答後、人間側の8秒秒読み中に予定した通常停止操作が間に合わなかった。ゲームは人間側の切れ負け（`gameover win`）で終了し、探索中の通常`stop`送信と、それに続く応答はログ・画面で確認できなかった。これはエンジンの秒読み超過や停止成功ではなく、操作の遅れによる運用上の未達である。
- 従って確認済みは「この一局面・この条件で一度合法手が返った」ことだけ。通常停止、内部の停止因果、他局面の時間保証は未確認。本人は最終理解確認に「両方の確認完了前に手が帰ってきたから」と回答し、応答と通常停止は別条件だと理解した。この回答と補足は学習記録に保存済み。
- 本人は部分結果の記録を承認したが、再試行は承認していない。さらにmain統合と最後の理解確認は完了した。今回の新テーマは残った通常停止の条件設計であり、物理再試行そのものではない。
