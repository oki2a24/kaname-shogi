# 第25回：駒取りと持ち駒の基礎

実施日：2026-09-22

## 目的

相手駒を取った直後の盤上と盤外の状態を区別し、その最小の状態を局面へ追加して、候補内の駒取りだけを実装する。

## ルールの確認

[日本将棋連盟「駒の動かし方」](https://www.shogi.or.jp/knowledge/shogi/02.php)で、相手駒のあるマスへ進むとその駒を取ること、取った駒を持ち駒と呼ぶこと、持ち駒は原則として空きマスへ打てることを確認した。

### 第1問

先手の歩が５五、後手の歩が５四にあるとき、先手が５五の歩で５四の後手歩を取った直後の５五、５四、先手の持ち駒の歩はどうなるか。

本人の回答：５五は空き、５四には先手の歩がある状態になる。先手の持ち駒の「歩」は54にある状態になる。

補足：５五が空き、先手の歩が５四へ移るところまでは正しい。５四にあるのは盤上の先手の歩である。取られた後手の歩は盤上から取り除かれ、先手の持ち駒になるため、盤上のマスにはない。

### 再確認

５四の先手の歩と、先手の持ち駒になった歩は、それぞれ盤上のどこにあるか。

本人の回答：５四の先手の歩は盤上の54にある、先手の持ち駒になった歩は盤上にない。

補足：正しい。盤面にある駒と、先手が盤外で保持する持ち駒を区別できている。

### 振り返り

本人の振り返り：ありません。

## 設計の合意

`Hand` は「一方の持ち駒の枚数」というデータで、物理的な駒台そのものではない。取った駒だけを保持し、先後・盤面・手番を持たない可変オブジェクトにする。`Position` が先手・後手それぞれの `Hand` を保持する。玉は `Hand` に入れず、玉取りは `ValueError` で拒否する。

外部実装も調べ、python-shogi と cshogi が盤面と持ち駒を分けて保持していることを参考にした。今回は必要な操作を `count` と `add` に限定し、将来の駒打ちや不変化は先取りしないことを合意した。詳細は[設計書](../design/13-capture-and-hands.md)、手順は[実装計画](../plans/2026-09-22-capture-and-hands.md)を参照する。

## 実装記録

### Red

1. `Hand` と `Position.sente_hand` / `gote_hand` のテストを追加した。`Hand` が未実装であること、`Position` に持ち駒属性がないことを振る舞いのアサーションとして確認した。
2. 候補内の相手歩を取る先後二通りと玉取り拒否のテストを追加した。既存実装では占有到着を `ValueError: 到着マスは空にしてください` と拒否し、玉取り専用の `玉は取れません` ではないため失敗した。読み込みエラーではない。
3. レビューで、`Hand` の内部枚数を生成引数から渡せないこと、失敗経路で双方の全基本駒種の持ち駒が不変であることを追加テストで確認した。

### Green と Refactor

- `Hand` を追加し、`Position` に独立した `sente_hand` と `gote_hand` を既定値で追加した。既存の `Position(board, side_to_move)` は維持した。
- `apply_move` は候補照合後、空マスなら既存の `move_piece` に委譲し、相手の玉以外なら盤面を更新して手番側の `Hand` に追加する分岐を最小で追加した。
- `move_piece` は「空マスへの盤面操作」のままとし、局面規則を増やなかった。持ち駒の打ち・成り・王手判定は追加していない。
- Refactorとして、`Hand` の内部辞書を `init=False, repr=False` にして外部から渡せないようにした。失敗時不変性のテストは、玉以外の全駒種を比較する補助操作へまとめた。生産コードの追加Refactorは不要と判断した。

## レビュー

`Hand` と `Position` のレビューではCritical/Importantはなく、内部辞書を初期化引数として公開しないMinor指摘を反映した。駒取り分岐のレビューでもCritical/Importantはなく、失敗時の持ち駒比較を全基本駒種へ広げるMinor指摘を反映した。最終レビューもCritical/Importantはなく、`apply_move` のdocstringに駒取り成功時の持ち駒変更を明記するMinor指摘を反映した。
