## 資料と実機観測

### USI一次資料

[The Universal Shogi Interface](https://hgm.nubati.net/usi.html) はUSI原案に将棋所GUIの拡張を加えた説明である。標準入出力による行単位通信、`usi` に対する識別行と `usiok`、`isready` に対する `readyok`、`position` での局面通知、`go` に対する `bestmove` を確認した。`go` には、候補手を制限する `searchmoves`、深さ・探索ノード数・詰み探索を指定する引数、時計情報、`infinite`、`ponder` などがある。未知のコマンドやトークンを無視する説明もある。

資料のすべてのコマンドを実装要件にはしていない。今回は時計値を使わず即時応答し、意味を実装しない既知の検索条件 `searchmoves` / `depth` / `nodes` / `mate` / `infinite` / `ponder` を未対応エラーにする。未知の `go` トークンと未知コマンドは読み飛ばす。`bestmove resign` と `gameover` は同資料の将棋所系拡張として記載されており、本テーマでは選択して利用した。

### ShogiHomeの使い捨てプローブで観測したこと

[第54回の記録](54-usi-shogihome-connection-scope.md)には、Mac版ShogiHome 1.28.1と使い捨てプローブの一例がある。受信したコマンドは次のとおり。

```text
usi
setoption name USI_Hash value 32
setoption name USI_Ponder value true
isready
usinewgame
position startpos moves 7g7f
go btime 591199 wtime 600000 byoyomi 30000
```

プローブは `usi` に識別行と `usiok`、`isready` に `readyok` を返し、`bestmove resign` の後にShogiHomeが `gameover lose` と `quit` を送った。この一例は実機観測であり、合法な一手を返した場合のGUI挙動を示さない。

[第56回](56-usi-position-replay.md)では設計時に通常手を複数含む `position startpos moves ...` の例を追加観測した。成り・駒打ち・SFEN、検索停止・先読み、今回の実装を使った対局は実機で確認していない。今回のプロセステストはローカルの標準入出力契約を検証するもので、ShogiHomeとの互換性確認ではない。

## 実装と検証

- `kaname_shogi/usi_engine.py` に `run_usi_engine(input_fn, output_fn, rng=None)` と `main()` を追加した。最新局面は関数内で保持し、新しい `position` で置き換え、`usinewgame` で未設定に戻す。
- `go` は既存 `legal_moves` / `choose_weak_move` / `format_usi_move` に委譲する。選んだ手を内部局面へ適用しない。合法手がなければ `bestmove resign` を返す。
- `usi` / `isready` の応答、`setoption` / `gameover` / 未知コマンドの読み飛ばし、未知 `go` トークンの読み飛ばし、`quit` / EOFの終了を実装した。時計引数は使わず、既知の未対応検索条件は `ValueError` にする。
- 標準入出力入口はUSI応答ごとに改行を書いてflushする。`ValueError` の診断は標準エラーだけに出し、終了コード1を返す。
- 専用テストは関数境界11件と実プロセス2件。実プロセステストはバイナリpipe、selector、`os.read`、有限タイムアウトを使い、改行なし・flushされない応答を検出できるようにした。
- TDDの最初は未作成モジュールのimport失敗を確認した。その後、何もしない関数スタブでは11テストメソッドに対し17件の失敗（0 errors）を確認した。失敗は必要な応答の欠落、`ValueError` 未送出、投了応答の欠落、乱数生成器未生成、`quit` 未読込など、未実装の振る舞いによるものだった。
- 実装後は関数テスト11/11件が成功し、全体275/275件が成功した。
- 実行入口を加える前のプロセステストは2件とも失敗した。一方は最初の識別行が届く前にstdoutが閉じ、もう一方は不正局面でも終了コード0だった。
