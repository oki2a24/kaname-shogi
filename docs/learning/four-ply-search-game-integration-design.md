# 全幅4手とαβ枝刈り4手の対局接続設計

## 学習の目的

開発用比較として実装済みの全幅読みとαβ枝刈りを、既存の三つの対局方式を残したまま通常対局CLIとUSIで選べる形にする設計を学ぶ。反復深化・時計・停止・通信応答の責任を分け、設計承認が実装承認を意味しないことを確認する。

## 確認した背景

先行する設計・実装では、全幅とαβの指定深さ探索、および両方式の開発用比較は深さ2〜4まで扱う。比較は同一局面・評価・合法手順序を使い、全幅が根候補の確定評価を持ち、αβは確定評価と最善手を返す。開始側視点の駒得評価と詰み優先を使う。実装済みでも、当初合意では開発用の比較にとどまり、通常対局・USIの方式選択、時間制御との接続、対局棋力や応答時間は対象外だった。

時間制御付き反復深化は別の設計・実装で `COMPLETE`、`NO_LEGAL_MOVE`、`STOPPED`、`SUPPRESSED` を返す。通常停止は最後の完了手、なければ合法予備手を持ち、抑制は応答手なしとする。探索部品は通信せず、USI接続側が送信前に抑制を再確認して一度だけ応答する。単一処理を強制停止できず、時間内応答を保証しない。

現行の技術上の差分は、共通探索本体 `core.search_controlled` が `pruning=False` を受け付ける一方、公開された制御付き反復の一深さ探索先がαβに固定され、全幅の公開制御付き入口がないこと。薄い全幅ラッパーと共通反復管理の呼出し先選択で接続できる構成とし、全幅を比較専用に限定する根拠とはしない。

## 設計提示と本人の承認

2026-10-19、両方式を通常対局CLI・USIで選べるようにし、既存三方式を維持する設計案を提示した。各手1→4の反復深化、USIのみ既存時計制御を使うこと、CLIは時計なし、通常停止と抑制の結果、探索データ返却とUSI送信責務を明記した。共通制御付き探索本体を使う全幅接続案、設計確認の観点、実行時間等の未検証事項、実装計画とコード変更を含めない境界も提示した。

本人の明示回答は「yes」。上記を含む[設計仕様](../plans/2026-10-19-four-ply-search-game-integration-design.md)全体が承認された。実装計画、コード・テスト・設定変更、実装、接続、時間保証は承認・実施されていない。

## 確認方法と検出したい誤り

ここに記すのは後続実装時に確認すべき設計観点であり、テストを作成・実行した記録ではない。`docs/knowledge/test-coverage-review.md` と個人観察 `~/.codex/observations/test-driven-development.md` を事前に確認し、対象契約、独立した期待値、代表ケース、局所テストと全体テスト、未検証範囲を分けて整理した。

- 選択メニュー・USI宣言に新二方式を追加し、既存三方式を維持する。表示方式と探索の対応ずれを検出する。
- 小さな人工探索木で深さ1〜4の期待評価・最善手を手計算し、全幅とαβを独立に照合する。二方式同士の一致だけに正解を依存させない。
- 一手ごとに探索深さが1→2→3→4となり、次のコンピュータ手で1に戻ることを確認する。
- 制御を決定的に操作し、深さ完了前の予備手、途中停止時の最後の完了手、抑制時の手なしと記録保持を区別する。
- USIで通常停止時の合法応答が最大一回、抑制時の送信が0回、合法手なしが既存の投了表現となることを確認する。
- CLIの一局固定、USIの最初の `go` 固定と `usinewgame` 後の反映、既存三方式・時計・停止の回帰を個別と全体で確認する。

これらで全局面の正しさやすべての競合順序を証明できず、実時間保証・全OSでの応答・ShogiHomeでの実戦・棋力向上も検証できない。全幅四手の実対局待ち時間、実際の深さ到達、期限内応答は後続の実測課題である。

## 振り返りと未決事項

選択寿命を既存方式に合わせることで、対局途中の方式切替を設計に持ち込まずに済む。時間制御はUSIへ限定し、CLIの時計機構を別途設計しない。停止時は探索結果とUSI送信の境界を守ることで、通常停止に必要な合法手と応答抑制の「送らない」を両立する。

USIの新しい表示値・内部識別子、実装タスクの分け方、全幅四手の実測性能は未確定である。表示名・識別子は[設計仕様](../plans/2026-10-19-four-ply-search-game-integration-design.md)で候補を示し、具体値は実装計画で確定する。実装計画の作成は今回の範囲外であり、開始していない。
