## 要点・契約・実際の変更

`Position` は盤面・手番・持ち駒のデータ、`SfenPosition` は局面と手数のデータ。`format_sfen` はSFENへ書き出す操作、`run_usi_engine` はUSIコマンドを処理する操作、`choose_move` は手を選ぶ操作、`parse_usi_move` は応答の一手をデータへ読む操作である。

指定1メソッドを追加した。教材は先手９九玉・５五飛、後手１一玉・５三金・５四歩、先手番、持ち駒なし、他は空マス。既存SFEN書出しでposition入力を作り、TwoPlyMaterial設定→position→go→go→quitを送る。

- 応答はちょうど二つ。各行が二語のbestmoveで、resignではなく、parseした一手が元教材の全合法手に含まれる。全合法手から４五飛だけが一意に選ばれるとは扱わない。
- 実選択を呼ぶ観測ラップで、各goへTWO_PLY_MATERIALが渡り、選択前後の81マス・手番・双方の玉以外の全持ち駒が教材の値と一致することを確認する。終了後も保存され、二回とも同じPosition参照が渡る。
- 別の新しいエンジン実行で、空盤・先手番・持ち駒なしの部分局面をSFENにして入力する。実合法手が空であること、新方式が実選択へ渡ること、応答が `bestmove resign` 一つで局面も保存されることを確認する。既存モデルは玉なし部分局面を表現できるため、詰みと同一視せず「合法手なし」の小さい代表例とした。

盤面の独立期待値はテストが配置した駒と空マス、手番は先手、双方の持ち駒は空。合法手の所属判定は計画指定の既存legal_movesを利用し、選択結果から期待値を生成しない。観測ラップは入力を記録して本物のchoose_moveを呼び、固定手を返すspyでは代替しない。
