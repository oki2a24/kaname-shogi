実施開始日：2026-09-26
設計承認日：2026-09-26

## 目的

人間の入力と第38回で作った弱い自動指し手をCLIの対局ループへ接続する。人間を先手、コンピュータを後手とし、手番交代、表示、乱数生成器の寿命、終局・中断、`GameRecord`の責務を説明できるようにする。

## 一次資料で確認した規則

日本将棋連盟の対局規則第2条は、先手番が対局を開始し、二人が交互に駒を動かすことを定める。第6条は、詰みまたは相手の投了で対局が終了することを定める。第10条には先後誤りや二手指しが反則として挙げられている。

本テーマでは、詰み・投了・既存の合法手だけをCLIへ接続し、千日手、持将棋、入玉、時間、反則勝敗は扱わない。EOF/Ctrl-Cは公式終局規則ではなく、学習用CLIの勝敗にしない入力中断として扱う。

出典：[日本将棋連盟「対局規則」](https://www.shogi.or.jp/match/taikyoku_rules/)、[日本将棋連盟「王手と詰み」](https://www.shogi.or.jp/knowledge/shogi/04.php)

## 確認問題と回答

### 第1問：コンピュータの担当手番

問題：コンピュータを先手・後手のどちらに固定するか。

本人の回答：人間が先手、コンピュータが後手。

補足：既存のCLIは先手から入力を始めるため、人間の初手後に自動手を確認できる構成とした。

合意：人間を先手、コンピュータを後手とする。

### 第2問：CLI開始方法

問題：人間対コンピュータ対局の起動方法をどうするか。

本人の回答：既存の `python3 -m kaname_shogi` を人間対コンピュータ用に変更する。ただし将来、人間対人間、人間対コンピュータ、コンピュータ対コンピュータへ切り替えられるように設計する。

補足：今回の引数や選択画面は追加せず、手番ごとの担当判定をCLI内部の境界へ置く。将来はその境界を差し替える。

合意：既定起動は人間先手・コンピュータ後手。3形式の切替機能自体は別テーマとする。

### 第3問：乱数生成器の生成と寿命

問題：乱数生成器を一局の間どう扱うか。

説明：乱数生成器は「0.12という一つの数」を固定するものではなく、次の乱数を順番に作る状態を持つ道具である。対局開始時に一個作ると、コンピュータの各手で次の値を取り出し、状態が進む。固定種を渡すと同じ手の並びを再現できる。

本人の回答：良い。

合意：`run_game`は乱数生成器を注入でき、指定がなければ対局開始時に一個だけ生成する。コンピュータの全自動手で同じ生成器を使う。

### 第4問：人間手と自動手の表示時機

問題：人間手とコンピュータ手をいつ表示するか。

本人の回答：開始局面を表示 → 人間の入力を促す → 成功した人間の手の後の盤面を表示 → コンピュータが選んだ手を表示 → 適用後の盤面を表示 → 次の人間入力、の順にする。

合意：上記の表示順とする。自動手は適用前に `後手の指し手: ...` と表示する。

### 第5問：コンピュータの合法手なし

問題：詰みでないのにコンピュータの合法手一覧が空の場合をどう扱うか。

本人の回答：まず既存の `is_game_over` で詰みを判定し、詰みなら勝者を表示する。詰みでないのに一覧が空なら、`None`を勝敗と解釈せず、「コンピュータの合法手がありません。」を表示して勝敗なしで終了する。

合意：選択器の`None`は選択不能だけを表し、終局・投了・勝敗は対局進行層が扱う。

### 第6問：投了

問題：投了をどの担当者が入力できるか。

本人の回答：良い。

合意：投了は人間（先手）の `resign` 入力だけで扱う。コンピュータは投了せず、合法手があれば一手を指す。投了は局面と指し手履歴を変更しない。

### 第7問：EOF/Ctrl-C

問題：EOF/Ctrl-Cをどう扱うか。

本人の回答：人間入力待ちで受け取り、勝敗・投了へ変換せず「入力を終了しました。」と表示して終了する。そこまでの成功手は`GameRecord`に残し、コンピュータは追加で指さない。

合意：上記の責務とする。

### 第8問：GameRecordへの記録

問題：人間手とコンピュータ手を`GameRecord`へどう記録するか。

本人の回答：人間・コンピュータを区別する情報や終局理由を追加せず、成功した盤上移動・駒打ちを手番順に記録する。

合意：既存の`RecordedMove` / `RecordedDrop`とJSON保存形式を維持する。投了、詰み、EOF/Ctrl-C、合法手空一覧は履歴へ含めない。

## 設計・実装記録

設計仕様は `docs/plans/2026-09-26-human-vs-computer-cli-design.md`、実装計画は `docs/plans/2026-09-26-human-vs-computer-cli.md` に記録した。設計書には、実際の入力・自動手・盤面表示を追えるCLI進行例も含めた。
