# 第60回：息子によるShogiHome試用

## 目的

息子がShogiHomeの盤面から人間として指し、`kaname-shogi` が応じる一局を実際に試す。強さや時計の正確さを評価せず、操作と応答が続くか、本人が試してみる価値を感じるかを観察する。

- [USI一次資料](https://hgm.nubati.net/usi.html)と[ShogiHome公式のエンジン登録手順](https://github.com/sunfish-shogi/shogihome/wiki/%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%B3%E7%99%BB%E9%8C%B2%E6%89%8B%E9%A0%86)、[エンジン機能の操作方法](https://github.com/sunfish-shogi/shogihome/wiki/%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%B3%E3%82%92%E4%BD%BF%E3%81%86%E6%A9%9F%E8%83%BD%E3%81%AE%E6%93%8D%E4%BD%9C%E6%96%B9%E6%B3%95)は仕様・操作確認の資料である。実際に送受信されたコマンドの証拠とは分ける。
- 第54回の[使い捨てプローブ](54-usi-shogihome-connection-scope.md)は、特定局面に対する `bestmove resign` の一例と、その後の終了通知をログで観測したもの。通常の合法応手をGUIが受け入れた証拠ではない。
- 第55〜58回はUSI一手変換、局面再現、合法手応答、状態管理のローカル実装とテストである。ShogiHome上の操作性や実通信を確認したものではない。
- 第59回は人間の７六歩・２六歩にエンジンが４四歩・９二飛と応じる短い実対局で、人間の投了後にShogiHomeの「対局終了（投了）」を確認した。詳細は[第59回記録](59-shogihome-even-game.md)にある。
- 本回はShogiHomeの盤面・棋譜と終局画面を目視確認した。USI通信ログを有効にしていないため、今回のコマンド列や最終応答の実際のUSI文字列は未確認である。

## 合意した試用方法

本人と一問ずつ相談し、試用の範囲・手順・確認方法の案を提示して明示承認を得た。

- ShogiHome 1.28.1で平手、人間先手（息子）、後手 `kaname-shogi` とする。
- 持ち時間は画面設定の10分+30秒を維持するが、時計精度は評価しない。
- `USI_Ponder` はOFFにする。既存の `usi_engine.py` が `go ponder` を未対応として拒否することによる。
- 先手が約3手指した時点で続けるか確認する。その確認でユーザーが続行と返答したため、対局終了まで続ける。
- 終局ボタンを押す必要がある場合は息子が投了する。感想は先に尋ねず、自発的な発言だけを記録する。
- コード・テスト変更は不要と判断したため、実装計画は作成せず、実機試用を行う。

## 登録・開始時の観測

- ShogiHomeの登録設定を実際に開くと、登録済みランチャーはアーカイブ済みワークツリー配下を指し、起動時に `ENOENT` となった。安定した `/Users/oki2a24/kaname-shogi/kaname-shogi-usi` を登録し直し、設定画面を再度開いて読み込めることを確認した。古い重複登録は削除した。
- `USI_Ponder` は設定画面でOFFにし、保存後に再確認した。対局設定にもPonder OFFと表示された。
- ローカル対局の初回開始時、後手エンジンが未選択でShogiHomeに「USI is required」と表示された。後手に `kaname-shogi` を選んで再開すると対局が始まった。
- 第59回の未保存棋譜は保存確認なしに新規対局へ切り替わり、その画面から外れた。第59回の棋譜は保存・書き出しされていない。本回の棋譜もShogiHome上の未保存記録で、KIF等へ保存していない。

## 学んだこと

- ShogiHomeの人間側の盤面操作と `kaname-shogi` の応答は、少なくともこの一局で19手目まで交互に続いた。
- 事前の約3手のチェックポイントでユーザーが続行を伝え、一局を最後まで試した。息子からは、自分が角の頭を狙ってから少し良くなったという自発的な感想があった。これは本人の受け止めであり、局面評価の客観的な分析ではない。
- 最終局面は人間の投了操作ではなく、エンジン側の手番で自動終了した。UI上は投了として記録された。USIログがないため、最終コマンドやShogiHome側の終了判定の詳細は未確認である。
- 登録済みランチャーの古いパスが実際に起動不能だった。安定したmain側パスへ直すことで読み込みを確認できた。Ponder OFFも保存後に確認した。
- エンジンの強さ、時計精度、Ponder ON、棋譜の保存・再読込、全USIコマンド、別OS・版は評価していない。

### 本人の回答（2026-10-04）

> 今回は第54回の前回と異なり開始から終局まで実践した事が異なる。投了は将棋エンジンが行ったことも前回と異なる。

### アシスタントの補足

第54回は、使い捨てプローブが一回の局面通知に `bestmove resign` を返し、その後ShogiHomeが `gameover lose` と `quit` を送ったログ上の一例であり、通常の指し手を往復する対局ではなかった。本回は棋譜で人の19手とエンジンの18応手が確認され、息子は投了ボタンを押さず、最後の `☗４一金` 後にエンジン側の番でShogiHomeが投了終局を表示したため、開始から終局まで実対局した点が異なる。

ローカル実装では、`go` 時の合法手一覧が空なら `bestmove resign` を出す。しかし本回は通信ログを取っていないので、その文字列がShogiHomeへ実際に送られたか、ShogiHomeがどの経路で終局を処理したかは分からない。画面・棋譜と本人の説明から確認した終局と、USI通信上の詳細は分けて記録する。
