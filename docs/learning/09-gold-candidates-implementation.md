## 目的と合意

第8回の学習を金の候補生成として実装する。利用者は[設計案](../design/03-gold-move-candidates.md)とTDDでの実装に同意し、現在のディレクトリでの作業を選択した。

## 実装の要点と判断

- `gold_move_candidates` は金の候補を求める操作。Board（盤面のデータ）とSquare（出発マスの値）を受け、移動先のリストを返す。
- 先後による前方の段の増減と6方向の表を使い、各候補について盤外・自駒を除外する。
- 除外では `continue`（現在の繰り返しを終え、次の方向へ進む操作）を使う。他の候補も残るため、途中で関数全体を終了しない。
- 所有者は盤上の金から読む。盤面の書き換えも手番への依存もない。
- 歩との処理共有は見送った。短いループで読める現段階では、共通化のための引数や間接参照を増やす必要がない。
