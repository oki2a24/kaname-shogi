# 第22回：手番更新

## 目的

`Board` が盤面だけを表し、`Position` が盤面と次に指す側を表す局面であることを理解する。空マスへの移動が成功したときだけ手番を先手・後手で交代し、不正な移動では盤面と手番の両方を変えない最小範囲を扱う。

今回は、駒取り、持ち駒、成り・不成、王手、王手放置を避ける合法手判定、詰み、CLI入力、評価、探索、不変な盤面・局面への変更を扱わない。

## 要点

- `Board` は81マスの駒の配置を保持する可変の盤面データであり、手番を持たない。
- `Position` は `Board` と `side_to_move` を持つ可変の局面である。
- `move_piece` は盤面だけを変更する操作であり、手番の更新とは責務を分ける。
- 将棋は先手・後手が交互に一手ずつ指す。先手が対局を開始し、同じ側が連続して指す二手指しは反則である。
- 今回の手番更新では、移動成功時だけ `side_to_move` を先手・後手で交代する。不正な移動時は盤面と手番の両方を変更しない。

## 確認問題と回答

### 第1問：移動成功後の局面

問題：`Position` の手番が先手で、空の到着マスへの移動が成功した直後、盤面と `side_to_move` はそれぞれどうなっているべきでしょうか？

本人の回答：盤面は変わる。`side_to_move` は後手になる。

アシスタントの補足：正しい。成功時には、出発マスの駒が空の到着マスへ移るため盤面が変わり、次に指す側は先手から後手へ交代する。一方、移動が不正なら例外にして、盤面も `side_to_move` も変えない。

## 振り返り

本人の振り返り：ありません。

アシスタントの補足：盤面の変更と手番の交代を、成功した移動にだけ結び付ける点に引っかかることはないと確認した。次はこの理解を保ったまま、既存の `move_piece` と手番更新付きの操作の責務を分ける設計を相談する。

## 将来の課題

- 出発駒の所有者と手番の一致、移動方向、王手放置を避けることを含む合法手判定は、別テーマで扱う。
- 評価・探索の段階で、可変な `Position` を直接変更する方式を、不変な局面を返す方式へ見直す。
