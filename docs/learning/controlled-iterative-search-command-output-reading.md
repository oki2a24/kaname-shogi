# 小さいSFENで時間制御付き反復探索の出力を読む

## 目的・範囲

2026-10-18、選定済みテーマとしてREADME記載の小さいSFENを使い、時間制御付き反復探索の開発用コマンドを一回実行して出力を読んだ。目的は、実行条件・終了状態・選択手と由来・最後の完了記録を対応付けること。

通常対局・USIへの新方式接続、予算式変更、時間保証、コード・テスト変更、実装は対象外。コマンドの出力、終了コード、および今回確認した文書・コードの範囲だけを実測として扱う。

READMEのコマンド例、承認済み設計、実装記録、探索停止メモ、`run_controlled_iterative.py`、`result.py`を確認した。設計では目標・上限を予算として探索へ渡し、選択手と完了記録を分ける。`STOPPED`は通常停止を表すが、表示用の結果に停止理由は含まれない。コマンドは経過時間を表示しない。

## 実行した一回と観察結果

次のREADME記載例をそのまま実行した。

```sh
.venv/bin/python -m kaname_shogi.search.run_controlled_iterative \
  --sfen "8k/9/9/9/9/9/9/9/K8 b - 1" \
  --max-depth 4 --target-ms 50 --maximum-ms 100
```

実際の標準出力:

```text
入力SFEN: 8k/9/9/9/9/9/9/9/K8 b - 1
評価視点: 先手
指定上限深さ: 4
目標期間(ms): 50
上限期間(ms): 100
終了状態: STOPPED（通常停止）
選択手: 9i9h（9九→9八）
手の由来: 完了結果
完了記録: あり
完了深さ: 2
完了深さの評価: ＋0
完了深さの訪問回数: 9
反復累計（完了した深さまで）: 13
```

終了コードは `0`。

- 入力局面の手番による評価視点は先手。指定上限深さは4、目標期間は50ms、上限期間は100ms。
- 終了状態は `STOPPED（通常停止）`。完了記録として確認できる最後の深さは2で、指定上限深さ4まで完了した表示ではない。
- `9i9h（9九→9八）`は完了結果に由来する選択手。完了記録には深さ2の評価 `＋0`、同深さの訪問回数9、完了した深さまでの累計13が表示された。
- 「手の由来」は選択手の出どころを示し、「完了記録」は最後に完了した探索の記録を示す。どちらも停止原因を表す項目ではない。
- 出力からは、停止が目標50msと上限100msのどちらで判断されたか分からない。経過時間も出力されていない。`--maximum-ms`は探索へ渡す予算であり、実応答時間の保証とは扱わない。

深さ・終了状態・探索結果はこの一回の実測である。別の実行でも同じ結果になるという期待や、時間内応答の保証は置かない。

## 最後の理解確認（2026-10-18）

**確認したこと:** 出力上の選択手・完了記録と、停止原因を区別して読めるか。

**最初の質問:** この出力から、`STOPPED`の原因を目標50msと上限100msのどちらかに結びつけられるか。根拠とあわせて回答する。

**本人の最初の回答:**

> 目標50ms。手の由来: 完了結果 完了記録: あり、なため

**アシスタントの補足:** 「手の由来: 完了結果」は選択手が完了済み探索に基づくことを示し、「完了記録: あり」は完了記録があることを示す。これらは停止原因を示さない。出力には停止理由も経過時間もないため、目標50msと上限100msのどちらが原因かは読み取れない。

**再確認の質問:** 今回の出力で「完了結果」と「完了記録」から何が分かり、停止原因について何が分からないか。

**本人の再確認回答:**

> 完了結果は選択手が完了済みの探索結果に基づくことがわかる。停止原因が時間由来であるかどうかがわからない。

**アシスタントの補足:** 選択手が完了済み探索結果に基づくという理解は正しい。停止理由の詳細は出力に現れず、特に目標50msと上限100msを区別できない。より正確には、確認したコマンド経路は`SearchControl`へこの二つの予算を渡し、`request_stop`を呼ばないため、このコマンドの通常の`STOPPED`は時間制御による停止である。ただし、今回の出力だけでは目標到達か上限到達かは分からず、実際の経過時間も表示されない。完了深さ2の記録と指定上限深さ4も別の値として読む。上限期間から実応答時間を保証しない。
