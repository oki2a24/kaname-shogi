# 第17回：角の候補生成の実装

## 目的と実装範囲

承認済み設計[角の設計](../design/07-bishop-move-candidates.md)と実装計画[角の実装計画](../plans/2026-09-19-bishop-move-candidates.md)に従い、成る前の角の移動先候補を実装した。`bishop_move_candidates(board, source)`は盤面と出発マスを受け、右前・左前・右後ろ・左後ろの順に各方向を近い順で走査する。盤面の変更、手番による制限、成り、馬の動き、王手、合法手の確定、実際の移動や駒取りは扱わない。

## TDDの実施記録

### タスク1：入力契約

角関数をimportした直後は、関数未定義による`ImportError`になった。これは準備段階のエラーとして記録し、仮関数を置いた後に空マス・角以外で`ValueError`が出ないこと、および候補が空のままであることによる振る舞いのRedを確認した。

最小実装で出発駒の存在と駒種を確認し、該当しない場合に`ValueError`を送出した。

### タスク2：斜め4方向

５五の先手・後手の角について、4方向の固定順と候補列をテストした。最初の期待値は先後共通にしていたため、後手の前後を正しく扱う実装に対して失敗した。これは実装ではなくテスト期待値の誤りであり、先手は段を減らし、後手は段を増やす方向順へ修正した。

方向データを`(筋の増減, 段の増減)`で表し、各方向を1マスずつ走査する最小実装を追加した。入力契約と開いた盤面のテストがGreenになった。

### タスク3：停止条件と境界

自駒の手前で停止すること、相手駒のマスを最後の候補に含めて停止すること、1方向の停止が他方向を妨げないこと、四隅で盤外へ出ないことをテストした。

自駒テストの期待値に角の経路ではない５三・３五を含めていたため失敗した。５五からは斜めだけを進むことを確認して期待値を修正し、10個の角テストがGreenになった。

### タスク4：契約とRefactor

候補計算後の全81マス不変、呼び出しごとのリスト独立性、`Position.side_to_move`による候補非制限を確認した。方向データと走査処理は角関数内で共有し、飛車との共通化は今回の学習範囲を広げないため行わなかった。公開docstringには引数、戻り値、例外、副作用、前提条件、方向順、対象外を記載した。

## 実装後の理解確認

### 第1問：相手駒のマスで走査を止める処理

本人の回答：

「`if occupant is not None:`で止める」

評価・補足：正解。`occupant is not None`で駒があることを検出し、その方向の走査を止める。ただし、自駒はその条件より前に`break`するため候補へ追加しない。相手駒は先に`candidates.append(target)`で候補へ追加し、その後の`if occupant is not None: break`で相手駒の先へ進まない。
