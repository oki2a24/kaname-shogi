## 学習の要点

- SearchBudgetは目標・上限期間を持つデータ。SearchControlは期限と停止要求を管理する制御データ。search_controlledは最終結果一件を返す同期操作。
- 目標は次の深さを始める前に確認する。上限・通常停止・抑制は深さ内部でも確認する。
- 通常停止では最新完了結果を使う。完了記録がなければ合法予備手を使い、評価を捏造しない。
- 初回の合法手確保または手なし確定まで通常停止を保護する。0msでも準備を行うので時間保証ではない。抑制は保護しない。
- 旧比較入口は深さごとに完了記録を受け取る。新入口は終了時に結果一件を返すため、途中表示やCtrl+Cの扱いを旧入口から自動的に引き継げない。

### 表示内容と時計原点の選択

表示内容の提案に本人が「yes」と回答した。個別承認の対象は次の組合せ。

- 実行条件：入力SFEN、開始側の評価視点、指定上限深さ・目標ms・上限ms。
- 終了結果：終了状態、USIと日本語の選択手、予備手か完了結果の手か。
- 完了記録：最後に完了した深さ、その評価・訪問回数、完了反復の訪問累計。
- 記録がない場合は「完了記録なし・評価なし」。深さごとの途中表示は加えず、終了時にまとめる。

ここでの「操作セット等の準備」はコマンド側の設定準備を指し、探索内部の合法予備手準備とは異なる。実行条件の出力を探索前に行うなら、その出力も原点取得前に終える必要がある。出力タイミングの詳細は設計文書で確定する。
