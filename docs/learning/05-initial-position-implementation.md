# 第5回：初期配置CLIの実装と検証

## 学習の目的

承認した設計をコードにし、筋・段で初期配置を扱えることを確かめる。今回は駒を動かす前の「盤面を正しく作って表示する」一つのテーマに絞る。

## 実装の要点

- `model.py` に `Square`、`Side`、`PieceType`、`Piece`、`Board`、`Position` と初期配置生成を実装した。
- `Square(7, 6)` が７六を表す。`to_index()` だけが `(file - 1) * 9 + (rank - 1)` で内部添字59に変換する。
- `Square` と `Piece` は `frozen=True`。座標の範囲と整数型は生成時に検証し、真偽値も拒否する。
- `Board` は81個の `None` から開始する。`None` 自体は変更される値ではなく、各盤面で新しいリストを作るため、別の盤面とは要素の設定を共有しない。
- `set_piece()` は駒を置く・マスを空にする操作であり、移動や合法手の判定ではない。
- 初期配置の飛角は先後で筋が異なるので、８八・２八・８二・２二を明記した。
- `display.py` は段ごとに筋9→1をたどる。保存順と表示順は別である。
- `__main__.py` が初期配置を作り、表示文字列を出力して終了する。

## 検証の記録

環境はmacOSのPython 3.9.6。外部パッケージは導入していない。

各段階で先にテストを書き、対象モジュールまたは関数が未実装のため読み込めないことを確認してから実装した。実装後は次の順に成功した。

| 段階 | テスト数 | 確認内容 |
| --- | ---: | --- |
| 値と盤面 | 9 | 座標の一意性と範囲、不正値の拒否、不変性、配置と取得、盤面の独立性 |
| 初期局面 | 12 | 全81マス、各側20枚・歩9枚・玉1枚、先手の手番、初期局面の独立性を追加 |
| 表示とCLI | 15 | 初期配置の全文、後手の手番表示、実プロセスの正常終了・標準出力・標準エラーを追加 |

配置の期待値には、学習済みの表から作った独立した9行のデータを使った。生成関数の出力から期待値を作ると、飛角の逆配置などの誤りを見逃すためである。このテスト用データはSFENの読み込み機能ではない。

`python3 -m kaname_shogi` でも実際に初期配置が出力されることを確認した。

## 確認問題

次の問題をコード確認用に用意し、対話では1、2、4、3の順に確認した。

1. ７六の駒を読むとき、呼び出し側が59という添字を直接使わないのはなぜか。
2. `set_piece(Square(7, 7), None)` は何を変更するか。この操作だけで将棋の合法手を判定できるか。
3. 初期配置を二つ作り、一方の歩を消しても他方の歩が残る必要があるのはなぜか。
4. 初期配置のテストで、駒数だけでなく全81マスを確認するのはなぜか。

## 回答

1. 添字を直接使わない理由
   - 回答：人間のため。人間は59が７六であるとすぐには理解できないから。
   - 評価：正解。補足として、内部の保存方法を変更しても呼び出し側を筋・段のまま保てることを説明した。
2. `set_piece(Square(7, 7), None)` の意味
   - 回答：７七を駒がない状態にする。
   - 評価：正解。対話ではマスの変更内容を質問した。合法手判定については本人の回答を求めず、この操作だけでは移動・手番変更・合法手判定を行わないことを補足した。
3. 局面の独立性
   - 回答：それぞれの局面は独立しておりお互いに関係がないから。一方の局面がもう一方の局面に影響があってはならないから。
   - 評価：正解。別々に生成した局面の一方を変更しても、もう一方の盤面が変わらないことを確認した。
4. 全81マスを確認する理由
   - 回答：駒数だけでは、駒がどのマスにあるかわからないから。
   - 評価：正解。飛角が逆でも40枚という数は変わらず、空マスへの誤配置も全マスの照合で検出できることを補足した。

## 途中で確認した用語と実行場所

- 利用者から、`Square` は「指す」「置く」という意味か、という質問があった。`Square` は盤上の「マス」を表す値であり、操作ではないと確認した。`piece_at` は駒の取得、`set_piece` はマスの内容の設定を行う。
- コードは元の作業ディレクトリとは別のGit作業ツリーにあり、そのディレクトリで `python3 -m unittest discover -s tests -v` と `python3 -m kaname_shogi` を実行できると案内した。利用者自身による実行結果は、この対話ではまだ報告されていない。

## 振り返り

実装・検証上は、筋・段を公開操作に用いながら内部保存を一次元リストにできた。初期配置生成、表示文字列の生成、標準出力を分けることで、それぞれの役割を追える形になった。

対話で質問した4点への回答はすべて正解。利用者は、筋・段の読みやすさ、空マスへの設定、配置を検証する必要性、別々に生成した局面の独立性を自分の言葉で説明できた。`Square` のような英語名は、操作かデータかという役割と日本語の意味を併せて確認すると理解しやすい。
