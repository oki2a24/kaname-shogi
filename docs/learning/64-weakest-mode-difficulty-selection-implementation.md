## 合意した細則

- 利用面はCLIとShogiHome（USI）の両方。
- 現行の一様ランダムを明示選択できる最弱とし、未指定時も既定値にする。
- 方針は対局開始前に選び、その局の間は固定する。
- 駒得方針は与えられた合法手を一手だけ適用した直後の評価を比べる。探索せず、同点の最高手からランダムに選ぶ。
- 駒価値は谷川浩司さんの参考値を採用する。歩1、と金12、香5、成香10、桂6、成桂10、銀8、成銀9、金9、角13、馬15、飛15、竜17。玉将は採点しない。盤上と持ち駒は同じ値で数え、取った成駒は基本駒の持ち駒値へ戻す。
- 候補手の評価は、その手を指した直後の「指し手側の合計 − 相手側の合計」。盤上と持ち駒を含み、指し手側から見た値の大きい手を選ぶ。
- CLI表示語は「最弱（一様ランダム）」「駒得を考える」。USI option名は `Difficulty`、値は `Random` と `Material`。
- 自動テストとコードレビューを確認方法とし、ShogiHome実機での設定・対局・ログ採取はこのテーマでは行わない。

## 実装内容

`kaname_shogi.movegen` に `MoveSelectionPolicy`、`material_balance`、共通の `choose_move` を追加した。Randomは従来の `choose_weak_move` へ委譲する。Materialは元の手番側から見て、各候補手を複製局面へ一度適用し、成駒・持ち駒の値を含めた合計差を比べる。候補の再生成、相手の応手の探索、元局面の変更はしない。

CLIはコンピュータが参加する対局形式で開始前に選び、空入力をRandomとして一局中固定する。人間対人間ではメニューを出さない。`run_game` を直接呼ぶ場合も省略時はRandomとする。

USIは `usi` 応答でDifficulty comboを `usiok` より前に通知する。設定がない場合はRandomで、設定値は最初の `go` で局の間固定する。`usinewgame` は選択済みDifficultyを保ったまま局内固定を解除する。USI仕様に沿ってoption名・値の照合は大文字小文字を区別しない。未知optionは無視し、Difficultyの不正値は最後の有効値を保つ。

## 振り返り

駒の点数合計は通常の勝敗規則ではなく、候補手を比べるための評価値である。今回は盤上・持ち駒を同じ参考値で数え、玉を含めず、取った駒は基本駒として手駒へ加えた後の差を見る。したがって銀を取れば相手の銀8点が減るだけでなく、指し手側に銀8点が加わり、駒得差は16点増える。この意味と通常対局の勝敗や持将棋・入玉の規則上の点数計算との違いは[一手選択の知識メモ](../knowledge/31-weak-move-selection.md)に記録した。

## 最終理解確認

### 質問

銀を一枚取った直後、ほかの駒の状態が変わらない場合、駒得評価は指し手側から見て何点変わりますか。その理由も説明してください。

### 本人の回答

> プラス１６点。指しては銀を手に入れプラス８点。刺された側はマイナス８点なため

### アシスタントの補足

点数差の計算はそのとおりである。指し手側の合計が8点増え、相手側の合計が8点減るため、「指し手側 − 相手側」は `+8 - (-8) = +16` 点変わる。
