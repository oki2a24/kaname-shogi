## Task 2：二方式で共通の反復深化

2026-10-19、標準・制御付き反復入口にキーワード専用 `pruning: bool = True` を加えた。Trueは従来どおりαβ、Falseはminimax全幅を選ぶ。深さごとの反復・前回最善手・累計・制御・予備手・停止結果の組み立ては既存共通処理に保ち、対局接続や時間制御はまだ加えていない。

TDDのRedでは、制御付き両方式の前回最善手引き継ぎと方式／深さの事前検査を追加し、既存APIに `pruning` がないことによるテスト内の明示assertion failureを確認した。検査は探索操作・prepareより前に行い、標準側はTrue/False両方で不正上限、両入口は非boolの0・1・Noneを拒否する。手計算した深さ1〜4の結果・訪問数・累計に加え、省略可能な数値木で全幅の全訪問・根候補値を照合した。制御付きでは初回停止の予備手、手なし、深さ3停止時の深さ2完了結果、同一control、操作例外、完了後抑制での手隠蔽、前回最善手を両方式で確認する。

最小実装は方式モジュールを一度選び、各深さでその `search` / `search_controlled` を取得して既存 `_iterations` へ渡す薄い接続とした。既存のαβ既定呼出し、操作、準備、停止・最終結果ロジックは変更していない。公開入口のdocstringへ引数・戻り値・副作用・前提と共通化の理由を記した。
