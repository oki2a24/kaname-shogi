# 第62回：ShogiHome接続手順書とCodexスキルを作成する

## 目的

ShogiHomeへの接続を依頼されたとき、操作対象・対局条件・設定変更の承認・停止条件を迷わず確認できるよう、人間向けの再利用手順書と、このリポジトリで発見できるCodexスキルを整える。

## 合意した範囲

- 保存先を `docs/shogihome-connection-guide.md` と `.agents/skills/shogihome-connection/SKILL.md` にする。
- 人間向け手順書は単独で通常対局、KIFの指定局面からの再開、依頼された場合のUSIログ採取を説明する。Codexスキルは手順書へ案内し、事前確認・承認境界・停止条件を示す。
- どちらも学習記録、引き継ぎ、過去セッションを運用上の参照先や根拠として必要としない。スキルから手順書へのリンク、および公式資料・現行知識資料へのリンクは許容する。
- 文書・スキルの作成時点では、ShogiHomeの設定変更・対局・ログ採取、コード・テストの変更は範囲外とした。成果物完成後、本人が実証テストを希望し、一局だけの具体案を承認したため、設定変更・ログ採取・棋譜保存をしない限定対局を追加で実施した。
- 基本の確認方法は文書とShogiHome/Codexの公式資料、現行知識資料との照合、読み取り専用のシナリオ評価とした。追加承認後は、手順書に記載した範囲でShogiHome 1.28.1の一局を実地確認した。

- 登録先は `/Users/oki2a24/kaname-shogi/kaname-shogi-usi` で、現在のチェックアウト内の実行可能ランチャーと一致した。`USI_Ponder` はOFFだったため、設定変更や再起動は不要だった。
- 先手を人、後手を `kaname-shogi` とし、開始局面に「平手」を選択した。時計は持ち時間10分・秒読み30秒・増加0秒、連続対局1局で、自動保存はOFFだった。

- 先手投了でテスト局を終了した。終局表示を確認し、監視画面が `USIエンジン: 0` と「稼働中のUSIエンジンはありません」を示した。

この実証で確認したのは、記載したShogiHome 1.28.1の環境・設定における一局の接続、合法な一手応答、投了後のセッション終了である。ログ機能、Ponder ON、他バージョン、他局面での通信列や互換性を確認したとは扱わない。

## 独立レビュー

初回の独立レビューではCriticalはなく、現行USIの局面対応範囲についてのImportantを受けた。`position startpos moves <1手以上>` のみ対応し、初手前・SFEN・駒落ち・別初期局面には対応しないため、この範囲を手順書・スキル・設計仕様・実施計画へ明記した。変更後、初手からエンジンに指させる新規平手と駒落ちKIFの2件を読み取り専用で評価し、範囲外として停止することを確認した。

局面範囲の修正後レビューはコード知識との一致を確認した。また、停止条件の「ログ採取の許可がない」がログ不要の通常対局も止めるように読めるとの指摘を受けた。当初はMinorと評価されたが、計画が求める「ログ未依頼なら通常手順を案内する」振る舞いへ直接影響するためImportantとして対応し、「ログ不要なら通常手順を続ける」と条件を明記した。さらに、スキルの根拠を公式資料だけに限定する表現は、承認済み設計が根拠とする現行のリポジトリ知識・運用文書を除外し得るためImportantと判断し、利用を明示した。学習記録・引き継ぎ・過去セッションを運用根拠にしない条件は維持した。

ログ条件と資料範囲の修正後、独立した読み取り専用レビューでCritical・Important・Minorの追加指摘はなかった。レビューではログ設定の承認・復帰、現行資料と履歴資料の境界、局面形式と実装、KIFの明示選択、通信例の非一般化が整合していることを確認した。別の読み取り専用評価者も、ログ不要の一局ではログ設定変更・再起動なしに通常手順を進めると判断した。

## 理解確認

### 質問

ShogiHomeのエンジン一覧に似た名前の項目があっても、現在の `kaname-shogi-usi` と照合する必要があるのはなぜですか。

### 本人の回答

使いまわさないため

### アシスタントの補足

そのとおりです。ShogiHomeの表示名が同じ、または似ていても、登録先が古いworktreeや別ブランチの実行ファイルを指している可能性があります。現在作業中のチェックアウトにある `kaname-shogi-usi` の実在・実行可能性と絶対パスを登録先と照合すれば、古いエンジンを使い回したり、削除済みパスを選んだりするのを避けられます。

## 振り返りと次回への問い

固定シナリオでスキル導入前後の判断を比較したことで、必須の停止判断を人間向け手順書とCodex向けスキルの両方に揃えられた。手順書は公式Wikiと現行の実装知識へ直接たどれる構造とし、操作判断が一過性の学習記録に依存しない形にした。後日、限定した実地確認でも登録先・Ponder・平手開始・初手後の応答・終了状態を確かめたが、この一局を全環境や全局面の保証には広げない。画面や版が手順書と違う場合には差異を確認する必要がある。
