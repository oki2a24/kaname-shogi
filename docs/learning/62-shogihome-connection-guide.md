# 第62回：ShogiHome接続手順書とCodexスキルを作成する

## 目的

ShogiHomeへの接続を依頼されたとき、操作対象・対局条件・設定変更の承認・停止条件を迷わず確認できるよう、人間向けの再利用手順書と、このリポジトリで発見できるCodexスキルを整える。

## 合意した範囲

- 保存先を `docs/shogihome-connection-guide.md` と `.agents/skills/shogihome-connection/SKILL.md` にする。
- 人間向け手順書は単独で通常対局、KIFの指定局面からの再開、依頼された場合のUSIログ採取を説明する。Codexスキルは手順書へ案内し、事前確認・承認境界・停止条件を示す。
- どちらも学習記録、引き継ぎ、過去セッションを運用上の参照先や根拠として必要としない。スキルから手順書へのリンク、および公式資料・現行知識資料へのリンクは許容する。
- ShogiHomeの設定変更・対局・ログ採取、コード・テストの変更は行わない。必要と判明した場合は、具体案を示して別途承認を待つ。
- 確認方法は文書とShogiHome/Codexの公式資料、既存の現行知識資料との照合、読み取り専用のシナリオ評価とする。

## 独立レビュー

初回の独立レビューではCriticalはなく、現行USIの局面対応範囲についてのImportantを受けた。`position startpos moves <1手以上>` のみ対応し、初手前・SFEN・駒落ち・別初期局面には対応しないため、この範囲を手順書・スキル・設計仕様・実施計画へ明記した。変更後、初手からエンジンに指させる新規平手と駒落ちKIFの2件を読み取り専用で評価し、範囲外として停止することを確認した。

局面範囲の修正後レビューはコード知識との一致を確認した。また、停止条件の「ログ採取の許可がない」がログ不要の通常対局も止めるように読めるとの指摘を受けた。当初はMinorと評価されたが、計画が求める「ログ未依頼なら通常手順を案内する」振る舞いへ直接影響するためImportantとして対応し、「ログ不要なら通常手順を続ける」と条件を明記した。さらに、スキルの根拠を公式資料だけに限定する表現は、承認済み設計が根拠とする現行のリポジトリ知識・運用文書を除外し得るためImportantと判断し、利用を明示した。学習記録・引き継ぎ・過去セッションを運用根拠にしない条件は維持した。

ログ条件と資料範囲の修正後、独立した読み取り専用レビューでCritical・Important・Minorの追加指摘はなかった。レビューではログ設定の承認・復帰、現行資料と履歴資料の境界、局面形式と実装、KIFの明示選択、通信例の非一般化が整合していることを確認した。別の読み取り専用評価者も、ログ不要の一局ではログ設定変更・再起動なしに通常手順を進めると判断した。
