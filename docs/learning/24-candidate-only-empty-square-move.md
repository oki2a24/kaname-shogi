# 第24回：移動先候補に合う空マスへだけ移動できること

## 目的

すでに求められる各駒の移動先候補を、局面を一手進める
`apply_move` と結び付ける。手番と出発駒の所有者が一致するときでも、
候補に含まれる**空マス**へだけ移動を適用し、候補外は局面を変えずに
拒否する最小範囲を学ぶ。

今回は、候補に含まれる相手駒のマスへの駒取り、持ち駒、成り・不成、
王手、王手放置を避ける合法手判定、詰み、CLI入力、評価、探索を扱わない。

## 要点

- 日本将棋連盟は、自分の駒がある所には進めないこと、相手駒のある所へ
  進む場合は駒取りになることを説明している。
- 今回の `apply_move` は駒取りを扱わないので、移動先候補のうち空マスだけを
  実際の移動先として受け付ける。
- `apply_move` は出発駒の駒種から既存の候補生成関数を選び、`destination` が
  その結果に含まれるかを盤面変更前に照合する。
- 候補外なら `ValueError` を送出し、盤面と `Position.side_to_move` を変更しない。
- `move_piece` は候補照合を持たない盤面専用の操作として残す。

## 出典

- [日本将棋連盟「駒の動かし方」](https://www.shogi.or.jp/knowledge/shogi/02.php)
- [日本将棋連盟「駒の動きと特徴」](https://www.shogi.or.jp/knowledge/shogi/03.php)

## 確認問題と回答

### 第1問：候補内と候補外の空マス

問題：先手番で先手の歩が５五にあり、５四は空、５六も空だとします。
この回の `apply_move` は、５五→５四 と ５五→５六 をそれぞれどう扱い、
失敗する場合の盤面・手番はどうなるべきでしょうか？

本人の回答：

- ５五→５四 は `apply_move` が成功し、盤面・手番を変更する。
- ５五→５六 は `apply_move` が失敗し、盤面・手番は変化させない。

アシスタントの補足：正しい。先手の歩の候補は一つ前の５四であり、空いて
いれば移動できる。５六は候補外であるため、盤面を動かす前に `ValueError` を
送出し、手番も交代しない。

## 設計の合意

本人は次の設計案を承認した。

- `apply_move` が、手番・所有者の照合後に出発駒の種類に対応する既存の候補生成関数を呼ぶ。
- 到着マスが候補に含まれなければ `ValueError` とし、盤面・手番を変えない。
- 候補に含まれても到着マスが相手駒なら既存の `move_piece` が拒否する。駒取りは追加しない。
- 候補に含まれる空マスだけを `move_piece` へ委譲し、成功後に手番を交代する。
- 駒種から既存候補関数を選ぶ非公開ヘルパーを使い、公開APIは増やさない。

## 次回への問い

候補照合を `apply_move` のどの位置に置けば、空出発・所有者不一致・候補外・
占有到着のいずれでも局面を変更しない契約を保てるか。

## 実装・検証記録

- Redでは、候補外の空マスを指定する先手・後手の歩のテストが、どちらも
  `AssertionError: ValueError not raised` で失敗した。これは読み込みエラーではなく、
  既存の `apply_move` が任意の空マスを受け入れたことによる振る舞い上の失敗だった。
- Greenでは、`_move_candidates_for_piece(board, source)` を非公開で追加し、盤上の
  `PieceType` から既存の8種類の候補関数を選ぶようにした。`apply_move` は所有者と
  手番の照合後、盤面変更前に候補外を `ValueError` で拒否する最小実装にした。
- 候補内の空マスへの全8駒種の移動、候補外の先後の歩の局面不変、後手歩の前方への
  成功移動をテストした。`move_piece` は候補照合も手番も知らない盤面専用の操作として
  変更しなかった。
- Refactorでは、候補関数を一つに統合したり、`move_piece` に候補照合を移したりしない
  と判断した。駒種の選択を非公開ヘルパーに集めるだけで、今回の責務分離と重複削減を
  満たしている。
- `python3 -m unittest discover -s tests -v` は100テストすべて成功し、
  `python3 -m kaname_shogi` の初期配置表示と `git diff --check` も成功した。
- コミット `60f9559` を対象に独立コードレビューを実施した。CriticalとImportantの
  指摘はなく、候補照合を盤面変更前に置く責務分離、全8駒種の候補内移動、先後の歩の
  候補外拒否と局面不変が確認された。計画のチェックボックスが実際の進捗に追随して
  いない軽微な指摘を受け、下記の実施済み状態へ修正した。
