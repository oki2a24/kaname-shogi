## 計画の要点

契約ごとに独立期待値と誤り例を対応付け、`test_search_control.py`、制御付き結果/探索テスト、共通整形テスト、既存比較入口のテストが補う範囲を明示した。特に、argparse由来 `SystemExit(0)/(2)` と入力値 `ValueError` の区別、NO_LEGAL_MOVEで記録4行を全て出さないこと、設計どおりの表示順、内部ValueError伝播、KeyboardInterrupt時の130と結果回収なしを具体化した。

タスクごとに対象assertionのRed、最小実装、Green、Refactor要否、独立レビューを置いた。新規モジュール等の読込み失敗だけでRedとせず、骨格上で契約アサーションの失敗を確認する。製品テストや代表変異の実行はこの計画段階では行わない。実時間保証・全SFEN/OS・実プロセスSIGINT配送・棋力などは未検証事項として残す。
