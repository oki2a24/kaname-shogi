# 支えがある駒への低価値駒の利き：学習記録

2026-10-31。対話を設計作成の節目で整理した記録。製品実装未着手。

## 目的と選定

本人：「将棋エンジンの棋力を上げたい。だが、改善点は特に思いついていない。」前テーマを選んだ理由を遡って推測しない。

候補プールと現行評価を比較。角可動性の懸念を本人が示した。アシスタントはC1が悪化ではなく判断不能、C2が指定条件で悪化支持だったと区別した。角の移動候補数だけでは、歩に角を取られ金で取り返しても損する関係を補わない部分局面を説明した。

本人は候補比較後、「価値の違いを含む駒の危険」を選択した。手法は、危険の静的な目安と駒取り・取り返しを読む方法を比較し、本人が前者を選んだ。小さく定義しやすいという推薦理由はアシスタントの判断であり、本人の選定理由として記録しない。

## 本人回答と補足

- Uの説明後、本人：「Uでは駒の価値を考慮に入れていないから。」補足：価値だけでなく、支えがあれば対象外であり交換損得を見ない。
- 支えのある角が歩に狙われる場合、本人：「含めるべき」。
- 同価値の角から狙われる場合、本人：「支えているならば角交換できるので含めなくて良い」。補足：今回の指標は合法な交換成立を保証せず、同価値を対象外にする。支えなしで同価値から狙われる危険はUへ任せる方針にYES。
- 先手対象2枚・後手1枚の先手視点、本人：「-1」。正解として説明。その後、合成方法への問いにも「-1」と回答したためYESとは解釈せず問い直し、10M+U+Vへ明示的なYESを得た。

## 個別にYESを得た事項

1. 安い駒から狙われる現在の関係を危険の目安とする。
2. 同価値は対象外とし、支えのない駒の危険はUへ任せる。
3. 攻撃元が複数でも対象一枚は1。価値差を点数にしない。
4. Uとの二重減点を避け、Vは支えのある駒へ限定する。
5. 既存の駒得参考値を共用する。
6. 玉は対象・安い攻撃元から除き、支え役には含める。
7. ピンされた駒を含む既存利きの意味を使う。
8. 仮合成10M+U+Vと、将来V係数だけ0/1を変える比較方針。
9. 安い駒に狙われた駒は、支えを付けてもUからVへ移るだけで等重み時の合計が改善しない性質。
10. 今回のB範囲はV計算・合成・既存一手選択器との接続確認。CLI/USI公開と対局比較は別段階。
11. 上記を前提に設計案をまとめること。
