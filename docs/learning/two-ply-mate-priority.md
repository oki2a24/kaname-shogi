## 盤上の要点と表現

先手は９九玉・５三飛・４三金、後手は５一玉と４一・６一・４二・６二の歩。５二飛とすると、後手玉は周囲を自分の歩に塞がれ、飛車を取ろうとしても４三金の利きがある。飛車と玉の間に空きマスがなく、持ち歩を打って王手を遮ることもできない。後手に持ち歩1000000枚を加えても詰みが成立することを、実操作で照合した。

負け側の教材は筋・段を `10-n` にし、所属を交換した鏡像。先手５九玉と６九・４九・６八・４八歩、後手１一玉・５七飛・６七金、後手番の一手後相当局面である。後手の５八飛が合法で、応手後は先手が詰む。開始側は先手のまま評価する。自分の最初の一手の経路を再現するテストではなく、計画どおり一手後相当の局面を採点操作へ直接渡す。

[日本将棋連盟の対局規則](https://www.shogi.or.jp/match/taikyoku_rules/)第2条第4・5項を確認した。相手を先に詰ませることが勝利であり、詰みは応対しても玉が取られることを防げない状態である。持ち歩百万枚は実戦で到達可能な局面ではなく、内部モデルで表現可能な極端入力での優先順位を検証するもの。

- `BoardMove` は盤上移動を表す変更不可のデータ。`Square` は筋・段を持つマスの値。いずれも指す操作ではない。
- `apply_move` は局面へ移動を適用する操作、`legal_moves` は合法手を列挙する操作、`is_checkmate` は手番側の詰みを判定する操作。
- `_two_ply_score` は自分の一手後から開始側の最悪応手評価を返す非公開操作。評価データの組は勝ち `(1, 0)`、通常 `(0, 駒得差)`、負け `(-1, 0)`。先頭の区分を先に比較するため、通常点の桁数が勝敗を逆転させない。
