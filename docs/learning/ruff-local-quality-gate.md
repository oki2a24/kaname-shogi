Pythonコードの整形と基本検査をプロジェクト内だけに導入し、別PCのcloneでも同じ構築手順を再現する。将棋ルールや強化方式の変更は扱わず、第76回の強化設計とは別の開発環境整備とする。

## 要点と選定理由

- Ruffは整形と検査を一つで扱える。Black＋Flake8は整形と検査を別管理、Black＋Pylintは型推論・設計上の提案まで扱う。今回は管理対象を少なくし、基本検査から理解するためRuffを選んだ。
- Python 3.9.6でインストールできたRuff 0.16.10、Black 25.11.0、Flake8 7.3.0、Pylint 3.3.9を比較した。最新版であることや全バグの検出性能は保証しない。
- 既存24ファイルでRuffの `E4,E7,E9,F` は指摘0件。`I,B`追加はimport順序20件。Flake8既定185件（行長170・継続行字下げ15）、行長88・E203除外で50件。Pylint既定104件は規約77・refactor17・警告9・エラー1。エラー1はTypeErrorを期待して意図的に禁止引数を渡すテストだった。件数は検査範囲が違うため順位ではない。
- 整形はRuff・Blackとも20ファイルに差分。調査コピーで両方ともAST一致・326テスト成功。最初のコピーはUSI起動ファイル不足で2テスト失敗し、コピーを補って成功した。
- 仮想環境（`.venv`）は依存関係の保存場所であり、別PCへの配布物ではない。`requirements-dev.txt` は導入する固定版データ、`setup_dev.py` はその導入とGit設定を行う操作である。
- インデックスはコミット予定内容。作業ツリーは編集中の内容。フックではGitのblobを一時領域へ複写して前者を検査する。自動修正と再ステージは行わない。

出典：[Ruff設定](https://docs.astral.sh/ruff/configuration/)、[リンター](https://docs.astral.sh/ruff/linter/)、[フォーマッタ](https://docs.astral.sh/ruff/formatter/)、[Gitフック](https://git-scm.com/docs/githooks)。

## 実際の変更と判断

- `.venv` にRuff 0.16.10を導入。`pyproject.toml` に固定版・py39・行長88・基本ルール・Pythonのみの対象を明記した。
- `setup_dev.py` に初回・再実行、既存フック競合時の停止、導入失敗時の停止を実装した。グローバルGit設定は変更しない。macOS/Linux向け通常cloneが対象で、Windows・別worktreeは対象外。
- `.githooks/pre-commit` と `check_staged_python.py` で、ステージした通常Pythonファイルと設定を検査する。削除済み・未追跡ファイルは混ぜない。シンボリックリンクと未解決競合は止める。
- 計画で想定したcheckoutによる展開では、改行変換やフィルタが入り得る。実際には `git cat-file blob` でステージ内容をそのまま取得する方式にした。
- Ruff 0.16.10の `format .` がMarkdownコード例まで整形したため、その操作で生じた既存文書22件の差分を元のHEADから復元し、`include = ["*.py"]` を追加した。文書整形は今回の範囲に含めない。
- READMEに別PCセットアップ・日常作業・手動構築・復旧手順、AGENTS.mdにアシスタントの確認・検査手順を追記した。
