# 第21回：空マスへの移動適用

## 目的

候補生成と実際の移動適用の違いを理解し、空いている到着マスへの移動だけを扱う。今回の学習では、駒取り、持ち駒、成り、不成、手番更新、王手、合法手判定、詰み、CLI入力、評価、探索は扱わない。

## 要点

- 候補生成は到着先を調べる操作で、盤面を変更しない。
- 移動適用は出発マスを空にし、空いている到着マスへ駒を置く盤面変更の操作である。
- `Square` は筋・段を表す値であり、駒を動かす操作ではない。
- `Board` は各マスの駒または空を保持する可変の盤面データである。
- 不正な入力を検出した場合、盤面を変更してはいけない。
- 今回は既存の可変な `Board` を直接変更する方式で進める。
- 将来、評価・探索で複数の局面を扱う段階では、不変な盤面または局面を返す方式への見直しを課題として残す。

## 出典

- [日本将棋連盟「対局規則」](https://www.shogi.or.jp/match/taikyoku_rules/)

## 確認問題と回答

### 第1問：前回の振り返り

本人の回答：候補生成時は盤の状態が変化していない。実際の移動時は、盤の状態が変わる。

アシスタントの補足：正しい。候補生成は盤面を変更せず、移動できそうな到着マスを調べる操作である。一方、実際の移動適用は、出発マスを空にし、到着マスへ駒を置くことで盤面を変更する操作である。

### 第2問：不正入力時の不変性

本人の回答：盤の状態が変わってしまうから。

アシスタントの補足：正しい。不正な入力が判明した後に出発マスを空にすると、移動に失敗したのに盤面だけが変更される。したがって、入力の検証を先に完了させ、前提を満たす場合だけ盤面を変更する。

### 第3問：可変方式と不変方式

本人の回答：可変方式で進める。ただし、将来の評価・探索では不変方式の利点も見越し、将来的には不変にすることをやるべきこととして残す。

アシスタントの補足：方針として採用する。今回は `Board` の既存設計に合わせて移動操作が盤面を変更する可変方式にする。一方、評価・探索で局面を分岐させる段階では、元の局面を保ったまま次の局面を作れる不変方式が有用になるため、将来の設計課題として記録する。

## 振り返り

本人の振り返り：候補生成では盤面が変わらない、移動適用は盤面が変わる、という違いがわかった。

アシスタントの補足：正しい。候補生成は移動先を調べる操作であり、移動適用は検証に成功した後に出発マスと到着マスを変更する操作である。今回の実装では、不正入力時に盤面を変更しないことも移動適用の契約に含めた。

## 実装・検証記録

- `move_piece(board, source, destination)` を `kaname_shogi/movegen.py` に追加した。
- 空の到着マスへの移動では、出発マスを空にし、同じ `Piece` を到着マスへ置く。
- 空の出発マス、占有された到着マス、同一マスは `ValueError` とし、盤面を変更しない。
- TDDのRedでは未実装による失敗を確認し、最小実装後に対象4テストと全95テストが成功した。
- CLI実行と差分確認は完了した。独立したレビュー用サブエージェントはこの環境では利用できず、差分ベースの自己レビューを行った。
