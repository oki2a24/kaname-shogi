# 時計つき棋譜を短いCLI操作で保存・再読込する

## 目的・範囲

2026-10-20、ランダム方式の人間対コンピュータCLIを短く一回観察し、指定した二手の棋譜と時計が保存・読込・再保存を通じてどう保たれるか確認した。実行時に表示・保存された値を記録し、所要時間や探索深さの固定期待は置かない。

今回の対象は通常対局CLIの操作と、その表示・JSONの読み取りまで。製品コード・テスト・設定・承認済み設計は変更していない。テストは実行していない。今回のテーマを実装承認とは扱わない。

型名と操作の区別では、`GameRecord`は開始局面と成功手の履歴を表す棋譜データ、`CliSession`は棋譜データと任意の時計をまとめたセッションデータである。`save`と`load`はそれぞれファイルへ保存する操作、ファイルから検証済みセッションを読む操作を表す。

## 実行した一回と観察結果

リポジトリ直下から次を起動した。

```sh
.venv/bin/python -m kaname_shogi
```

入力した開始条件は次のとおり。

1. 対局形式 `2`（人間対コンピュータ、先手人間）
2. 一手選択方針 `1`（ランダム）
3. 持ち時間は空入力（既定の10分）
4. 秒読みは空入力（既定の30秒）

先手人間が`move 7 7 7 6`を入力した。後手コンピュータの実際のランダム手は`move 8 3 8 4`だった。CLIは次の値を表示した。

```text
探索状態: 完了
消費時間: 0.013秒
後手の残り持ち時間: 09:59.986（秒読み30秒）
後手の指し手: move 8 3 8 4
```

人間の次の手番で`save /tmp/kaname-shogi-clocked-roundtrip-before.json`を実行した。直後に同じ手番でそのファイルを`load`し、再表示された手番が先手、盤面が二手後の局面であることを確認した。その後、`save /tmp/kaname-shogi-clocked-roundtrip-after.json`を実行した。終了時は入力EOFで対局を終えた。

開始時計はJSON上で持ち時間`600000ms`、秒読み`30000ms`だった。保存前後のJSON比較は次の結果になった。

| JSON部分 | 観察した値・比較結果 |
| --- | --- |
| 外側形式 | `kaname-shogi-cli-session-v1` |
| 棋譜形式 | `kaname-shogi-game-record-v1` |
| `game_record.moves` | `7七→7六`、続いて`8三→8四`（いずれも成らず） |
| `clock.initial_time_ms` | `600000` |
| `clock.byoyomi_ms` | `30000` |
| `clock.sente_remaining_ns` | `600000000000` |
| `clock.gote_remaining_ns` | `599986433834` |
| 保存前後の`game_record` | 一致（`True`） |
| 保存前後の`clock` | 一致（`True`） |
| 保存前後のJSON全体 | 一致（`True`） |

後手時計のJSON値の差は`600000000000 - 599986433834 = 13566166ns`（約13.566ms）。画面表示はミリ秒単位に切り捨てられて`0.013秒`、残り`09:59.986`だった。表示値だけから保存されたnsを逆算せず、JSONの実値も併記した。ランダム方式なので探索深さは表示されず、今回の観察対象でもない。

## 確認できたことと限界

- 人間の次の手番で保存・読込・再保存でき、読込後の局面と手番は保存時点へ戻った。
- 棋譜の二手と先後の時計値が一つのJSONに保存された。今回の保存前後では棋譜部分、時計部分、JSON全体が一致した。
- 開始時に先手・後手へ同じ時計条件を設定し、今回減ったのは後手の時計だった。人間の入力・保存・読込に伴う時計値の変化は前後JSONになく、時計を差し引かない契約と整合した。
- この一回は保存・再読込の成功経路だけを観察した。不正ファイル、読込失敗時の状態保持、別の初期局面・時計値・OSでの挙動は確認していない。表示された時間・ランダム手は今回の実測であり、次回の期待値ではない。

## 最後の理解確認（2026-10-20）

**確認したいこと:** 棋譜と時計が保存・読込を通じてどう扱われ、どの時間が時計から差し引かれないかを説明できるか。

**質問:** 今回の保存前後のJSON比較を根拠に、棋譜の二手と時計値がどう保たれたか、また保存・読込・人間の入力にかかった時間が時計へどう扱われたかを説明してください。

**本人の回答:**

> 保存・読込には時間を消費しない、人間の入力にかかった時間も消費しない

**アシスタントの補足:** 保存・読込、人間の入力にかかった時間は時計から差し引かない。今回のJSONでは、先手は`600000000000ns`のまま、後手はコンピュータの一手で`600000000000ns`から`599986433834ns`へ減り、その後の保存・読込・再保存の前後で値が一致した。後手の差`13566166ns`は画面表示の`0.013秒`と同じ一回のコンピュータ手の実測である。棋譜には`7七→7六`と`8三→8四`の二手が手番順に保存され、読込後の再保存でも棋譜部分が一致した。本人の回答は人間の操作時間を時計から差し引かない点を捉えている。
