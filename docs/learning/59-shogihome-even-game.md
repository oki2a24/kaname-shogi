# 第59回：ShogiHomeで平手対局する

## 目的

USIの局面再現と合法な一手応答を実装した `kaname-shogi` をShogiHomeへ登録し、標準平手の短い対局で、合法な応手が盤面・棋譜へ反映され、通常の投了で終局できるかを実機で確かめる。エンジンの強さや全てのShogiHome機能との互換性は評価しない。

## 資料と根拠の範囲

- [USI一次資料](https://hgm.nubati.net/usi.html)はUSIの仕様を読む根拠とした。そこに書かれたコマンドを全てShogiHomeが送る、または今回のエンジンが扱うべきとは推測していない。
- [ShogiHome公式のエンジン登録手順](https://github.com/sunfish-shogi/shogihome/wiki/%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%B3%E7%99%BB%E9%8C%B2%E6%89%8B%E9%A0%86)、[スクリプト実行条件](https://github.com/sunfish-shogi/shogihome/wiki/%E3%82%B7%E3%82%A7%E3%83%AB%E3%82%B9%E3%82%AF%E3%83%AA%E3%83%97%E3%83%88%E3%82%84%E3%82%A4%E3%83%B3%E3%82%BF%E3%83%97%E3%83%AA%E3%82%BF%E5%9E%8B%E8%A8%80%E8%AA%9E%E3%81%A7%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%B3%E3%82%92%E5%AE%9F%E8%A1%8C%E3%81%97%E3%81%9F%E3%81%84%E6%96%B9%E3%81%B8)、[エンジン機能の操作方法](https://github.com/sunfish-shogi/shogihome/wiki/%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%B3%E3%82%92%E4%BD%BF%E3%81%86%E6%A9%9F%E8%83%BD%E3%81%AE%E6%93%8D%E4%BD%9C%E6%96%B9%E6%B3%95)、[基本操作](https://github.com/sunfish-shogi/shogihome/wiki/%E5%9F%BA%E6%9C%AC%E7%9A%84%E3%81%AA%E6%93%8D%E4%BD%9C%E6%96%B9%E6%B3%95)を公式手順・画面操作の参考にした。今回の対局中のプロトコル内容までは、これらの資料から事実認定していない。
- 第54回の[使い捨てプローブ記録](54-usi-shogihome-connection-scope.md)は、７六歩後の局面・時計付き `go` に `bestmove resign` を返した一例である。合法な応答をShogiHomeが受け入れることや、通常対局を示す証拠ではない。
- 第56回には別の使い捨て記録用エンジンが複数手の `position startpos moves ...` を受け取った観測がある。今回の `kaname-shogi` の対局実績とは別である。
- 第55〜58回の相互変換、平手手順の再生、合法な `bestmove` 生成、コマンド間の局面保持と、それぞれのテストはローカル実装の確認である。ShogiHomeで実際に合法手が受理される証拠は本回で初めて得た。

## 本人との設計確認

実対局はShogiHomeのローカル対局を使い、平手、先手を人、後手を `kaname-shogi` とする。人間が合法手を二回指し、二回の合法な応手を確認した後、人間が投了する。詰みまでの長時間対局、強さ評価、特殊局面、時計管理の評価、棋譜ファイルの保存は範囲外とした。本人は設計案・実装計画を承認してから変更と実機操作へ進んだ。

## 学んだこと

- ローカルテストで `bestmove` が合法だと分かることと、ShogiHomeがその応答を受け入れて盤面を進めることは別の確認である。今回、短い実対局により後者も確かめられた。
- 使い捨てプローブの投了応答は、USI終了通知が一例で届いたことを確認したものだった。今回の終了確認は、実エンジンとの対局を人間が投了し、ShogiHomeの画面が「対局終了（投了）」を表示したことによる。
- エンジン設定画面では `USI_Ponder` が既定ONと表示された。ローカルコードは `go ponder` を拒否するため、今回の局面では相手番思考をOFFにした。USI通信ログは無効のまま対局したため、ShogiHomeがどのコマンドを実際に送信したか、OFF設定によってどの送信が変わったかは確認していない。
- 二回の応手を確認した結果は、探索の強さ、時計管理、他のShogiHome版・OS、全USIコマンドとの互換性を証明しない。

## ShogiHome実対局の観測（2026-10-04）

- 対象アプリはMac版ShogiHome 1.28.1。作業ブランチの `kaname-shogi-usi` をエンジンとして登録し、エンジン管理で「対局」用途を有効にして保存した。
- 「ローカル対局」で先手を人、後手を `kaname-shogi`、開始局面を「平手」にした。持ち時間は画面既定の10分+30秒で開始したが、時計機能の正確さは評価していない。
- `USI_Ponder` は登録後の設定画面に既定ONと表示された。`usi_engine.py` の既存実装・テストでは `go ponder` を未対応として拒否するため、設定画面でOFFを選び、対局設定に「Ponder: OFF」と出ることを確認して開始した。USI通信ログは有効化していない。
- 棋譜は `1 ☗７六歩`、`1... ☖４四歩`、`2 ☗２六歩`、`2... ☖９二飛` の順に進んだ。各応手はShogiHomeの棋譜と盤面に表示された。画面に表示された移動は盤面上の合法手であり、ShogiHomeがエンジンの応答を受け入れた。
- 人間が「投了」を選び、確認画面でOKを選択した後、ShogiHomeは「対局終了（投了）」を表示した。閉じた後の棋譜には5手目として「投了」が記録され、対局日時と終了日時も表示された。
- 対局記録はShogiHome上で未保存の新規棋譜として残っている。KIF等のファイルへ保存・エクスポートしていない。通信ログを取得していないため、今回のコマンド列や終了通知は記録していない。

### アシスタントの補足

人が画面から指した７六歩の後に、ShogiHomeの盤面と棋譜へ `kaname-shogi` の４四歩が表示された。続けて人が２六歩を指すと、９二飛が表示された。人が投了した後には「対局終了（投了）」が表示され、棋譜にも投了が記録された。この画面上の応手と終局が、今回の実対局を確かめた証拠である。第54回の使い捨てプローブでは `bestmove resign` を返す一例を試し、終了通知を観測しただけで、合法な通常応手や往復対局は確認していない。第55〜58回の確認はローカル実装とテストによるものだった。今回も通信ログを取得していないので、ShogiHomeが実際に送った全コマンド列やPonder設定で通信がどう変わるかは未確認のままである。
