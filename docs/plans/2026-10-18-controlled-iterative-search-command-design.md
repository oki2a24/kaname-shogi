## 選択した構成と理由

本人は、既存比較入口の拡張より専用入口を選択した。時間制御の観察に集中でき、比較探索の所要時間と探索予算を混同しないため。目標・上限を直接指定し、持ち時間からの予算計算は通さない。Ctrl+Cは協調停止へ変換せず中断終了とする。同期探索の内部記録を外から取り出す仕組みを増やさない。

以下の名前・配置・出力ラベル・エラー境界・確認方針は草案で具体化した提案であり、個別選択だけでは承認済みとしなかった。その後の設計全体への本人「yes」により、これらも承認対象に含まれた。

新モジュール名は `kaname_shogi.search.run_controlled_iterative`、入口は `main(argv=None)`（引数を解析して探索・表示を行い、終了コードを返す操作）。`argv` は引数文字列の一覧、Noneは実行時引数を使う。モジュール実行時はmainの戻り値をプロセス終了コードへ渡す。mainを直接呼ぶ場合、入力誤りとKeyboardInterrupt以外の内部例外は伝播する。

## 入力契約

次は未実装コマンドの利用形を示す設計例であり、実行済みの結果ではない。

```sh
.venv/bin/python -m kaname_shogi.search.run_controlled_iterative \
  --sfen "8k/9/9/9/9/9/9/9/K8 b - 1" \
  --max-depth 4 --target-ms 100 --maximum-ms 200
```

| 引数 | 内容・制約 |
| --- | --- |
| `--sfen` | 必須。既存parse_positionへ渡すSFEN文字列。入力局面を一回探索する |
| `--max-depth` | 必須。1以上の整数。深さ1からこの深さまでを要求する |
| `--target-ms` | 必須。0以上の整数ms。次の深さを開始する際の目標期間 |
| `--maximum-ms` | 必須。目標以上の整数ms。深さ内部でも確認する上限期間 |
| `--help` | 使用方法と制約を標準出力へ表示して0。探索や時計原点取得をしない |

深さ・予算に既定値は設けない。型変換はargparseのintを用い、整数として変換できない小数・文字列を入力誤りにする。範囲条件は変換後の値で検査する。目標と上限は既存SearchBudgetで `0 ≤ target_ms ≤ maximum_ms` を検査し、0を時計なしへ変換しない。独自の深さ上限や予算上限は設けず、資源制限は残る。

既存SFEN解析の受理範囲をそのまま使い、完全な対局履歴や全局面の妥当性検査を追加しない。先後の視点は入力局面の手番で決める。

argparseの通常のオプション解析に従い、未知引数は2、同一引数の反復は最後の値を採用する。長い引数名の一意な省略形も標準挙動に従う。ヘルプを除き必須条件はすべて検査する。重複拒否や独自の数値表記規則は追加しない。

## 責務・データの流れと時計原点

コマンドが入力解析、予算データ作成、時計原点取得、制御データ作成、探索呼出し、結果整形、出力、終了コードを所有する。探索アルゴリズム・将棋規則・採点を複製しない。

| 既存部品 | 意味と今回の使い方 |
| --- | --- |
| `comparison.make_parser` | SFEN必須の解析器を作る操作。新入口で深さ・両予算を追加し、既存コマンドの引数を変更しない |
| `comparison.parse_position` | SFENから局面データを作る操作 |
| `SearchBudget` | 目標・上限期間を保持するデータ。直接指定値から構築 |
| `shogi.make_controlled_operations` | 開始側視点の将棋用操作セットを作る操作 |
| `time.monotonic_ns` | 単調時計の整数nsを読む操作 |
| `SearchControl` | 一探索の期限と停止要求を管理する制御データ |
| `iterative_deepening.search_controlled` | 局面・上限深さ・操作セット・同じ制御を受けて最終結果を一件返す同期操作 |
| `ControlledSearchResult` | 終了状態・選択手・最新完了記録を持つデータ |
| `IterationResult` | 完了深さ・その探索結果・完了反復累計を持つデータ |
| `comparison.format_move/format_score` | USIと日本語の手／開始側視点の評価を整形する操作 |

入力検査・SearchBudget構築・操作セット作成を終えてから、探索呼出し直前にmonotonic_nsを一回読み原点とする。その原点でSearchControlを一回構築して探索へ渡す。時計の参照関数も同じ単調時計とする。実行条件を含め、通常出力はすべて探索返却後にまとめるため、探索前の表示待ちは入らない。

合法予備手の準備・全深さ・子の調査に同じ制御を渡し、原点・予算・停止要求を途中で作り直さない。入力解析・操作セット作成・結果整形と出力は予算に含めない。SearchControl構築と探索への受渡し時間は原点後なので含む。時間は整数msからnsへ既存制御が変換する。経過時間の計測表示は追加しない。

calculate_search_budgetと設定ファイル読込は呼ばない。予算式を変更せず、その出力に相当するデータを直接与える入口とする。

## 終了結果と表示

標準出力に実行条件と一件の終了結果を、項目名付きの日本語の行で表示する。表形式の深さ別途中出力、比較成功表示、機械向けJSONは設けない。開始側視点を先手／後手で明記する。評価・手の文字列表現は既存整形を使う。

実行条件の行は `入力SFEN`、`評価視点`、`指定上限深さ`、`目標期間(ms)`、`上限期間(ms)`。終了結果は `終了状態`、`選択手`、`手の由来`、`完了記録` の順。記録ありなら続けて `完了深さ`、`完了深さの評価`、`完了深さの訪問回数`、`反復累計（完了した深さまで）` を表示する。

| 状態 | 終了状態ラベル | 選択手・由来 | 完了記録 |
| --- | --- | --- | --- |
| COMPLETE | COMPLETE（指定上限深さまで完了） | 結果の手・完了結果 | あり。要求上限の深さ・評価・訪問数・累計 |
| NO_LEGAL_MOVE | NO_LEGAL_MOVE（合法手なし） | なし・該当なし | なし。深さや評価を作らない |
| STOPPED・記録あり | STOPPED（通常停止） | 結果の手・完了結果 | あり。最後の完了深さの情報 |
| STOPPED・記録なし | STOPPED（通常停止） | 結果の手・合法予備手 | なし。評価を付けない |
| SUPPRESSED | SUPPRESSED（応答抑制） | なし・該当なし | 保持されていれば記録だけを表示できる |

完了記録なしは `完了記録: なし（評価なし）` とする。完了深さを0や1として捏造せず、記録用の深さ・評価・訪問・累計の行は出さない。記録ありなら `完了記録: あり`。上限深さと完了深さを別の項目にする。

通常の本コマンドは停止・抑制要求を送らない。時間予算はSTOPPEDを生じ得る。SUPPRESSEDは既存の戻り値契約を漏れなく表示するための扱いで、これを起こす引数は設けない。記録があってもlast_completed内の手を選択手へ復活させず、投了とも表示しない。

STOPPEDから「目標に達した」「上限に達した」などを断定しない。現行結果型は終了理由をそこまで保持しないため。後から時計を読んで原因を推測しない。

累計は完了反復の訪問数だけ。準備・中断反復の訪問を推測加算しない。訪問数は実行時間や全作業量ではない。合法手なしを詰みや投了と断定しない。

概念表示例（0予算、合法手がある場合。実測結果ではない）：

```text
終了状態: STOPPED（通常停止）
選択手: 9i9h（9九→9八）
手の由来: 合法予備手
完了記録: なし（評価なし）
```

## 入出力・終了コード・例外境界

| 終了コード | 契約 |
| --- | --- |
| 0 | COMPLETE / NO_LEGAL_MOVE / STOPPED / SUPPRESSEDを受け取り、表示を完了。ヘルプも0 |
| 1 | 内部故障。mainは例外を原因付きで伝播し、通常のモジュール実行でtracebackと非成功終了を得る |
| 2 | 必須不足・未知引数・数値変換失敗・深さ範囲違反・予算範囲違反・SFEN入力不正 |
| 130 | コマンド処理中に捕捉したKeyboardInterrupt |

0は要求上限まで必ず到達した意味ではない。予算による通常停止や手なしも観察結果として成功とする。状態は終了結果の表示で区別する。

argparseによるSystemExitだけを解析呼出しの境界で終了コードへ変換する。入力値の範囲検査・SearchBudget構築・SFEN変換のValueErrorだけを入力誤りとして標準エラーへ診断し2を返す。不正入力では探索を開始せず標準出力は空。操作セット生成・時計・探索・整形・出力のValueError等を入力誤りとして捕捉しない。内部故障は「正常停止」に置き換えない。

KeyboardInterruptの捕捉範囲はmainが行う解析器作成から引数解析・入力検査・操作セット作成・時計原点取得・探索・整形・最終出力まで。Ctrl+Cを受けたら探索を再開せず、request_stopも呼ばず、最終結果を回収・再表示しない。標準エラーへ `中断: Ctrl+C。結果表示は未完了です` を診断して130を返す。

探索返却前は結果を持たず、通常出力もまだない。返却後の整形・出力で中断した場合も新たな結果を表示し直さない。出力済みの行・一部の文字は取り消せないため残り得る。中断時の部分出力を完了した結果表示とは扱わず、130と診断を優先して判断する。出力を一回にまとめてもOS上の原子的表示は保証しない。

捕捉ハンドラー自身での再Ctrl+C、モジュールimport前後やmain終了後、インタープリター終了時、出力先故障とシグナルの競合についてまで130と診断完了を保証しない。追加のシグナル処理や再試行は設けない。出力失敗は通常の例外として伝播させる。時間・出力完了の保証を拡大しない。

| 対象契約 | 代表ケース・独立期待値 | 検出したい誤り |
| --- | --- | --- |
| 必須・範囲・入力 | 各必須不足、小数・文字列、深さ0/1、予算負数・0・等値・逆転、未知引数、不正SFEN、ヘルプ | 既定値の混入、不正時の探索開始、0を時計なしへ変換 |
| 引渡し | 指定深さと両msをそれぞれ異なる値にし、受け取る予算・操作セット・制御を観察 | 目標と上限の入替、単位誤換算、停止なし入口や予算計算への誤接続 |
| 原点 | 注入可能な時計で入力・操作セット作成後に原点を取得し、制御へ同じ原点と時計を渡す | 起動直後からの誤計時、原点の取直し、異なる時計の混在 |
| 記録なしの通常停止 | 玉だけ局面・0予算。STOPPED、合法予備手、記録・評価なし | 投了化、深さ1の架空記録、評価0の捏造 |
| 記録ありの通常停止 | 独立に構成した深さ2・手B・評価1・訪問7・累計10の結果データ | 指定深さ3を完了深さとして表示、記録なしとの混同、累計への未完了加算 |
| 完了と手なし | 完了記録付きCOMPLETE、NO_LEGAL_MOVEの手・記録なし | 成功0を全深さ完了と同一視、旧入口と同じ手なし深さ1を作る |
| 抑制 | 記録なし／ありのSUPPRESSED | 選択手の復活、投了への変換、保持記録の消失 |
| 視点・手・評価 | 先手/後手の小局面、正負/勝ち/負け、成り・駒打ち・なし | 視点固定、符号反転、手の表記欠落 |
| エラー境界 | 入力段階のValueErrorと、操作セット・時計・探索・整形・出力での内部例外を分ける | 広い捕捉で故障を入力不正2へ変換、故障をSTOPPED扱い |
| Ctrl+C | 入力中・探索返却前・返却後の整形/出力中にKeyboardInterrupt、部分出力あり | 偽の完了表示、結果の再取得、0終了、抑制要求への誤変換 |

既存test_search_controlは期限境界・原点・0とNone、test_search_controlled_resultは状態整合性、test_search_alpha_beta_controlled・test_search_shogi_controlled・test_search_iterative_deepening_controlledは探索・将棋・反復内部を補完する。test_search_comparisonは既存整形を補完し、test_search_compare_iterativeは旧コマンド契約を守る。ただし、これらは新コマンドの必須引数・予算引渡し・出力対応・例外捕捉範囲を単独では検証しない。

時計境界は固定・注入時計による独立期待値、結果表示は独立に構成したデータによる期待値で確認する方針。実時間で「必ず深さ2で止まる」と期待しない。玉だけの実探索と0予算は接続確認の代表例であって全局面への証明ではない。代表的な誤りを検出できるかの実確認は後続の実装範囲へ残し、今回のレビューや文書検査を製品動作検証と扱わない。
