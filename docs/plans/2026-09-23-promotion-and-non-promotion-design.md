# 成り・不成の基礎：設計仕様

作成日：2026-09-23

## 目的と範囲

盤上の成駒を表現し、成り・不成を選ぶ盤上移動、強制成り、成駒を取ったときに基本駒種として持ち駒へ戻す処理を実装する。

日本将棋連盟の対局規則では、駒が移動する際に移動前または移動後が敵陣なら成ることができ、一度成った駒は元に戻せないと定めている。[対局規則・第5条第4項](https://www.shogi.or.jp/match/taikyoku_rules/) 同連盟は飛車・角・銀・桂・香・歩の成駒と、その動きを示している。[対局規則・第3条第3項、第4条](https://www.shogi.or.jp/match/taikyoku_rules/)

今回扱うのは、未成駒の移動を成りまたは不成として局面へ適用するところまでである。成駒の移動先候補とその局面適用、王手・合法手、打ち歩詰め、CLI入力、USI/SFEN、履歴、探索は扱わない。

## 駒の型と責務

### `PieceType`

`PieceType` は盤上の駒種を表すデータとし、未成8種と成駒6種の計14種を持つ。

- 未成: `KING`（玉・王）、`ROOK`（飛車）、`BISHOP`（角行）、`GOLD`（金将）、`SILVER`（銀将）、`KNIGHT`（桂馬）、`LANCE`（香車）、`PAWN`（歩兵）
- 成駒: `DRAGON`（竜王）、`HORSE`（竜馬）、`PRO_SILVER`（成銀）、`PRO_KNIGHT`（成桂）、`PRO_LANCE`（成香）、`PRO_PAWN`（と金）

盤上では、未成歩とと金、角と馬のように動き・表示が異なる状態を区別する必要があるため、成駒も盤上駒種として直接表す。

### `BasicPieceType`

`BasicPieceType` は、持ち駒・初期配置・成駒からの復元で使う基本8種を表すデータである。値は `KING`、`ROOK`、`BISHOP`、`GOLD`、`SILVER`、`KNIGHT`、`LANCE`、`PAWN` とする。

`Hand` の `count`、`add`、`remove` と `apply_drop` は `BasicPieceType` だけを受け取る。玉の持ち駒は従来どおり拒否する。これにより、成駒を持ち駒へ直接入れたり、成った状態で打ったりする操作を型の境界で防ぐ。

### `Piece`

`Piece` は引き続き不変の値で、`piece_type: PieceType` と `side: Side` を保持する。成りでは既存の値を変更せず、移動先へ成駒の新しい `Piece` を置く。

`Piece.base_piece_type` は、盤上の駒種を対応する `BasicPieceType` へ戻す読み取り専用の値とする。例えば、と金は歩、馬は角、竜は飛車へ戻す。`Piece.is_promoted` は成駒なら `True`、未成駒なら `False` を返す読み取り専用の値とする。

駒取りは `target_piece.base_piece_type` を `Hand` へ加える。これにより、成銀を取れば銀、馬を取れば角として持ち駒になる。

## 成り・不成を伴う局面適用

### `apply_move`

`apply_move(position, source, destination, *, promote=False)` は、未成駒の候補内移動・駒取り・手番交代に加え、成りの選択を局面へ適用する公開操作とする。`promote` は、この指し手で成りを選ぶかを表す真偽値であり、既存の3引数呼び出しは不成として互換を保つ。

以下の規則を検証し、失敗時は `ValueError` として盤面81マス、手番、先後双方の持ち駒を変更しない。

1. 既存どおり、出発駒の所有者と手番、未成駒の移動先候補、相手玉を取らないことを検証する。
2. 成駒を出発駒にする移動は拒否する。成駒の移動候補を未成駒の規則で誤って扱わず、次回の成駒の動きへ安全に分けるためである。
3. `promote=True` は、未成の飛・角・銀・桂・香・歩だけに許す。玉・金・成駒での指定は拒否する。
4. 先手は一〜三段、後手は七〜九段を敵陣とする。出発または到着のいずれかが敵陣でなければ、`promote=True` を拒否する。
5. 先手の歩・香が一段へ、先手の桂が一・二段へ進む場合、後手の歩・香が九段へ、後手の桂が八・九段へ進む場合は強制成りとする。該当する `promote=False` を拒否する。
6. すべての検証後、空マス移動または駒取りを適用する。`promote=True` なら到着マスへ対応する成駒を置く。相手の成駒を取るときは、相手駒の基本駒種を手番側の `Hand` へ1枚加える。成功後だけ手番を交代する。

`move_piece(board, source, destination)` は引き続き、方向・候補・成りを検証しない盤面だけの低水準操作である。この操作の公開契約は変更しない。

### `apply_drop` と二歩

`apply_drop(position, piece_type, destination)` の `piece_type` は `BasicPieceType` とする。成功時は対応する未成の `PieceType` を持つ `Piece` を配置し、成った状態の駒は配置しない。

二歩は、同じ筋に手番側の未成歩（`PieceType.PAWN`）があるかだけを調べる。と金（`PieceType.PRO_PAWN`）は二歩の対象に含めない。

## 確認方法

- `PieceType` の14種、`BasicPieceType` の8種、成駒から基本駒種への復元、成駒判定、`Piece` の不変性をモデルテストで確認する。
- 先後双方について、敵陣への任意成り、不成、移動前だけが敵陣の任意成り、歩・香・桂の強制成りを確認する。
- 玉・金・成駒の成り、敵陣外の成り、強制成りでの不成を拒否し、局面が不変であることを確認する。
- と金・成香・成桂・成銀・馬・竜を取ると、歩・香・桂・銀・角・飛として持ち駒へ戻ることを確認する。
- と金がある筋へ歩を打てることを確認し、二歩が未成歩だけを対象にすることを確認する。
- 成駒の出発移動を拒否することを確認する。
- 既存の移動・駒打ちを含む全テスト、CLI、`git diff --check` を実行する。

## 将来への接続

次回は、`PieceType` の盤上14種を使い、竜・馬・金相当の成駒の移動先候補を実装する。その段階で、同じ出発・到着マスに成りと不成の二つの指し手があり得ることを表す不変の `Move` 値（指し手データ）の導入を検討する。`Move` は局面を変える操作ではなく、局面に適用する指し手の内容を表すデータである。

## 実施しないこと

成駒の移動先候補、成駒の移動、王手・詰み・合法手、打ち歩詰め、CLI入力、USI/SFEN、対局履歴、評価、探索は今回の変更に含めない。
