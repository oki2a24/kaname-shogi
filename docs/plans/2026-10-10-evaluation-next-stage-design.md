## 読む範囲と手の比較

評価視点は開始局面の手番側に固定する。途中で手番が変わっても点数の意味を反転しない。

1. 開始局面の合法手を、自分の候補手とする。空なら既存の選択境界と同じく `None`（選択できる手なし）を返す。選択操作自体は投了・勝敗を決めない。
2. 候補ごとに独立した局面の複製へ一手を適用する。相手が詰みなら、この候補は勝ちとして評価し、応手を調べない。
3. 相手の全合法手を調べる。各応手も独立した複製へ適用する。その結果、自分が詰みなら負けとして評価する。それ以外は自分視点の駒得差で評価する。
4. 候補の値には、相手の応手後の評価のうち自分に最も不利なものを使う。
5. 自分の候補のうち最も有利な値を持つ手を選ぶ。同点は最高評価の候補だけから、呼び出し側が渡す乱数器で一様に選ぶ。

自分の一手と相手の一手、合計二手で読むのを止める。詰み判定に必要な合法な防御手の有無は既存の詰み判定で確認するが、防御手から先の駒得を比較する探索はしない。

この最大・最小の比較がミニマックスである。枝刈り、可変深さ、反復深化、静止探索、置換表、新評価項目は同時導入しない。

## 評価の表現と境界条件

設計上の評価を「勝ち・通常・負け」の区分と、通常の場合の駒得差に分ける。大小比較は `勝ち > 通常 > 負け`、通常同士だけ駒得差を比較する。勝ち同士・負け同士は同点とし、詰みまでの距離では差を付けない。具体的なPythonの型や保存方法は実装計画で定める。

勝敗を十分大きな固定整数に置き換える方式は採らない。持ち駒の数量などにより駒得差がその整数を超え、勝敗の優先順位が逆転する問題を避けるためである。

相手に合法手がなく、詰みでもない場合は、その一手後の局面の駒得差を候補の値にする。二手後に自分の合法手がなく詰みでもない場合も、通常の駒得差で評価する。引き分け・勝ち・負けを新たに認定しない。玉なし等の部分局面についても、既存の詰み判定の契約を変えない。

すべての候補が負けなら、負け評価で並んだ候補から抽選する。負けを必ず回避する保証はない。

開始局面、候補の手データ、双方の持ち駒を変更しない。抽選時だけ渡された乱数器の状態が進む。合法手を前提とする既存の選択境界を維持し、内部の不整合をRandomへの暗黙の切り替えで隠さない。

## 具体例

先手番。先手は９九玉・５五飛、後手は１一玉・５三金・５四歩、双方の持ち駒なし。他は空マスの教材用部分局面である。

５四飛で歩を取る直後は先手の駒得差が2点増えるが、５四金で飛車を取られると開始時から28点減る。現行Materialは歩取り直後までを比較する。新方式は取り返し後まで比較する。４五飛なら、この二手の範囲で相手は先手の駒を取れず、駒得差は開始時のままである。候補をこの二つに限れば、新方式は４五飛を選ぶ。

この例の手の合法性と点数は既存操作で確認済み。全合法手から４五飛だけが一意に選ばれることは主張しない。他の安全な手が同点になる可能性がある。

## 将来の実装での検証

対象の振る舞いごとにRedの理由を確認し、最小実装、Green、Refactorの要否確認、独立コードレビューを行う。実装計画は本書の承認後も別途提示・承認を受ける。

| 確認対象 | 確認する振る舞い |
| --- | --- |
| 取り返し | 上の二候補で安全な手を選ぶ。直後の駒得だけでは選ばない |
| 相手の全応手 | 相手の手の列挙順に依存せず、自分に最も不利な結果を使う |
| 得な駒取り | 取り返し等で損しない駒取りまで一律に避けない |
| 先後の視点 | 後手開始でも開始側に有利な結果を選ぶ |
| 詰み | 自分の一手で相手を詰ませる手を通常の駒得より優先し、相手の応手で自玉が詰む候補を通常評価より低くする |
| 同点と全候補負け | 最高評価の手だけを抽選し、低い評価の手を混ぜない |
| 手なし | 開始時はNone。途中で詰みでない手なしは通常の駒得評価とする |
| 複製と手種 | 移動・成り・駒打ちを扱い、複数候補・応手の確認後も元の盤面・手番・持ち駒を保つ |
| 既存動作 | 既存二方式の選択動作と一様ランダムの既定を保つ。改名時はCLI/USIの対応と合意した互換性を確認する |

局面例は手計算と照合し、新方式に都合のよい一例だけに限定しない。製品変更後は変更に見合うテスト、全体回帰検証、Ruff、差分確認を行う。

## 棋力の確認と限界

局面テストは仕様の正しさと対象局面での改善を確認する。対局棋力とは区別する。旧Materialと新方式の比較は、複数の開始局面、先後入れ替え、乱数種、使用機器、計算条件、勝敗と未決着の扱い、採否の基準を事前に決めて行う。試行数や統計的判定は実験計画で合意し、少数対局の勝率だけで向上を断定しない。

千日手未対応・手数打ち切り・処理時間を結果に明示する。打ち切りを勝手に規則上の引き分けへ読み替えない。対局測定の道具が必要なら別途範囲を決め、今回の設計に大きな基盤作りを追加しない。

深さ2の打ち切り後に取り返される等の見落としは残る。全合法手の組合せを調べるため、既存Materialより処理量が増える。実用上の応答時間も測定し、遅すぎる場合は未解決として次の改善を検討する。ShogiHome操作・接続調査・Ruff追加ルール・自作UIは本テーマの必須条件としない。
