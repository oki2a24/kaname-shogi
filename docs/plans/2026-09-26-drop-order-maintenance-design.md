# 第40回 駒打ち順の保守改善：設計書

作成日：2026-09-26

## 目的

`legal_moves(position)` が返す駒打ちの順序を、`BasicPieceType` の宣言順に偶然依存する状態から、`movegen.py` に明示した非公開定数へ移す。第38回で合意した公開APIの順序「飛・角・金・銀・桂・香・歩」と、各駒種の打ち先「1一から9九」を、既存の合法性と局面不変性を変えずに保守しやすくする。

## 規則とAPI契約の切り分け

日本将棋連盟の対局規則第5条第3項は、持ち駒を反則に該当しない空きマスへ置けることを定める。一方、合法手候補をどの順に列挙するかは定めない。

したがって、駒打ち順は将棋規則ではない。`legal_moves` の戻り値をテスト、表示、固定種の乱数による弱いコンピュータの選択で再現可能にする、本プログラムの公開API契約である。

出典：[日本将棋連盟「対局規則」](https://www.shogi.or.jp/match/taikyoku_rules/taikyoku_rules.pdf)

## 対象範囲

- 駒打ちの駒種順だけを明示する。
- `BasicPieceType` の定義、宣言順、列挙値、持ち駒・成駒復元での役割は変更しない。
- 盤上移動の順、成り・不成の順、駒打ち先の走査順、合法性の判定、CLIの動作、乱数選択器のインターフェースは変更しない。
- 評価・探索、USI/SFEN、対局モード、他の列挙順の整理は扱わない。

## 設計

`kaname_shogi/movegen.py` の合法手列挙処理の近くに、モジュール非公開の順序定数を置く。

```python
_DROP_PIECE_TYPES = (
    BasicPieceType.ROOK,
    BasicPieceType.BISHOP,
    BasicPieceType.GOLD,
    BasicPieceType.SILVER,
    BasicPieceType.KNIGHT,
    BasicPieceType.LANCE,
    BasicPieceType.PAWN,
)
```

`_legal_moves` の駒打ち列挙は、この定数だけを順に使う。玉は定数に含めないため、列挙中の玉除外分岐は不要になる。

`BasicPieceType` は「持ち駒の種類を表すデータ」、`_DROP_PIECE_TYPES` は「`legal_moves` の公開順を表す順序表」として責務を分ける。順序定数は非公開であり、公開APIを増やさない。

## 確認方法

### 新しい順序確認

先手・後手それぞれについて、盤上の81マスを空にし、手番側へ飛・角・金・銀・桂・香・歩を各1枚持たせる。盤上移動がなく、駒打ちだけが返る局面で、`legal_moves` の戻り値全体を期待値と比較する。

期待値は、駒種を「飛・角・金・銀・桂・香・歩」の順にし、各駒種の打てるマスを筋1から9、各筋の段1から9の順に並べる。既存規則により、先手は歩・香の一段および桂の一・二段を、後手は歩・香の九段および桂の八・九段を除く。これにより、全7駒種、全81打ち先と、既存の行き所のない駒の規則を確認する。

### 回帰確認

- 既存の局面不変性テストを変更せずに通し、合法手列挙前後で盤面、両者の持ち駒、手番が変わらないことを維持する。加えて、新しい全駒種・全打ち先の順序テストでも列挙前後の局面全体を比較し、持ち駒を多種類へ増やした場合の不変性を確認する。
- 既存の二歩、行き所のない駒、自玉への王手、打ち歩詰めを含む合法性テストを変更せずに通す。加えて、先手・後手の両方で、飛・角・金・銀・桂・香・歩を同時に持つ局面を確認し、複数駒種・全打ち先の列挙でも既存の行き所のない駒の規則を維持する。
- 新しい順序テストを先に失敗させ、最小実装後に成功させる（TDD）。
- 実装後、対象テスト、全テスト、`git diff --check` を実行する。CLIの振る舞いは変更しないが、既存のCLIスモークも実行する。

## 受け入れ条件

1. 駒打ちの列挙が `BasicPieceType` の直接反復に依存しない。
2. `legal_moves` の駒打ちは飛・角・金・銀・桂・香・歩の順を維持する。
3. 各駒種の打ち先は1一から9九の順を維持し、既存の打てない段は含めない。
4. 先手・後手の全駒種・全打ち先の確認がテストで行われる。
5. 既存の局面不変性と合法性の回帰テストが通る。
