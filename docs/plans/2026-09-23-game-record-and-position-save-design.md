# 第36回：棋譜・局面の保存 設計仕様

作成日：2026-09-23

## 目的と対象範囲

CLIで開始した一局について、成功した盤上移動・駒打ちの順序と現在局面をメモリ上に保持し、開始局面から任意の手数時点の局面を再現できるようにする。

今回の対象は次に限定する。

- 開始局面、成功した指し手列、現在局面を保持する。
- 0手目から最終手までの任意の手数時点を再現する。
- `run_game` が対局記録を作成して利用し、終了時に返す。

ファイルへの保存・読み込み、CLIでの履歴表示や保存コマンド、時間の記録、投了・EOF・Ctrl-Cの履歴化、千日手、SFEN、USIは対象外とする。

## 背景と一次資料

日本将棋連盟の対局規則第12条第1項は、公式棋戦で記録係または自動記録による採譜を行うと定める。同条第2項は、棋譜と時間を正確に記録することを記録係の役割としている。連盟の棋譜利用ガイドラインは、公式記録に基づいて指し手進行を再現した盤面図および指し手順の文字情報を棋譜と説明する。

本プロジェクトは時間管理をまだ実装していないため、今回は採譜のうち「成功した指し手の順序」と、その順序からの局面再現だけを学ぶ最小範囲に絞る。

出典：[日本将棋連盟「対局規則」](https://www.shogi.or.jp/match/taikyoku_rules/)、[日本将棋連盟「棋譜利用のガイドライン」](https://www.shogi.or.jp/kifuguideline/)

## 設計判断

### `Position` と対局記録を分ける

`Position` は盤面・手番・持ち駒という一時点の局面を表す可変データである。合法手の探索では `Position.copy()` を試し指しに使うため、対局全体の履歴を持たせない。

新設する `GameRecord`（対局記録）は、開始から現在までの経過を表し、合法手を一手進める操作と局面を再現する操作を持つ可変オブジェクトとする。これにより、局面の責務と対局経過の責務を分離する。

### 指し手の表現

盤上移動と駒打ちは、変更されない履歴データとして別々に表す。

- 盤上移動の値は出発 `Square`、到着 `Square`、成り指定 `bool` を持つ。
- 駒打ちの値は `BasicPieceType` と到着 `Square` を持つ。

これらは既存の `apply_move` / `apply_drop` に必要な値だけを保持する。`Square` は筋・段を表す値、`BasicPieceType` は持ち駒の基本駒種を表す値であり、どちらも局面を変更する操作ではない。

### 更新と失敗時の不変性

`GameRecord` の盤上移動・駒打ちの操作は、内部の現在局面へ既存の `apply_move` / `apply_drop` を実行する。既存操作が成功した場合だけ、対応する履歴データを末尾へ追加し、更新後の局面を現在局面として保持する。

既存操作が `ValueError` を送出した場合、履歴を追加しない。既存の操作は失敗時に局面を変えないため、開始局面・現在局面・履歴をいずれも変えない。入力形式エラーはCLIの解析段階で起き、記録操作を呼ばない。

### 複製と再現

`GameRecord` は作成時に受け取った開始局面を複製して保持する。外部へ開始局面または現在局面を渡す公開の読み取り口も複製を返す。呼び出し側が返された局面を変更しても、記録内部を破壊できないようにする。

`position_at(move_count)` は、開始局面の複製へ履歴先頭から `move_count` 手だけを既存の局面操作で適用して、新しい局面を返す。`move_count == 0` は開始局面を、履歴長と同じ値は現在局面と等しい局面を返す。負数または履歴長を超える値は `ValueError` とする。

各手後の局面を全件保存しない。履歴を再適用する方式は小規模な学習用対局に十分であり、履歴と現在局面の関係を明確に保てる。

### CLIとの関係

`run_game` は初期局面を作った後に `GameRecord` を作成する。盤上移動・駒打ちの指示は記録の操作へ渡し、画面表示には記録から得る現在局面を用いる。投了、詰み、EOF、Ctrl-Cのいずれで終了しても `run_game` はその記録を戻り値として返す。

投了は局面を変えない意思表示であり、今回の指し手履歴には含めない。CLIの入力形式と終局メッセージの仕様は第35回から変更しない。CLI画面に履歴を見る操作やファイル保存操作は加えない。

### SFEN・USIを除外する理由

SFENは局面を文字列で表す形式、USIは将棋GUIとエンジンの通信方式である。今回の最小目的は、既存のPython内部の値を使って履歴と局面再現の関係を理解することである。そのため、外部文字列形式や通信は次テーマ以降に分離する。

## 確認方法

TDDで次の振る舞いを確認する。

1. 盤上移動と駒打ちが成功した場合だけ、順序どおりの履歴と現在局面を保持する。
2. 合法性エラーでは開始局面・現在局面・履歴が変化しない。
3. 返した局面を変更しても記録内部の開始局面・現在局面は変化しない。
4. 0手目、途中手数、最終手数の `position_at` が期待する局面を返し、範囲外の手数を拒否する。
5. CLIの合法な盤上移動・駒打ちが記録され、投了・詰み・EOF・Ctrl-Cでも記録が返る。
6. 既存のCLIの入力エラー、投了表示、詰み表示が維持される。

対象テスト、全テスト、実CLI、`git diff --check` を実行する。実装後はRefactorの要否を確認し、変更の有無にかかわらず独立レビューを行う。CriticalまたはImportantを解消した後に再検証・再レビューする。
