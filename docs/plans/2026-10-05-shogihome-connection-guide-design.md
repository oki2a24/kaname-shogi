# ShogiHome接続手順書・リポジトリスキルの設計

作成日: 2026-10-05
状態: 本人承認済み。2026-10-05に実施計画を作成し、独立レビュー後に現行局面形式の制約を操作境界へ補足した。

## 目的

ShogiHomeへの接続を依頼されたとき、アシスタントが毎回判断に迷わず、安全に準備・接続・確認・終了できる再利用手順を用意する。人間にも同じ操作を再現できる手順書を提供し、Codexにはリポジトリ内スキルからその手順を発見・適用できるようにする。

## 合意した方針

- 人間向け手順書の保存先は `docs/shogihome-connection-guide.md` とする。
- Codex向けスキルは `.agents/skills/shogihome-connection/SKILL.md` に置く。Codex公式のカスタマイズ資料では、リポジトリの `.agents/skills` 以下にあるスキルを検出・利用できると説明されている。
- 手順の対象は、通常の接続と対局、KIFの指定局面からの再開、依頼がある場合のUSIログ採取と元設定への復帰とする。
- 確認は、作成する文書とShogiHome公式資料・現行の知識資料との照合を基本とする。ShogiHomeの実機設定変更や追加対局は今回行わない。
- 人間向け手順書とスキルは互いに参照してよい。両方とも学習記録、引き継ぎ、過去セッションの記録を参照先・前提条件にしない。履歴資料がなくても、目的の操作を実行できるだけの手順と制約をそれぞれに持たせる。
- 今回は文書とスキルだけを対象にする。コード・テストの変更が必要に見えた場合は、理由と別の実施計画を示し、明示承認を得るまで着手しない。

## 成果物

### 人間向け接続手順書

`docs/shogihome-connection-guide.md` に、接続を依頼された人が準備から終了まで追える手順を記載する。

含める内容:

1. 適用範囲、前提、開始前の確認事項
2. ShogiHomeへのエンジン登録と、登録済みエンジン設定の確認
3. `kaname-shogi-usi` の起動方法と、Ponder設定など接続時に確認する項目
4. 通常の対局を始めるときの確認と終了
5. KIFを使う場合に対象手を明示選択してから局面を再開する手順
6. 依頼がある場合だけ行うUSIログの有効化、保存、再起動、ログの確認、元設定への復帰
7. 想定外の時計進行、対象局面の不一致、起動失敗などが起きた場合の停止・報告
8. 公式資料と現行の知識資料へのリンク

第61回の実例から持ち込む事実は、環境依存の観察として明記する。登録ランチャーのパスは `/Users/oki2a24/kaname-shogi/kaname-shogi-usi`、PonderはOFF、ShogiHome 1.28.1でログ設定を保存後にアプリを再起動したこと、37手KIFでは対象手を選んでから「現在の局面」を選ぶ必要があったことを記す。これらは毎回の前提にせず、接続時に実際の設定・表示を確認する。

USIログの説明では、公式仕様と第61回の一事例を区別する。第61回に限る結果の記録として、本人回答の `bestmove resign`、その後の `gameover lose`、さらに別コマンドとしての `quit` を正確に保つ。この一局の通信を他の対局にも必須の手順として一般化しない。

### Codex向けリポジトリスキル

`.agents/skills/shogihome-connection/SKILL.md` に、スキルの発動条件、実行前の確認、操作境界、停止条件、結果報告を簡潔に記載する。詳しい人間向け手順は `docs/shogihome-connection-guide.md` を参照する。スキルの記述だけでも、ユーザーの依頼や現在のアプリ状態を確認してから行動し、未承認の永続設定変更や追加対局を始めない判断ができるようにする。

### 案内・学習記録

- `AGENTS.md` に、このリポジトリでShogiHome操作を行う場合は新しいスキルと手順書を確認する短い案内を加える。
- `README.md` と `docs/README.md` から人間向け手順書へ案内する。
- `docs/learning/62-shogihome-connection-guide.md` に今回の目的、合意範囲、成果、確認結果、未解決事項を学習記録として残す。ただし手順書・スキルからこの学習記録へリンクしない。

## 操作上の境界

- 起動ランチャーや既存設定を、過去の記録だけで正しいとみなさず、その時点の実値を確認する。
- 対局前に、依頼された対局形式・先後・局面・時間設定と、ShogiHomeの表示が一致していることを確認する。
- 現行エンジンが受け付ける局面は、平手初期局面から1手以上を含む `position startpos moves ...` に限られる。新規平手対局は人間先手・エンジン後手とし、初手前をエンジンへ渡す場合、SFEN、駒落ち、別の初期局面を必要とする場合は停止する。KIF再開も平手初期局面からの1手以上の履歴を必要とする。
- KIFの再開では対象手を明示選択し、局面表示を確認してから進める。対象が曖昧、時計が予期せず進む、または表示局面が違う場合は操作を止めて報告する。
- ログ採取は依頼に含まれる場合だけ行う。既存の設定値を先に記録し、必要なログ種別だけを有効にして、保存と再起動を確認する。調査後は開始時の値へ戻して再起動し、復帰を確認する。
- ShogiHomeのUSIコマンド入力欄へ手動でコマンドを送らない。ログ・モニターなどの表示機能を使って確認する。
- 追加対局や永続設定変更が依頼内容から明確に認められない場合は、具体的な操作案を示して明示承認を待つ。

## 確認方法

1. 手順書にある登録・スクリプト起動・ログ・基本操作をShogiHome公式資料と照合する。
2. エンジンパス、Ponder、USIの応答、KIF局面再開について、現行の知識資料・ランチャーと照合する。
3. 第61回から引き継ぐ環境依存観察が、一般要件や全対局共通のUSI通信として書かれていないことを確認する。
4. 手順書とスキルから学習記録・引き継ぎへの参照がなく、過去記録なしでも操作判断に必要な情報が揃っていることを確認する。
5. スキルの構造・配置・説明の品質を `writing-skills` とCodex向け `skill-creator` の手順に沿って確認する。スキル導入前の基準応答と導入後の応答を、読み取り専用のシナリオで比較する。通常接続、KIFの対象手が曖昧な依頼、ログ採取を伴う急ぎの依頼など、少なくとも5つの状況で手順書への誘導と未承認操作の抑止を独立した評価者にも確認してもらう。これは文書・スキルの動作確認であり、リポジトリのコードテストでもShogiHome実機での設定変更・対局でもない。

## 次の段階

この設計案を本人がレビュー・承認した後、`superpowerssuperpowers:writing-plans` を使ってファイル別の実施順、レビュー点、検証項目を含む実装計画を作成し、計画内容を提示して明示承認を待つ。計画の承認後に限って、手順書・スキル・案内リンク・学習記録を作成する。

`.agents` は現在の実行環境で読み取り専用として扱われている。承認後の実装計画では、スキルファイルの作成に必要な書き込み許可の申請方法と、許可されない場合の扱いを明示する。
