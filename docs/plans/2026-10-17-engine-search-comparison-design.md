## 目的と合意した範囲

未知局面で判断する仕組みを学ぶため、現行の駒得評価を固定し、枝刈りなしのミニマックスとαβ枝刈り付きミニマックスを比較する。深さは開始局面からの着手数で二・三・四手。各深さは独立実行し、浅い探索の結果を深い探索へ引き継がない。

最初は開発用コマンドによる比較まで。Random（最弱・既定）、一手駒得、現行二手先読みの選択と振る舞いを維持する。通常対局のCLI/USIへの新方式追加、反復深化、時間制御の組み込み、置換表、駒取り継続、評価項目の追加、定跡は対象外。対局による棋力測定は後段の候補。

## 探索・評価・選択の合意

- 評価視点は開始側に固定。開始側の手番では最大、相手手番では最小の値を採用する。
- 詰みの勝ち > 通常の駒得 > 詰みの負け。末端でも詰みを確認する。勝ち同士・負け同士は同点で、詰み距離は比較しない。
- 詰みに到達したらその枝を終了。詰みでない合法手なしは通常駒得で終了。
- 両方式の合法手を調べる順序をそろえる。同点の最善手は最初のものを選ぶ。
- 指定深さまで完了した結果だけを比較する。手動中断は未完了であり、比較成功と表示しない。
- 元局面と枝同士を独立させる方針を引き継ぐ。

追加合意：全幅側で各根候補の確定評価を結果へ保持し、その値から最善候補集合を求め、αβ側の根の評価と選択手を比較する。確認のための再探索は行わない。枝刈りされた候補の上限・下限を、その候補の確定値として表示したり、最善候補集合へ混ぜたりしない。αβ側で最善手を全列挙する要求はない。

## 訪問回数と比較条件

本人が合意した計数単位は、探索処理に入った局面の訪問回数。開始・途中・末端を含み、同じ局面への再訪も毎回数える。開始局面は各探索実行で一度数える。

計数境界（追加合意済み）：詰み判定・合法手生成の内部で王手回避等を検査する局面は、探索本体の訪問には含めない。訪問回数は実行時間や全処理回数そのものではない。最善候補の基準作成のために別実行を追加する場合は、比較対象の探索に混ぜて集計しない。探索本体の入口で加算する。合法手として生成済みでも、枝刈りにより探索本体へ渡さなければ加算しない。

比較成功は、同じ局面・深さ・手順序・評価方法で、根の評価が一致し、各選択手が独立に確認した最善候補に含まれること。全幅で求める候補集合に加え、人が検算した期待値も用意する。共通探索本体の誤りが両方式へ同時に現れる可能性があるため、一致だけで正しさを主張しない。

枝刈りで訪問回数が減る例と、同じになる例を扱う。全局面での削減や棋力向上は成功条件にしない。

## 開発用入力と表示

合意：SFENで開始局面を指定すると二・三・四手の結果をまとめて表示する。各行に深さ、方式、評価、選択手、訪問回数を示す。選択手はUSI表記と日本語を併記する。例：`5e5d`（5五→5四）、`2d2c+`（2四→2三・成り）、`P*5e`（5五に歩を打つ）。

提案：入力SFEN、開始側、評価一致、αβ選択手の最善候補への所属を表示する。勝ち／負けを通常点と区別して表示する。開始局面に合法手がない場合、詰みなら負け、それ以外なら駒得評価、選択手なし、訪問1回。両方式の評価が一致し、双方とも選択手なしなら比較成功とする（追加合意済み）。

既存SFEN読込みを再利用し、探索は入力形式から独立した局面データを受け取る案。JSONの棋譜読込みは今回追加しない。SFENの手数欄から履歴は復元できず、千日手等の履歴依存の判定は追加しない。

## ファイル境界・依存方向（全体レビュー対象の具体案）

本人が合意した範囲は、新探索と必要な共通処理の分割まで。既存三方式の全面移動は行わない。以下の具体名・公開契約を全体レビューで提示し、設計として承認された。

| ファイル | 責務・依存 |
| --- | --- |
| `search/__init__.py` | パッケージ宣言。入出力や探索をimport時に開始しない |
| `search/minimax.py` | 枝刈りなしの公開入口。共通本体を利用 |
| `search/alpha_beta.py` | αβ付きの公開入口。共通本体を利用 |
| `search/core.py` | 再帰探索、最大／最小、境界、訪問回数。contractsとresultのみ利用 |
| `search/contracts.py` | 探索へ渡す操作と局面調査結果のデータ。将棋の型に依存しない |
| `search/result.py` | 評価値と探索結果のデータ。将棋の型に依存しない |
| `search/shogi.py` | Position・Moveと探索本体を接続。既存ルールとevaluationを利用 |
| `evaluation.py` | 現行の駒価値定数と駒得評価を集約。modelのみ利用 |
| `search/compare.py` | SFEN入力、二方式実行、比較、表示と終了状態 |

依存方向は `compare → 方式入口 → core → contracts/result` と、`compare → shogi → movegen/evaluation/model`。`movegen → evaluation → model`。movegenから新しいsearchパッケージへ依存させない。

駒得関数と駒価値表の正本をevaluationへ移す。`movegen.material_balance` は委譲する互換入口として維持する。既存非公開定数の参照が必要な箇所も同じ表を参照し、値のコピーを増やさない。既存の選択・時間制御コードは移動しない。

複製への一手適用には、movegenへ公開操作 `position_after_move(position, move)` を設け、既存の停止なし `_position_after_move` へ委譲する。新探索は非公開名を直接importしない。将来の全ルール分割を先取りせず、この公開化で既存の適用経路を共有する。新旧とも元局面を変更せず、型・不合法手・内部故障の例外を隠さない。

薄い方式入口は利用者が方式を選ぶ境界とする。共通本体内の明示的な枝刈り有無の切替を採用し、同じ再帰処理を二重実装しない。将棋接続と汎用の操作契約を分ける二ファイルは、数値木による同一本体の検証に必要な範囲の追加である。

## 公開操作とデータの契約（具体案）

英語名の位置付け：型はデータ、関数は操作。Nは探索対象の局面データ型、Mは手のデータ型を表す型引数であり、将棋用にはPositionとMove、数値木には確認用の節点と枝を使う。

| 名前 | 種類と契約 |
| --- | --- |
| `Score` | 評価データの別名。整数二要素 `(勝敗区分, 駒得差)`。勝ち `(1,0)`、通常 `(0,n)`、負け `(-1,0)` |
| `NodeInspection[M]` | 局面調査結果の変更不可データ。順序付き `moves`、`maximizing`、`terminal_score` を持つ。継続可能ならterminal_scoreはNone。終了ならmovesは空で終端評価がある |
| `SearchOperations[N,M]` | 三つの呼出可能な操作を束ねる変更不可データ。`inspect(node)`、`advance(node, move)`、`evaluate(node)`。継承階層は設けない |
| `SearchResult[M]` | 完了した探索結果データ。`score`、`move`（手なしはNone）、`visited_nodes`、`root_scores`。全幅のroot_scoresは順序付きの手と確定値の組。αβは未提供をNoneで表す |
| `minimax.search(node, depth, operations)` | 全幅探索操作。根を含めて訪問を数え、根候補の確定値を保持したSearchResultを返す |
| `alpha_beta.search(node, depth, operations)` | αβ探索操作。確定した根の値と最初の最善手を返す。各候補の境界を確定値として公開しない |
| `shogi.make_operations(perspective)` | 開始側固定の将棋用操作セットを作る。盤面を保持せず、開始側を評価と最大／最小の基準として閉じ込める |
| `compare.main(argv=None)` | コマンド操作。整数終了コードを返し、モジュール実行時の入口が終了へ反映する |

内部の `core.search(..., pruning=...)` は二入口の共有実装とし、比較コマンドから直接利用しない。汎用入口のdepthは0以上の整数とし、bool・非整数・負数はValueError。コマンドは二・三・四手のみ。depth=0では開始局面を一度調べ、終端なら終端値、そうでなければ静的評価、手なしを返す。全幅のroot_scoresは空で、αβはNone。

inspectは局面を変更せず、同じ入力では同じ順の手を返す。advanceは他の枝と元局面に影響しない局面を返す（不変の数値木は既存節点の参照を返してよい）。evaluateは静的評価であり、探索を再帰呼出ししない。操作の例外を偽の評価へ変換しない。探索内部に乱数・入出力・時刻依存・グローバルな訪問計数を置かない。

将棋用inspectは `legal_moves` を一度呼ぶ。手があれば継続、なければ既存 `is_in_check` を呼び、王手なら手番側の負けを開始側視点へ変換、王手でなければ駒得で終了。合法手を再生成する `is_checkmate` を別途重ねない。既存の玉なし部分局面・打ち歩詰めの契約は既存操作に従う。合法手生成内部の仮適用は訪問回数に加えない。

## 評価の境界と探索の手順（仕様）

本人が同意したScoreの組を辞書順比較する。有限の巨大整数を詰みや無限大の代用にしない。上下限の未設定はそれぞれNone。Noneとの大小比較は行わない。

各訪問で、計数→inspect→終端なら返却→残り深さ0ならevaluate→手を順にadvanceして再帰、の順とする。末端の詰みを通常評価で上書きしない。最大側は厳密に大きい場合だけ、最小側は厳密に小さい場合だけ選択手を更新する。

αβでは、最大側で下限を引き上げ、最小側で上限を引き下げる。両境界が設定済みで下限が上限以上になれば残りを省く。子には現在の境界を渡す。根からの通常実行は両方Noneで始め、根で最初に得た基準を後続の子にも渡す。内部で返る値は境界の場合があるため、各候補の確定値をαβ結果に収集しない。根の値は全範囲での探索結果として確定し、同値の境界で先に確定した最善手を置き換えない。

全幅では境界による省略を行わず、各根候補の値を一度の探索で保持する。全幅の確定値から作った最善候補集合との所属比較と、手計算の独立期待値との確認を別々の役割として行う。

## 確認局面と期待値の状態

以下は対話で提示し、既存操作による局所検算を行った部分局面。通常の初期配置から到達した合法棋譜であることを主張しない。数値は先手視点。新しい探索の実行結果ではない。

### 取り返し

```text
8k/9/4g4/4p4/4RS3/9/9/9/K8 b - 1
```

開始13、`5e5d`（飛車が歩を取る）で15、`5c5d`（金が飛車を取る）で−15、`4e5d`（銀が金を取る）で3。各手は合法と確認。特定の枝の検算であり、根の二・三・四手のミニマックス値と最善候補は未確定。

### 静かな逃げと交換

```text
8k/9/4gs3/9/4R4/9/9/9/K8 b - 1
```

開始−2。`9i9h`、`5c5d` の後、`5e5f`、`5d5e` の枝は−2のまま。一方 `5e5d` で16、`4c5d` で−14。各手は合法と確認。逃げた後の全応手を列挙した結果ではなく、根の期待値は未確定。教材の枝と探索全体の契約を区別する。

### 玉だけの同点・枝刈り

```text
8k/9/9/9/9/9/9/9/K8 b - 1
```

二・三・四手では玉が接触せず、駒取り・詰みがない。根の期待値は通常0。根の全合法手が最善候補。既存生成順は `9i9h`、`9i8h`、`9i8i` と確認した。この順序を採用する場合、選択手は `9i9h`。

二手の手計算：全幅は1＋3＋9＝13訪問。等号でも枝刈りし、根の最初の候補の値を後続へ渡すαβでは、1＋3＋(3＋1＋1)＝9訪問。これはそのアルゴリズム条件での期待値で、未実装の計測結果ではない。三・四手の訪問数は未検算。

### 詰み

```text
3pkp3/3p1p3/4RG3/9/9/9/9/9/K8 b - 1
```

既存テストの配置をSFEN化。`5c5b` で相手が詰み、駒得差は20だが評価は勝ちになる。既存処理で合法・詰みを確認した。根に即詰みの候補があるので各比較深さの最善評価は勝ちを期待するが、最初の勝ち手と全最善候補集合は未列挙。

### 数値だけの木

本人は将棋局面と併用することに同意。将棋ルールの検証と、探索アルゴリズムの検証を補完させる。

- 根は最大、各子は最小。Aの葉を `[3, 5]`、Bの葉を `[4, 6]` の順に読む。根4、選択B、全幅／αβとも7訪問。枝刈りなしの例。
- 同じ形でAを `[3, 5]`、Bを `[-2, 10]` とする追加案。根3、選択A、全幅7、αβ6訪問。Bの10を読まないことを確認。Bの返却上限−2を候補の確定値と混同しない（この木では偶然同値）。
- 最大側の枝刈り：根を最小、各子を最大とし、Aの葉 `[2,4]`、Bの葉 `[5,10]`。根4、選択A、全幅7／αβ6訪問。Bの10は省く。本人は相手がAを選ぶためBの上昇を確認しなくてよいと理解確認済み。
- 実際の将棋の根は開始側の最大になるため、この最小の木を一本道の最大根の下へ付けた深さ3の例も用意する。根4、訪問は全幅8／αβ7で、内部の最大側の枝刈りを同じ本体で確認する。
- 上限と確定値の区別：最大根、最小のA `[3,5]`、B `[3,-2]`。根3、選択A、全幅7／αβ6。Bは境界3を返し得るが確定値は−2。これで同点境界による選択上書き・偽の最善候補追加を検出する。
- 真の同点：A `[3,5]`、B `[3,4]`。最善集合A/B、最初のAを選ぶ。順序反転では最初のBを選ぶ。上限だけの同点例と対にする。

## 追加で合意したコマンド契約

実装予定の呼出形式：

```sh
.venv/bin/python -m kaname_shogi.search.compare --sfen "8k/9/9/9/9/9/9/9/K8 b - 1"
```

二・三・四手に固定し、両方式で既存の合法手生成順を使う。深さ・順序を変更するオプションは今回設けない。

- 全深さで比較成功：一覧を表示し正常終了。
- 評価または最善候補所属の不一致：深さと不一致内容を表示し異常終了。
- 不正SFEN：探索を開始せず入力エラーを表示し異常終了。
- Ctrl+C：完了済み結果は残し、実行中の探索を未完了と表示して中断終了。
- 訪問回数が同じであることだけでは失敗にしない。

追加合意：成功0、比較不一致1、不正引数／SFEN2、Ctrl+C130。結果一覧は標準出力、入力エラー・中断通知・内部エラーは標準エラー出力。比較不一致は一覧と短い標準エラー診断の両方へ出す。入力変換のValueErrorだけを入力エラーに分類し、探索で生じたValueError等を不正SFENへ変換しない。

内部エラーはトレースバックを保って伝播させ、通常のPython異常終了に従う（通常1）。比較不一致との違いは診断で判別する。Ctrl+Cはコマンド境界で扱い、実行中の方式と深さを表示。完了した各方式の行は即時出力し、対になる二方式が完了した深さだけ合否を表示する。不一致があっても残る固定深さの比較を続け、全実行後に1を返す。途中で中断・内部エラーが発生した場合はその終了を優先し、全体成功とは表示しない。ヘルプ表示は0。

一般的な慣例と今回の割当を区別する。0は成功、非0は失敗。1／2は全CLIに厳密に共通の分類ではなく、今回2にSFEN内容不正を含めるのは入力エラーの設計判断。130はシェルでの128＋SIGINT(2)の慣例に合わせ、捕捉後に明示的に返す。
