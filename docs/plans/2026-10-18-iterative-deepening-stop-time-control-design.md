# 反復深化と既存時間制御の接続設計

## 状態・目的・範囲

2026-10-18作成・全体承認済み。本人が文書全体の承認確認に「yes」と回答し、型名・引数・配置・公開する共通処理の入口を含めて承認した。[学習記録](../learning/iterative-deepening-stop-time-control-design.md)に個別回答と全体承認を区別して記録する。本文の「案」「提案」「草案で具体化」は設計時の経緯を示し、全体承認にはこれらの具体案も含む。実装計画ではなく、作業順・TDD手順・コードやテストの変更は含めない。今回の範囲は学習・設計までで、実装計画・実装・通常対局接続へ自動移行しない。

目的は、既存の予算・停止判定を共用し、反復深化が中断時にも合法予備手または最後の完了結果を返せる探索部品の契約を決めること。通常対局・USI・CLIへの新方式接続、比較コマンドへの時計オプション追加、予算式や設定値変更、時間保証、性能・棋力向上は対象外。Random（最弱・既定）、一手駒得、現行二手先読みを維持する。

## 採用候補と代替案

- 推薦：既存予算計算・停止制御・合法手生成・手の適用を再利用し、必要な利用境界だけを追加する。通常三方式の振る舞いを保ったまま、反復深化の停止方針を分ける。
- 代替：停止可能な将棋処理を専用モジュールへまとめて移す。責務は見えやすくなるが、既存方式の参照変更が広がる。今回の接続に必要な切出しを超える移動は見送る。
- 採らない案：反復深化用に合法手・停止判定を複製する。規則と修正箇所が二重になるため。

## 責務と依存境界

| 部品 | 責務 | 持ち込まない責務 |
| --- | --- | --- |
| `time_management.py` | 設定・期間の予算計算（既存） | 探索、時刻取得、結果選択 |
| `search_control.py` | 原点・期限・停止要求と判定（既存） | 完了結果、将棋規則、送信 |
| `movegen.py` の共通処理 | 合法性調査・独立局面への適用と途中停止 | 深さ反復、予算配分 |
| 将棋用接続部 | 将棋の調査・適用・評価を探索の操作契約へ変換 | USI、応答送信 |
| 指定深さの共通探索 | αβと停止確認、正常完了だけの結果生成 | 前回反復の結果、予備手の選択 |
| 反復深化の制御付き入口 | 深さ開始判断、予備手・最新完了記録の所有、終了結果 | 時間予算式、送信、スレッド管理 |

個別合意済み：既存 `iterative_deepening.search`（完了記録を順に渡す操作）の契約を維持し、停止制御を受けて最終結果を返す入口を別に設ける。深さ反復・前回優先手・完了累計の共通部分は共有し、再帰探索や反復アルゴリズムを二重実装しない。新入口は呼出し側が用意した一回分の `SearchControl`（停止制御データ）と正の上限深さを受ける。開始時刻や制御を深さごとに作り直さない。独立した探索間では制御・予備手・記録を共有しない。

既存の汎用数値木による探索を維持する。探索本体は将棋やUSIへ依存せず、停止判定の操作と局面操作を受け取る。将棋側が停止可能な生成・適用を提供する。具体的な利用境界は後段の提案を参照する。設計全体は承認済みだが、実装開始の許可とは扱わない。

## 期限と停止確認点

- 同じ開始局面で深さ1から順に探索する。前回最善手は根の順序にだけ使い、各深さで評価を求め直す。
- 目標期限は新しい深さを始める直前に確認する。開始済みの深さの内部では目標を適用せず、上限・通常停止・抑制を確認する。
- 指定深さ探索では、局面調査の前後、子への適用の前後、評価後、子から戻った後、および根の結果を確定する直前に確認する案。合法手生成と打ち歩詰めの下位調査・適用でも既存の確認を利用する。
- 正当なαβ枝刈りは正常完了に含む。停止による未完了を枝刈り完了と混同しない。
- 個別合意済み：根の最終確認まで上限・通常停止を通過した時点を、一深さの完了の境界とする。そこまでに停止した反復の評価・手・訪問数は完了記録へ入れない。既に保持した完了記録は後の停止で取り消さない。返却前に抑制を再確認し、抑制なら応答手を渡さない。
- 一つの複製、利き計算、静的評価等は強制切断しない。確認点の間の遅延は残り、時間内応答を保証しない。

## 合法予備手と共通処理の利用

最初の合法手確保または全調査での手なし確定まで通常停止を保留する。応答抑制は保留しない。保護は一回の探索で一度だけであり、深い反復や子局面で再開しない。ただし最初の合法手の合法性を確定するために必要な下位調査には保護を伝える。

既存 `_legal_moves_controlled`（停止可能な合法手調査操作）の `root` 指定は目標確認と予備手保護を結合している。共通本体で両者を別々に指定できる境界を設け、通常三方式には従来の組合せを維持する。反復深化の深さ内は目標確認なし。途中の空一覧を手なしに変換しない。手の適用も既存の停止可能な処理を使い、途中の局面を正常な子局面として渡さない。

個別合意済み（2026-10-18「はい」）：反復開始前に最初の合法手だけを探す準備処理を置く。確保後に目標・上限を確認し、既に停止すべきなら深さ1を始めず予備手を返す。手なし確定なら反復を始めず終了する。この準備は反復の完了記録を生成しない。深さ1での合法手再調査という費用は増えるが、保護を最初の準備処理へ限定できる。根の一覧を保存して再利用する最適化は今回追加しない。準備途中に抑制された場合は手なし確定とは扱わない。

## 結果の表現

既存 `IterationResult`（一深さの完了記録データ）は維持し、予備手へ架空の深さや評価を付けない。外側に不変な終了結果を設ける案。概念上の項目は「終了状態」「応答候補の手」「最後の完了記録（なければなし）」。内部の暫定点は公開しない。

四つの終了状態の区別は個別合意済み。英語名は草案での具体化：

| 状態 | 応答候補の手 | 最後の完了記録 |
| --- | --- | --- |
| `COMPLETE`（要求範囲の完了） | 上限深さの選択手 | 上限深さの記録 |
| `NO_LEGAL_MOVE`（合法手なし確定） | なし | なし（準備で確定） |
| `STOPPED`（通常停止・期限停止） | 最新完了記録の手、記録なしなら予備手 | あれば保持、なければなし |
| `SUPPRESSED`（応答抑制） | なし | あれば保持するが応答には使わない |

`STOPPED` は必ず合法な手を持つ。目標で深さを増やさなかった場合もこの状態とする。「最後の深さが完了した」と「要求した上限まで終えた」は区別する。上限深さの完了を確定した後に通常停止が来ても、その完了を未完了へ戻さない。抑制は最終返却確認で優先する。送信は部品の責務外であり、将来の接続側でも送信前の抑制確認が必要。

個別合意済み：訪問累計は従来どおり完了反復の和。予備手確保・中断反復・比較用探索は含めない。完了記録なしを累計0の架空の完了記録で表さない。全作業量の計測は今回追加しない。

## 中断と故障

個別合意済み（2026-10-18）：中断は戻り値で伝える。完了と中断を別の型で表し、戻り値をそのユニオン型とする。共通の親クラスは設けない。専用例外による中断案は採用しない。採否の理由と一次資料の確認は[学習記録](../learning/iterative-deepening-stop-time-control-design.md)に保持する。

局面調査・適用・再帰呼出しから中断が返った場合は、その段で評価や最善手更新をせず、そのまま外側へ返す。内部の中断データは評価・手・完了訪問数を持たない。通常停止と応答抑制の区別は保持する。想定外の例外は原因を保って呼出し元へ伝え、保持手を返して成功扱いにしない。

### 内部結果と外側の終了結果の違い

以下の英語名と細部は草案で具体化し、文書全体として承認された。

- `SearchInterrupted`（探索中断を表すデータ）：理由は通常停止または抑制。継続を理由にできない。評価フィールドも評価取得操作も持たない。不変データとする。
- 一つの指定深さを探索する操作は、既存の `SearchResult`（完了結果データ）または `SearchInterrupted` を返す。深さ内の再帰が返す成功値はαβの境界値の場合もあるため、公開の根の完了結果とは区別する。中断値を評価の大小比較へ渡さない。
- 局面調査は既存の `NodeInspection`（局面調査の結果データ）または `SearchInterrupted`。中断を空の合法手一覧に変換しない。
- 局面遷移は `AdvancedNode[N]`（適用完了した次局面を包むデータ）または `SearchInterrupted`。汎用局面型Nをそのまま中断型と混在させず、成功した遷移を明示する。
- 静的評価は従来の `Score`（評価データ）を返す。単一の静的評価自体は途中切断せず、探索側が前後で停止を確認する。
- `ControlledSearchResult[M]`（制御付き反復探索の最終結果データ）は、内部の中断そのものではない。反復管理が最後の完了記録や予備手を選んだ後に作る、外側の終了結果である。既述の四状態・手・最後の完了記録を持つ。不変とし、状態と値の不整合を構築時に拒否する案。

外側の結果の不変条件：COMPLETEは上限深さの完了記録とその手を持つ。NO_LEGAL_MOVEは手と記録ともなし。STOPPEDは手が必須で、記録があるならその手と一致する。SUPPRESSEDの手は常になしで、過去の記録だけは保持できる。これらを満たさない状態を中断の通常ケースとして受け入れない。

## 操作の利用境界案

この節は新たな提案。名前は操作かデータかを明記し、既存APIの変更を必要以上に広げない。

| 提案する操作・データ | 入力と出力・責務 |
| --- | --- |
| `iterative_deepening.search_controlled`（操作） | 開始局面、上限深さ、制御付き操作セット、一回分のSearchControlを受け、ControlledSearchResultを一件返す同期操作。送信・新規thread生成なし |
| `alpha_beta.search_controlled`（操作） | 局面、深さ、制御付き操作セット、同じSearchControl、任意の根の優先手を受け、SearchResultまたはSearchInterruptedを返す。反復・予備手の所有なし |
| `ControlledSearchOperations`（操作を束ねるデータ） | 初回予備手準備、局面調査、独立局面への適用、静的評価の操作を持つ。停止可能な各操作へ呼出し側から同じ制御を明示的に渡し、別の制御を隠して保持しない |
| `shogi.make_controlled_operations`（操作） | 開始側の視点から将棋用の制御付き操作セットを作る。予算計算・時計原点設定なし |

既存の `SearchOperations` と停止なし入口は維持する。共有本体へ渡すところで既存の操作を成功結果として扱い、停止なしの公開戻り値へ中断型を追加しない。再帰の採点・枝刈り・前回手優先・訪問計数の本体を共有する。内部補助関数の名前や共通化の記述手順は実装計画の段階へ残すが、アルゴリズムの二重実装は避ける。

新反復入口はboolを除く1以上の上限深さを呼出し時に検査し、準備処理の前に不正値をValueErrorとする。指定深さ入口は既存同様0以上。優先手の照合は根の調査が完了してから行い、完了前に中断した場合は未確認の優先手を不正と断定しない。停止なしでは既存の入力検査・例外を維持する。

予備手準備は `PreparedRoot[M]`（準備完了のデータ）またはSearchInterruptedを返す案。PreparedRootの手があれば確定した最初の合法手、なしなら全調査で合法手なしと確定した意味。全手一覧・評価は持たない。保護中でも抑制は中断データとして返し、手なしへ変換しない。汎用探索では「手の値としてNoneを使わない」という既存前提を維持する。

将棋の共通処理には、停止可能な合法手生成、最初の合法手の取得、独立局面への適用の公開入口をmovegen.py内に設ける案。名前案は `legal_moves_controlled`、`first_legal_move_controlled`、`position_after_move_controlled`（すべて操作）。既存の非公開本体へ委譲し、将棋規則を複製しない。目標適用と初手保護は別の指定とし、深さ内部では両方無効。初手準備だけ通常停止を保護し、確保後は反復側で期限を確認する。将棋側の既存completed付き結果を、接続部で探索用の成功型または中断型へ変換する。既存三方式の結果型を今回全面的に作り直さない。

一回の探索中は入力局面を変更せず、同じ局面・視点で準備と再調査の合法手が一致することを操作セットの前提とする。将棋以外の数値木でも準備と調査を整合させる。制御付き将棋処理から未完了が返ったら、SearchControlで抑制を再確認して理由を決める。既存の停止要求・単調時計を前提に、未完了を再判定で継続へ戻さない。中断後に抑制へ進んだ場合は、外側の最終確認でも抑制を優先する。

### 提案する引数・フィールドの対応

以下は設計上の記法であり、実装コードではない。Nは局面データの型、Mは手データの型を表す。

| 操作 | 呼出しの形 | 戻り値 |
| --- | --- | --- |
| 制御付き反復探索 | `search_controlled(node, max_depth, operations, control)` | `ControlledSearchResult[M]` |
| 制御付きαβ | `search_controlled(node, depth, operations, control, *, preferred_move=None)` | `SearchResult[M]` または `SearchInterrupted` |
| 将棋用セット生成 | `make_controlled_operations(perspective)` | `ControlledSearchOperations[Position, Move]` |
| 初回準備 | `operations.prepare(node, control)` | `PreparedRoot[M]` または `SearchInterrupted` |
| 局面調査 | `operations.inspect(node, control)` | `NodeInspection[M]` または `SearchInterrupted` |
| 次局面への遷移 | `operations.advance(node, move, control)` | `AdvancedNode[N]` または `SearchInterrupted` |
| 静的評価 | `operations.evaluate(node)` | `Score` |

`prepare` は最初の手確保に必要な調査だけ通常停止を保護するため、正常な操作契約では中断理由は抑制のみ。通常停止による「手も手なし確定もない」結果は契約違反とし、投了や正常停止へ変換しない。`inspect` と `advance` は目標を適用せず、通常停止の保護も行わない。

データの配置案：`SearchInterrupted(reason)`、`ControlledSearchResult(completion, move, last_completed)`と四状態を表す`ControlledCompletion`は `search/result.py`。`AdvancedNode(node)`、`PreparedRoot(move)`、`ControlledSearchOperations(prepare, inspect, advance, evaluate)`は `search/contracts.py`。いずれもデータであり操作ではない。新しい親クラスや任意の処理用の汎用ラッパーは追加しない。

`reason` は既存 `SearchSignal.STOP` または `SearchSignal.SUPPRESS`。CONTINUEや他の値を中断理由として構築することは拒否する。`last_completed` は既存 `IterationResult` またはNone。外側のデータ構築時に確かめられるのは状態と手・記録の組合せであり、指定した上限深さとの一致や手の合法性は探索側の契約として確かめる。型名に共通のSearchResultという語があっても、通常三方式の `movegen.SearchResult` とは混同しない。

公開将棋操作の形は、`legal_moves_controlled(position, *, control, include_target=False, protect_first_legal=False)`、`first_legal_move_controlled(position, *, control, protect_first_legal=False)`、`position_after_move_controlled(position, move, *, control)` とする案。すべて打ち歩詰めまで確認する。探索接続部は最初の取得だけ保護を有効にする。手あり確認で使う内部の「最初の一手だけ調べる」生成ロジックを共用し、規則をコピーしない。

将棋側の結果は既存方式との互換性のためcompleted付きデータを維持する。全生成は既存LegalMovesResult、最初の取得も同じ型で完了時の手を0または1件に限定する。適用は既存内部の完了状態と次局面の対に対応する公開データ `MoveApplicationResult(completed, position)` を提案し、完了なら独立局面、中断ならNoneという組合せに限定する。将棋接続部がこれらを探索の別型へ変換し、既存の非公開適用型を新公開APIから漏らさない。

初回準備の最初の合法手は生成順で選び、乱数器は使わない。停止なし入口で要求される遅延取得・既存の同点規則・手なし時の一件の反復記録は維持する。新入口は準備で手なし終了するため、その場合の完了記録なしという違いを仕様として明記する。

## 確認方法と未検証事項

以下は設計上の確認方針。テスト作成・実行・変異注入の手順や実績ではない。[検出力の点検方針](../knowledge/test-coverage-review.md)に従う。

| 契約 | 代表ケース・独立した根拠 | 検出したい誤り |
| --- | --- | --- |
| 同じ原点・制御を保持 | 注入時計で深さが変わっても同じ期限、途中の停止要求を維持 | 原点・要求のリセット |
| 目標と上限の区別 | 期限直前・一致・直後、目標後に進行中の深さを完了、上限で中断 | 目標を深さ内部へ適用、上限を深さ間でしか確認しない、期限判定の>=を>に誤る |
| 最新完了結果を使う | 手計算の木：深さ1 A=5/B=3、深さ2 A=min(1,-2)、B=min(2,1)、深さ3途中で暫定手をAとして停止。手B・深さ2・評価1・完了累計を一組で確認 | 浅い高得点Aを固定、深さ3途中結果でBを上書き |
| 予備手と保護 | 0予算、開始時stop、手なし、初手合法性確認中の抑制、深さ2の最初の調査で停止 | 完了前の投了、深さごとの保護、抑制の保留 |
| 未完了の伝達 | 合法手未発見・一手確保後・打ち歩詰め調査・手の適用途中 | 空一覧を手なしにする、不明をFalseにする、部分局面を渡す |
| 完了の確定点 | 最終評価後・根の最終確認前の停止、確定後の通常停止、返却前抑制 | 未完了の記録化、完了記録の消失、抑制時の応答手 |
