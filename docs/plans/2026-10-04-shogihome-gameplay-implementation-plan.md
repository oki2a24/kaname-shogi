# ShogiHome平手対局の実装・確認計画

状態: 2026-10-04承認済み。ランチャー・テスト・独立コードレビューを完了し、ShogiHome 1.28.1で限定した平手対局と投了終了を実機確認した。学習記録・知識メモ・README・索引・ロードマップ・再開案内を作業ブランチに反映済み。2026-10-04に元のmainへfast-forwardで取り込み、取り込み先の全283テストも成功した。最後の理解確認と回答記録も完了した。

## 目的

既存の `kaname-shogi` を ShogiHome のローカル対局で起動し、平手の初期局面から合法な応手を複数回返し、通常の投了で終局できることを実機で確かめる。強さや全ルールの網羅は対象にしない。

## 根拠と未確認事項

- 第54回の使い捨てプローブでは、先手の `7g7f` 後に `position startpos moves 7g7f` と時計情報付きの `go` を受け、`bestmove resign` を返した一例がある。ShogiHomeはその後 `gameover lose` と `quit` を送った。この一例は合法な `bestmove` の受理や通常対局を示さない。
- 第56回には別の使い捨て記録用エンジンで、通常手による `position startpos moves ...` の列を観測した。これも本体エンジンの応手や対局成立の証拠ではない。
- 計画作成時点では、第55〜58回のUSI指し手変換、`position` の再生、合法手からの `bestmove` 生成、エンジン状態管理はローカルテストだけで確認されており、ShogiHomeとの実対局は未確認だった。実対局の結果は手順5〜6に記録する。
- USI原案の記述はプロトコルの参考にするが、ShogiHomeが必ず送るコマンドや受け入れる応答を、仕様または使い捨てプローブだけから追加要件として推測しない。
- 計画作成時点ではShogiHome 1.28.1にエンジンが登録されておらず、USI通信ログは無効だった。リポジトリには専用ランチャーがなく、起動方法は `python3 -m kaname_shogi.usi_engine`。このMacでは `/usr/bin/python3` (Python 3.9.6) を確認した。
- 計画作成時点で確認済みのShogiHome公式手順は実行ファイルを選ぶ登録方法であり、macOSのスクリプトにはシバンと実行権限が求められていた。実際の登録以後の画面・挙動は手順5〜6で確認した。

## 対局の範囲案

- ShogiHomeの「ローカル対局」を使い、標準の平手初期局面で始める。
- 人側を先手、`kaname-shogi` を後手にする。
- 人側が通常の合法手を指し、エンジンが少なくとも2〜3回、合法な応手を盤面に反映するところまで進める。
- その後、人側が投了し、ShogiHomeに終局が記録・表示されることを確かめる。
- 変則局面、駒落ち、詰みまでの長時間対局、強さ評価、棋譜エクスポート、時計管理の評価は範囲外。

## 実装計画

1. **完了:** 承認後、`codex/shogihome-gameplay` ブランチを管理対象ワークツリー `/Users/oki2a24/.codex/worktrees/shogihome-gameplay/kaname-shogi` に作成した。`.git` の書き込み制限により元ディレクトリではブランチを作成できなかった。元ディレクトリは `main` のままで、変更の取り込みは未実施。
2. **完了:** リポジトリ直下に実行可能ランチャー `kaname-shogi-usi` を追加した。既存の `main` を起動し、終了コードもプロセスへ伝播する。USI処理や探索の振る舞いは変更していない。シバンには確認済みの `/usr/bin/python3` を使った。
3. **完了:** 正常な `usi` 応答と不正な局面入力時の非0終了を検証する実プロセステストを追加した。ランチャー欠落時は要件のアサーションで失敗し、最初の実装後は終了コードを伝播しない不具合をテストが検出した。修正後、対象2件と全283件が成功。
4. **完了:** リファクタは不要と判断した。独立レビューの初回は終了コード未伝播をImportantと指摘し、テストを追加して `raise SystemExit(main())` に修正。再検証後の再レビューでCritical/Importantはなし。計画書の状態行の更新がMinorとして残ったため、本更新で対応。
5. **完了:** 作業ブランチの `kaname-shogi-usi` をShogiHome 1.28.1へ登録し、先手を人、後手を `kaname-shogi`、開始局面を平手にしてローカル対局を開始した。登録後のエンジン設定画面に `USI_Ponder` が既定ONと表示された。ローカル実装は `go ponder` を未対応として拒否するため、ShogiHome側の当該設定をOFFにしてから開始した。通信ログは有効化していない。
6. **完了:** 人間の７六歩に対して４四歩、人間の２六歩に対して９二飛が棋譜と盤面に反映された。人間が「投了」を選び、確認後にShogiHomeが「対局終了（投了）」を表示し、棋譜には最後の手として「投了」が記録された。観測した画面事実を第59回学習記録へ記載し、通信ログを見ていないコマンド列は推測していない。棋譜ファイルの保存・エクスポートや時計動作の評価は行っていない。
7. **完了:** 実装計画、学習記録、知識メモ、README、文書索引、再開案内、ロードマップを更新した。独立レビューの初回指摘を修正し、再レビューでCritical/Importantはなかった。作業ブランチを2026-10-04に元のmainへfast-forwardで取り込み、取り込み先の全283テストが成功した。最後の理解確認を一問だけ出し、本人の回答とアシスタントの補足を学習記録に分けて記録した。

## 完了条件

- ShogiHomeが `kaname-shogi` を起動し、標準平手局面でローカル対局を始められる。
- 人側とエンジン側の指し手が交互に棋譜と盤面へ反映され、エンジンの合法応手を2〜3回確認できる。
