# 手番更新の設計

## 目的

空マスへの移動が成功したときだけ、局面の手番を先手・後手で交代する最小の操作を追加する。既存の `Board` と `Position` の責務分離を保ち、失敗時には盤面と手番の両方を変更しない。

## 対象範囲

- `Board` は81マスの駒の配置だけを保持する可変の盤面データとする。
- `Position` は `Board` と次に指す側を表す `side_to_move` を持つ可変の局面とする。
- 既存の `move_piece(board, source, destination)` は盤面だけを変更する操作として残す。
- `Position` を受け取り、盤面移動と手番交代を順に適用する `apply_move` を追加する。
- 既存の移動が成功した場合だけ、`side_to_move` を先手・後手で交代する。
- 既存の移動が失敗した場合は、`ValueError` をそのまま送出し、盤面と手番を変更しない。

## 扱わない範囲

- 手番と出発駒の所有者が一致するかの検証
- 駒取り、持ち駒、成り・不成
- 移動方向、候補生成結果、王手、王手放置を避ける合法手判定、詰み
- CLI入力、評価、探索
- 不変な盤面・局面へ変更すること

## 用語と責務

- `Square` は筋・段を表す不変の値であり、移動操作ではない。
- `Piece` は駒種と所有者を表す不変の値である。
- `Board` は盤面だけを保持する可変のデータであり、手番を持たない。
- `Position` は盤面と手番をまとめる可変の局面である。
- `move_piece` は空の到着マスへの盤面移動だけを行う操作である。
- `apply_move` は一手を局面へ適用する操作であり、既存の盤面移動に成功した後だけ手番を更新する。

## 公開インターフェース

```python
def apply_move(position: Position, source: Square, destination: Square) -> None:
    """空の到着マスへの移動と手番交代を、渡された局面へ適用する。"""
```

引数の `position` は変更対象の可変な局面、`source` と `destination` は移動元・移動先の筋・段を表す `Square` である。戻り値はない。

内部では次の順に処理する。

1. `move_piece(position.board, source, destination)` を呼ぶ。
2. 成功時だけ、先手なら後手、後手なら先手へ `position.side_to_move` を更新する。

`move_piece` が空の出発マス、占有された到着マス、同一マスで `ValueError` を送出した場合、2には進まない。このため失敗時は盤面も手番も不変である。

## 判断理由

`move_piece` を `Position` 用に置き換えず、別の `apply_move` を追加する。これにより、盤面だけを扱う操作と局面を進める操作を分けて理解・テストできる。

本格的な将棋ライブラリでは、盤面・手番・履歴を一つの `Board` にまとめ、`push` で指し手を適用する例がある。しかし、現在のプロジェクトでは `Board` と `Position` の役割をすでに分けており、持ち駒・成り・履歴・探索は未実装である。今回 `Board` に手番を移すと学習済みの責務を崩し、対象範囲を不必要に広げるため採用しない。

また、手番と出発駒の所有者の一致は今回検証しない。今回の焦点は、既存の移動が成功した場合だけ手番を交代することである。所有者、移動方向、王手を含む検証は合法手判定の段階で扱う。

## 確認方法

- 先手番で移動が成功すると、盤面が更新され、手番が後手になることを確認する。
- 後手番で移動が成功すると、盤面が更新され、手番が先手になることを確認する。
- 空の出発マス、占有された到着マス、同一マスへの移動では `ValueError` となり、81マスの盤面と手番がともに変わらないことを確認する。
- 出発駒の所有者と手番が異なっても、今回は移動成功後に手番を交代することを確認する。
- 既存の `move_piece` が手番を変更しないことを維持する。
