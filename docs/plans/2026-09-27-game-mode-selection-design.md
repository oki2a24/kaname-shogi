# 第41回 対局モードの選択：設計書

作成日：2026-09-27

## 目的

CLI対局の進行設定として、人間対人間・人間対コンピュータ・コンピュータ対コンピュータを明示して選べるようにする。将棋の局面規則、合法手生成、弱い一手選択、`GameRecord`は既存の責務を保ち、各手番を人間とコンピュータのどちらが担当するかだけをCLI進行層で切り替える。

## 規則とCLI進行設定の切り分け

日本将棋連盟の対局規則第2条第1項は、先手番を持つ対局者が開始し、二人の対局者が交互に駒を動かすことを定める。同規則第10条第1項は、先後誤りと二手指しを反則としている。

このため、`Position.side_to_move`を成功手の後に先後交代させる局面規則は、対局形式にかかわらず維持する。一方、人間が入力を行うか、コンピュータが合法手を選ぶかは、規則が定める事項ではない。本プログラムのCLI進行設定として`GameMode`が決める。

出典：[日本将棋連盟「対局規則」](https://www.shogi.or.jp/match/taikyoku_rules/taikyoku_rules.pdf)

## 対象範囲

- `GameMode`を、対局形式を表す公開の`Enum`として追加する。これは局面を変更しないデータである。
- `run_game`の公開引数で`GameMode`を指定できるようにする。
- `python3 -m kaname_shogi`の起動時に、三形式を番号で選べるメニューを追加する。
- 一つの共通対局ループで、人間入力とコンピュータの自動手を手番ごとに切り替える。
- 既存の詰み、投了、EOF/Ctrl-C、詰みではないコンピュータの合法手空一覧、表示、`GameRecord`の意味を三形式へ適用する。

## 対象外

- 人間後手・コンピュータ先手の対局形式。
- 千日手、持将棋、入玉、手数上限、時間、反則勝敗。
- コンピュータの投了、評価、探索、定跡、強さ調整。
- USI、SFEN、CLIの保存・読込。
- 盤面・持ち駒・合法手生成・局面適用・棋譜形式の変更。

## 対局形式と担当

`GameMode`は次の三値を持つ。値名には英語名を使うが、いずれも対局形式を表すデータであり、「入力する」「指す」という操作ではない。

| 値 | 日本語名 | 先手の担当 | 後手の担当 |
| --- | --- | --- | --- |
| `HUMAN_VS_HUMAN` | 人間対人間 | 人間 | 人間 |
| `HUMAN_VS_COMPUTER` | 人間対コンピュータ | 人間 | コンピュータ |
| `COMPUTER_VS_COMPUTER` | コンピュータ対コンピュータ | コンピュータ | コンピュータ |

`GameMode`の担当照会を、`_is_human_turn`が利用する。先手・後手という将棋規則の状態は`Position.side_to_move`だけが持ち、対局形式はそれを書き換えない。

## CLIと進行

`__main__.py`は、標準入力から対局形式を選ぶ小さなメニューを表示し、選んだ`GameMode`を`run_game`へ渡す。選択に失敗したときの扱いは、既存の指し手入力と混ぜず、対局開始前に同じメニューを再表示する。テストではメニュー入力を注入できるようにする。

`run_game`は`mode`引数の既定値を`HUMAN_VS_COMPUTER`とする。これにより、既存の`run_game()`呼び出しは人間先手・コンピュータ後手のまま動く。初期局面を表示した後、毎手番で次を行う。

1. `is_game_over`で詰みを先に確認し、詰みなら勝者を表示して記録を返す。
2. `GameMode`と現在の手番から人間担当かを決める。
3. 人間担当なら、入力案内、`move`・`drop`・`resign`の処理、形式・合法性エラー時の同じ手番での再入力を行う。
4. コンピュータ担当なら、`legal_moves`、`choose_weak_move`、既存の`GameRecord`適用経路を使い、選んだ手と適用後局面を表示する。

成功した人間手・コンピュータ手の後には、既存の局面適用が`side_to_move`を一度だけ交代させる。これにより、担当が同じ形式でも二手連続で着手しない。

## 終局・中断・記録

人間担当の`resign`は、その人間側の投了として相手の勝ちを表示する。人間入力待ちのEOFまたはCtrl-Cは「入力を終了しました。」を表示し、勝者なしで記録を返す。局面は変更しない。

コンピュータ担当の手番では入力を読まないため、`resign`とEOFを処理しない。コンピュータ対コンピュータでも、詰みと詰みではない合法手空一覧で自動停止する。Ctrl-Cは、コンピュータ手の選択・適用・表示の合間に発生した場合にも、勝者なしで中断できるように進行層で扱う。千日手・持将棋・手数上限は追加しないため、コンピュータ対コンピュータが長時間または無限に続く可能性は残る。

`GameRecord.moves`には、`GameRecord`経由で成功適用した盤上移動・駒打ちだけを順番どおり残す。投了、EOF、Ctrl-C、詰み、合法手空一覧、メニュー選択は記録しない。

## 乱数の再現性

`run_game(rng=...)`へ渡された一つの`random.Random`を、一局の全コンピュータ手で再利用する。省略時は一局の開始時に一つだけ生成する。人間担当の手番では乱数を消費しない。

したがって、同じ開始局面、`GameMode`、固定種の`rng`、人間入力列なら、コンピュータ担当の手、`GameRecord`、表示を再現できる。人間対人間では乱数選択を行わない。

## 確認方法

### TDDで追加する確認

- `GameMode`の三値と、それぞれの先後担当を確認する。
- `run_game`が人間対人間では両手番の入力を読み、人間対コンピュータでは現行どおり先手入力後に後手自動手を指し、コンピュータ対コンピュータでは入力を読まずに先手・後手の自動手を交互に指すことを確認する。
- 各形式で、成功した盤上移動・駒打ちが順番どおり`GameRecord.moves`へ入り、停止イベントや未適用手が入らないことを確認する。
- 固定種と同じモードでの再現、複数自動手での一つの乱数生成器の再利用、人間対人間で乱数を消費しないことを確認する。
- 人間担当の投了・EOF、全形式のCtrl-C、詰み、コンピュータの合法手空一覧の表示・停止・勝者有無を確認する。
- 通常CLIのメニューで各形式を選べること、無効な選択では対局を開始せず再入力になることを確認する。

### 回帰確認

- `python3 -m unittest discover -s tests -v`を実行する。
- 人間対コンピュータの既存の固定種、表示順、駒打ち記録、エラー再入力のテストを維持する。
- `printf`による通常CLIのスモークで、メニュー選択、人間対コンピュータの一手、EOF終了を確認する。
- `git diff --check`を実行する。

## 受け入れ条件

1. 利用者とテストが、三形式を明示して選べる。
2. 先手・後手は全形式で交互に指し、担当だけが`GameMode`で切り替わる。
3. 人間担当・コンピュータ担当それぞれの表示、入力、乱数、停止が合意内容に従う。
4. 成功した盤上移動・駒打ちだけが`GameRecord`へ記録される。
5. 人間対コンピュータの既存の公開的振る舞いを、`run_game()`の既定値として保つ。

## 未解決事項

なし。コンピュータ対コンピュータの無限継続可能性は、千日手・手数上限を今回の対象外とする合意に基づく既知の制約である。
