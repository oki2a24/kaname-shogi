# 古い文書記述の是正：設計仕様

作成日：2026-09-27

## 目的

現在情報として参照される文書に残った古い記述だけを、現在の完了記録と文書上の役割を根拠に、必要最小限で是正する。過去の判断を消さず、現在の状態と履歴を読み分けられるようにする。

## 根拠

- 第43回は、文書ナビゲーションの改善と古い内容の是正を別テーマにすることを合意した。
- 第44回は文書ナビゲーションの改善を完了し、次テーマとして古い文書記述の是正を選定した。
- `docs/02-project-direction.md` の無見出しの方針・目標・未決定事項には、第42回までの実装・完了記録と矛盾する記述が残る。
- `docs/next-topics.md` は第42回完了時点の候補・推薦と、現在の選定を同一文書に持つため、時点の区別を明示する必要がある。

## 対象と情報の境界

変更対象は、`docs/02-project-direction.md` と `docs/next-topics.md` を基本とする。別の入口文書は、現在情報として読まれる根拠付きの古い記述が見つかった場合だけ、事前に追加の承認を得て扱う。

`docs/02-project-direction.md` では、無見出しの長期方針、最初のゴール、段階的な発展の見通し、「まだ決めていないこと」を現在情報として扱う。第32回から第42回までの「完了時点の見直し」は当時の判断履歴であり、変更しない。

`docs/next-topics.md` では、第42回後の候補、推薦、基盤整理の選定経緯を履歴として内容を変えず残す。現在の選定との境界を、題名・見出し・短い導入文で明示する。

学習記録、既存の設計書、既存の実装計画、引き継ぎ、ロードマップは、それぞれの時点の履歴として変更しない。既存文書の移動・改名・削除、コード・テスト・将棋規則・CLI動作・JSON保存形式の変更も対象外とする。

## 是正する表現

### `docs/02-project-direction.md`

- 最初のゴールが第42回までに達成済みであることを短く追記し、現在はリポジトリ基盤整理の小テーマを進めていると示す。
- 段階的な発展の見通しは将来像として維持し、最初の到達点を終えた現在地と矛盾しない最小限の補足を加える。
- 「まだ決めていないこと」から、使用するプログラミング言語と開発環境、盤面・駒・持ち駒・指し手の表現、最初の規則範囲、局面表示・入力、テスト方針を外す。USI/SFENの導入時期と範囲、探索・評価・強化、公開方法とライセンスは未決定として残す。

### `docs/next-topics.md`

- 題名と「現在地」「推薦」を、第42回完了時点の履歴と分かる名称にする。
- 冒頭に、現在の選定が「古い文書記述の是正」であることと、詳細な現在情報は `docs/resume.md` と `docs/roadmap-repository-foundation.md` を参照することを記す。
- 第42回時点の候補、推薦、基盤整理を選んだ経緯は内容を改変しない。

## 実施と検証

この設計の承認後に、`codex/stale-document-correction` 作業ブランチで実装計画を作成する。実装計画の明示承認までは、上記の対象文書を変更しない。

実装後は、変更対象文書、新規の実装計画、学習記録の相対Markdownリンクを検査する。あわせて `git diff --check`、`git diff --exit-code -- kaname_shogi tests`、既存全ユニットテストを実行する。独立レビューではCritical・Important・Minorを判定し、CriticalまたはImportantがあれば是正、再検証、再レビューを行う。結果と判断は学習記録に残す。

## 設計の自己レビュー

- 対象文書と変更しない履歴文書を区別した。
- 現在情報の是正と、過去の判断内容の改変を混同していない。
- コード、テスト、将棋規則、CLI動作、JSON保存形式の変更を含まない。
- 未決定の対象やプレースホルダは残していない。追加対象が必要になった場合は、実装前に本人の承認を得る。
