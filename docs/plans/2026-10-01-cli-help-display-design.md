# CLIの `help` 表示：設計仕様

## 目的

対局中に人間が `help` と入力すると、利用可能な `move`、`drop`、`resign`、`save <path>`、`load <path>` の書式と短い動作説明を確認できるようにする。

## 合意した範囲

### 対象

- `help` を人間入力コマンドとして解析する。
- コマンドの書式と動作説明を `output_fn` へ表示する。
- 表示後は局面・手番・棋譜を変更せず、同じ人間手番で入力を続ける。
- READMEのCLI操作に `help` を案内する。

### 対象外

- 既存コマンドの文法、将棋規則、保存形式、解析・進行動作の変更
- 毎回の「指し手を入力してください」案内文の変更
- `_hand_counts` の重複、SFEN、USI、評価関数、探索
- 実端末での手動確認

## 表示内容

一覧には次の5コマンドを示す。

```text
move <出発筋> <出発段> <到着筋> <到着段> [+]
drop <歩|香|桂|銀|金|角|飛> <筋> <段>
resign
save <path>
load <path>
```

各行に短い説明を添え、`+` が成りを表すこと、筋・段に全角数字も使えること、パスは空白なしの一語であることを記す。保存成功後は同じ手番を続け、読込成功後は読み込んだ局面から再開することも案内する。将棋規則や保存形式の詳説は含めない。

## 解析・公開API・進行

`HelpCommand` を、解析済みの `help` 指示を表す凍結データ型として追加する。これは局面を変える操作ではなく、指示の種類を表す値である。公開 `Command` 型別名に含め、`cli.__all__` に追加する。`parse_command("help")` は `HelpCommand` を返す。

`run_game` は `HelpCommand` を受け取ったとき、既存の `output_fn` へヘルプ文を渡し、対局記録の更新や盤面表示をせず次の入力へ進む。表示文は既存の案内文字列とは別にし、毎回表示される入力案内文は維持する。

既存5公開型の属性と凍結性、5コマンドの入力文法・解析結果・エラー文言・進行動作は変えない。公開APIは `HelpCommand` が加わる分だけ拡張する。

## 既存テストの意図と確認方法

既存の `CommandParsingTests` は各コマンドの形式と解析結果、全角・半角入力、および不正形式の例外文言を守る。既存進行テストは、保存・読込・投了・着手などの状態変化と再入力の境界を守る。これらの期待値を維持し、公開 `__all__` の一覧に `HelpCommand` を追加する。

新しいテストで、`help` の解析結果と表示内容、表示後も同じ手番・局面・棋譜が保たれて入力が再開することを確認する。表示は差し替え可能な `output_fn` を通して検証する。

確認コマンドは次のとおり。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest tests.test_cli -v
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
git diff --check
```

対象の解析・進行テスト、CLI全体、全テストを実行し、差分と文書リンクも確認する。テスト追加に伴う件数変化は実施結果へ記録する。

## 記録と次の承認

設計判断、実装内容、TDDのRed/Green、Refactor要否、独立レビュー（Critical・Important・Minorと対応）、検証結果、未解決事項をテーマの学習記録へ残す。READMEの利用案内を更新し、索引と再開案内はテーマ完了時に整える。将棋規則・保存形式の確定知識は増えないため、知識メモは追加しない。

本仕様書の自己レビュー後、本人の仕様書レビュー・承認を待つ。仕様書が承認されたら実装計画を文書化して提示し、その明示承認を待つ。計画承認前に作業ブランチでのTDD、コード・テスト・既存文書の変更、実装を始めない。実装は目的が分かる作業ブランチで行い、日本語のConventional Commitを使う。
