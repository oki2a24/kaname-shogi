# 文書整理と継続保守の実施計画案

**状態：** 2026-11-01作成。同日、本人が「承認する」と明示し、実施を開始した。

**目標：** 人と生成AIが現在の正本・承認段階・履歴に到達し、文書を継続更新できるようにする。

**方法：** 既存の入口と更新ガイドを整え、リポジトリ内で発見可能な文書整理スキルに共通の判断手順を置く。現在仕様はコード・学習記録に照合し、履歴と本人回答を保全する。スキルとガイドは責任を分け、互いに矛盾させない。

**使用する形式：** 既存のMarkdown文書とリポジトリ内Codexスキル。新しい製品コード・テスト・リンク検査スクリプトは今回作らない。

**仕様：** [本人承認済み設計](2026-11-01-documentation-maintenance-design.md)。各タスクの作業場所は `/Users/oki2a24/kaname-shogi`、branchは `codex/documentation-maintenance`。別worktree・別cloneは使わない。`.agents/tasks/`、`data/comparison/runs/`、C2保護4件、既存の未追跡物を変更しない。main統合とpushはそれぞれ別途承認を待つ。

## 見落としを防ぐ観点

1. 古い履歴を現在地と誤認しない。過去の回答・承認・リンク先は保持する。
2. コード・最新の学習記録と現行知識が食い違うときは、確認できた対象と時点を示す。
3. 依頼が簡単な誤字修正なら大規模棚卸しを強制せず、提案と本人の承認を混同しない。
4. このリポジトリ以外へスキルを設置せず、`.agents` の権限拒否を回避しない。
5. リンクの存在確認だけで内容・承認・棋力の真偽を保証しない。
