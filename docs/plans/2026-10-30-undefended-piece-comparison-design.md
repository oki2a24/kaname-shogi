# 駒の連携評価を接続して比較する：承認済み設計

## 状態と対象

2026-10-30作成。本人は比較CLI限定で、同一の一手選択経路における連携評価Uの重み0と1を比較し、予備比較と独立確認比較を行う方式を選んだ。独立ビルダーチェックでは重要な未解決質問なしとの結果だった。本人は同日、設計と実装計画の全体を明示承認した。実装・検証結果は後段の実装記録と実装計画を参照する。

今回の目的は、直前のB段階で実装した `E=10M+U` を既存の一手選択経路へ接続し、Uを加えることによる成績差を調べること。本人は評価項目のテーマを選んだ理由を述べていないため推測しない。

## 目的・仮説

改善仮説は「駒得評価と一手詰み優先を同じに保ち、攻撃され支えのない駒の差Uを加えると、比較した局面群における候補方式の得点が変化する」である。

主判定は候補方式の組平均得点率が互角境界50%を上回るか、下回るか、判断できないかとする。方式が比較可能になったことと、今回登録した局面群で改善を支持する結果が得られたこと、一般的な棋力向上は区別する。結論は登録局面・探索・手数上限・比較条件の範囲に限る。

## 比較した接続案と選択

| 案 | 比較 | 扱う差 |
| --- | --- | --- |
| 同じ選択経路の重み0対1 | `10M` 対 `10M+U` | 一手詰み優先と選択器をそろえ、Uを加える差を調べる。本人が選択 |
| 既存 `material` 対候補 | 既存駒得方式 対 `10M+U` | B段階の評価接続・評価重み・詰み優先をまとめた方式全体の差 |
| 通常CLIやUSIへの公開 | 各対局経路から候補を選択可能にする | 実験用接続を越えて通常利用の範囲を広げる |

今回は一つ目を採る。二つ目では既存 `material` に一手詰み優先がなく、U以外の差も含む。三つ目は今回の比較対象に含めない。

## 接続方式

比較CLIに限り、次の二方式を追加する。

| 方式名 | 設定 | 選択経路 |
| --- | --- | --- |
| `material-undefended-piece-material-only` | `UndefendedPieceWeights(material=10, undefended=0)` | `choose_one_ply_move` と一手詰み優先 |
| `material-undefended-piece` | `UndefendedPieceWeights(material=10, undefended=1)` | 同じ `choose_one_ply_move` と一手詰み優先 |

両方式ともB段階の `evaluate_material_undefended_piece` を使う。同操作はU重み0でもUを計算する契約なので、比較経路と評価計算をそろえ、重みだけを差とする。比較CLIの方式名、局面、seed一覧、summary、分析結果へ両方式が正しく記録されることを設計対象とする。

通常CLI・USIの方式選択肢、SFEN入出力、飛車可動性バージョン2、玉周辺安全度との合成、二手・四手への適用、ShogiHome対局は含めない。C2の4成果物と元の `/Users/oki2a24/kaname-shogi` の作業状態は保護対象とし、新しい比較の保存先に使わない。

## 比較局面

比較CLIが受け付ける既存形式に従い、平手初期局面からの合法なUSI指し手列で5つの開始局面を作る。以下の5局面は設計探索時に既存の局面読込・評価操作で読み取り検算し、全列が合法で、開始局面が重複しないことを確認した。C/Uの期待値はB段階の定義から個別に数え、プログラム出力から逆算した値を仕様とはしない。

| ID | setup_moves | 手番 | 先手C / 後手C | 先手U | 役割 |
| --- | --- | --- | --- | ---: | --- |
| `initial` | なし | 先手 | 0 / 0 | 0 | 平手の中立対照 |
| `two-unsupported-pawns` | `7g7f 3c3d 7f7e 7c7d` | 先手 | 1 / 1 | 0 | 双方に攻撃され支えのない歩があるが、差は0 |
| `both-pawns-supported` | `7g7f 3c3d 7f7e 7c7d 6i7h 6a7b 7h7g 7b7c 7g7f` | 後手 | 0 / 0 | 0 | 双方の対象歩に支えができた対照 |
| `sente-threatened` | `7g7f 3c3d 7f7e 7c7d 2g2f 6a7b 2f2e 7b7c` | 先手 | 1 / 0 | -1 | 先手の支えのない歩が狙われる状態 |
| `gote-threatened` | `7g7f 3c3d 3g3f 3d3e 4i3h 4c4d 3h3g 9c9d` | 先手 | 0 / 1 | +1 | 後手の支えのない歩が狙われる状態 |

Uは `後手C - 先手C`。後手視点のUは上記先手Uの符号反転となる。5局面はそれぞれ同じ重みで集計する。局面別と先後別の得点は記述値に留め、個別の強さ判定には使わない。局面ファイル `data/comparison/undefended-piece-positions-v1.json` を新規作成し、C1/C2の局面集合を流用しない。

## 二段階の比較条件

本人の希望により `--workers 4` を基本とする。pilotとconfirmationにはそれぞれ新しい独立seed一覧を作る。方式ごとのseedは各組で事前に割り当て、先後を交換した二局では同方式のseedを使う。

### 予備比較

| 項目 | 条件 |
| --- | --- |
| 目的 | 比較経路・保存・分析の動作、所要時間、上限到達や未裁定の有無を確認する |
| 局面数 | 5。上表の全局面 |
| 組数 | 各局面10組、合計50組・100局 |
| 手数上限 | 1局1024手 |
| worker | 4 |
| seed | `purpose=pilot` の新規seed一覧 |
| 成績の扱い | 記述のみ。改善・悪化の判定へ使わない |

pilotはconfirmationへ合算しない。比較・分析の入力と出力は専用の新規パスを使う。途中中断後の再開は同じseed一覧、条件、出力先に `--resume` を付ける。

### 独立確認比較

| 項目 | 条件 |
| --- | --- |
| 目的 | U重み1の候補方式が、U重み0の対照より高い得点を得るか主判定する |
| 局面数 | 5。上表の局面を均等重みとする |
| 目標組数 | 合計2035組、各局面407組、計4070局 |
| 手数上限 | 1局1024手 |
| worker | 4 |
| seed | `purpose=confirmation` の新規seed一覧。pilotとは独立 |
| 未決着・未裁定 | 削除・再戦・勝敗決め打ちをせず、分析CLIの候補視点 `[0,1]` の上下限へ含める |

組得点は先後交換二局の候補側得点平均で、勝ち1・負け0・通常千日手0.5。組内二局を独立とは仮定せず、組を独立抽出単位として扱う。

組得点の上下限平均を `Lbar` と `Ubar`、組数を `n` とし、`e = sqrt(ln(40)/(2*n))`、95%区間を `[max(0, Lbar-e), min(1, Ubar+e)]` とする。区間下端が0.5を上回れば改善を支持、上端が0.5を下回れば悪化を支持、それ以外は判断不能とする。仮目標55%・互角境界50%・信頼水準95%・検出力80%の下で、Hoeffding不等式による十分条件は `n > (sqrt(ln(40)) + sqrt(ln(5)))^2 / (2 * 0.05^2) = 2034.3037...`、したがって2,035組である。各局面へ均等に割り当てるため5で割り切れる2,035組を採る。これは未決着なしの場合の計画上の参考であり、必要最小数でも棋力改善の保証でもない。未決着があれば目標検出力を保証しない。

1024手上限は過去の比較で未決着を減らせた範囲を参考にして選んだ条件であり、今回の方式で同じ未決着率や実行時間になる保証はない。pilotの結果を強さ判定に使わない。正常な完了と分析ができた場合は、事前固定したconfirmation条件へ進み、上限到達が残れば分析区間に反映する。入力不正・保存故障・条件不一致が起きた場合はconfirmationを開始せず、原因と状態を報告する。

## テストの契約と範囲

実装計画で、次の契約ごとに新しいテストと既存テストの補完を定める。期待値は上表の独立C/Uと、B段階の設計A/B/Cおよび一手選択例から決める。

| 契約 | 代表ケース・検出対象 |
| --- | --- |
| 比較policyの対応 | 対照が重み10/0、候補が10/1で同じ一手選択器へ渡る。取り違え、候補側重み0、対照側重み1を検出する |
| 独立期待値の接続 | 支えを作る候補と支えから離れる候補で、両方式は重み0の同点、候補は重み1で期待差をつける。候補順・先後反転で固定や符号誤りを検出する |
| 詰み優先 | 既存一手選択器の詰み優先を両方式で維持する。通常評価を巨大値にする変異でも詰みを選ぶ |
| CLI入力・方式名 | `--baseline` / `--candidate` から2方式を選べる。既存方式の選択と旧artifact読込を回帰確認する |
| 条件・結果の保存読込 | conditions・棋譜・summary・分析結果に方式の識別が一貫する。方式対応の欠落や取り違え、旧成果物の誤読を検出する |
| 先後交換と集計 | 小規模pipelineで候補が両先後に割り当てられ、候補視点の得点区間へ集計される。上限未決着・双方未裁定は `[0,1]` に残る |
| 局面セット | 5局面を独立値と照合し、重複・不正手順・手番の誤りを検出する |

対象行動ごとに未実装状態で狙ったassertionが失敗することを確認し、読み込みエラーのみをRedと数えない。代表変異を隔離コピーへ入れ、意図したassertion failureと復元後成功を確認する。単独テストが検出する誤りと、既存テスト全体が補う旧policy・artifact・分析readerの回帰を区別する。計画作成時は `~/.codex/observations/test-driven-development.md` と `docs/knowledge/test-coverage-review.md` を適用する。
