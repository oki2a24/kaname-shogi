# AIとの共同作業に向けた文書運用整理 実装計画

> **AIエージェントへの指示:** この計画を実行するときは、移植された `executing-plans` スキルを使用してください。各ステップのチェックボックスを実際の進捗に合わせて更新してください。

**目標:** 必要な文書だけを選択して現在地・確定知識・判断履歴へ到達できる運用に整え、次テーマ選定後は本人の別希望がない限り新セッション用の引き継ぎを作成する。

**アーキテクチャ:** 現在の文書群と役割分担を土台にし、AI向けの常時指示と条件別の参照手順を整理する。次テーマ候補の過去記録は履歴側へまとめ、学習記録・設計判断・本人回答は保持する。新しい分類システムへの全面移行や全資料の書き直しは行わない。

**技術スタック:** Markdown、Git、Python標準ライブラリによる一時的な文書リンク検査。新たな依存関係や配布スクリプトは追加しない。

**仕様 (Spec):** 本書の「合意済みの対象と成功条件」。背景の記録は [前回の文書整理記録](../learning/documentation-chapter.md) と [今回の開始時引き継ぎ](../handover-documentation-chapter.md) を参照する。

**グローバル制約 (Global Constraints):**

- 既存の文書を正本として保ち、同じ現行情報の全文を複数の入口へ重複して置かない。
- 再開時はGitの現在状態と短い再開案内で現在地を確認し、README・索引・設計・知識・学習記録・過去引き継ぎは作業目的に応じて選ぶ。
- テーマ完了後の理解確認は一問ずつ行う。本人の回答と補足を区別し、未回答を完了扱いにしない。
- 次テーマ選定時は、本人から別の希望がない限り、新セッション開始用の引き継ぎ作成へ進むことを明示する。引き継ぎプロンプトの入力前に次テーマの学習・実装を開始しない。
- 学習記録、設計判断、本人回答、未確認事項を削除・改変しない。移す記録は元の内容を保全し、作成時点と履歴の性質を明記する。
- 学習回・章番号を改番しない。未決定の方式・エンジン構成を先取りして決めない。
- 変更は文書だけとし、製品コード、テストコード、Ruff設定、ShogiHome操作、評価・探索の学習・実装に広げない。
- 日本語で記録し、相対リンク・見出しアンカーを変更した場合は参照元を確認する。
- 独立レビューのCritical・Important指摘は解消して再確認する。mainへの取り込み・pushは別途本人の明示承認を待つ。

## 調査から採用する原則

- [OpenAI: Rethinking skills and prompts](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)：常時適用のAGENTS.mdを必要性に照らして見直し、全作業へ同じ資料読込を求めず、関連時に資料を案内する。
- [Diátaxis](https://diataxis.fr/) と [Google Technical Writing: Audience](https://developers.google.com/tech-writing/one/audience)：学習、作業手順、確定情報の参照、背景説明を読み手の目的に合わせる。分類は既存資料を見直す観点に使い、空の区分を作ったり全面移行したりしない。
- [Write the Docs: Docs as Code](https://www.writethedocs.org/guide/docs-as-code/) と [GitLab Documentation Style Guide](https://docs.gitlab.com/development/documentation/styleguide/)：Git差分で文書をレビューし、相対リンク・見出し変更の参照を検査する。AI作成文は重複、根拠、対象範囲を確認する。

## 合意済みの対象と成功条件

| 情報 | 正本・入口 | 今回の扱い |
| --- | --- | --- |
| 利用者向けの機能・利用・開発環境 | `README.md` | 正本として維持。AI向け作業指示との重複を増やさない |
| 文書の地図と目的別の参照先 | `docs/README.md` | 役割とリンクを更新。全学習記録を一括で読む指示にしない |
| 現在の作業状態 | `docs/resume.md` | 短い現在地と次に読む入口を更新 |
| 現在のテーマと候補 | `docs/next-topics.md` | 現在選択・未選定状態と現在候補を残す |
| 過去の候補提示・選定経緯 | `docs/next-topics-history.md` | `docs/next-topics.md` に残る日付付き履歴を保全して集約 |
| 文書の更新・参照・履歴運用 | `docs/documentation-guide.md` | 正本・選択的読込・段階ごとの更新・既定の新セッション引き継ぎを明記 |
| AIに常時適用する規則 | `AGENTS.md` | 必須の不変条件と条件付き参照を短く明確にする |
| 今回の目的・判断・検証・振り返り | `docs/learning/documentation-practices.md` | 実施後に作成し、本人回答は回答後に記録 |

README・`docs/02-project-direction.md`・既存の再開案内は現状を監査し、誤解や重複が確認された場合だけ最小修正する。過去の引き継ぎは作成時点の履歴として維持する。

成功条件：

1. 再開時にGit状態と再開案内で現在地が分かり、目的別に選んだ正本へ進める。作業と無関係な学習記録一式を読む必要がない。
2. 現行情報の正本が分かり、入口は短い説明とリンクに留まる。
3. 次テーマ候補の現在情報と過去の選定履歴が分離され、履歴本文の欠落・改変・意図しない重複がない。
4. 次テーマ選定時の既定動作が、新セッション用引き継ぎの作成・提示である。本人がプロンプトを入力するまでは次テーマへ進まない。
5. 変更した相対リンクと見出しアンカーが有効で、差分に文書以外の変更がない。
6. 独立レビューの重大度別結果、検証、未解決事項を学習記録へ残す。

## レビューフォーカス

1. **重要な規則の過剰な圧縮:** AGENTS.mdを短くする過程で承認、履歴保全、テスト、独立レビュー、main統合の条件を落とさない。
2. **無関係な文書を読み飛ばす:** 選択的読込の導入後も、現在テーマに必要な承認済み仕様・計画・知識・未完了記録は索引から辿れる。
3. **候補履歴の欠落:** next-topicsを短くする際、既存のnext-topics-historyと照合し、各日付の提示・理由・本人の選択を保持する。
4. **引き継ぎ開始の誤作動:** 次テーマ選定後にプロンプトを作る既定を示しつつ、本人が新セッションへ入力する前に次テーマを開始しない。
5. **相対リンクの破損:** 見出し・ファイルの変更後、変更ファイルだけでなく参照元のパスとアンカーも確認する。
