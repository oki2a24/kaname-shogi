# C1比較CLIの局単位再開：設計案・実装計画

2026-10-25作成。本人が実装計画全体を承認し、TDD・実装を開始した。通常CLI/USI、SFEN入出力、飛車可動性バージョン2は対象に含めない。

**目標:** 人が端末で比較を中断・再開し、完了済み局を保持できるようにする。

**実行方法:** 本人の既存選択に従い、このセッションの担当者が順に実装する。承認後にexecuting-plansとtest-driven-developmentを使用する。

**技術スタック:** 既存のPython標準ライブラリ、`unittest`、JSON成果物形式。

**仕様:** 本書の「承認対象の設計」。別の仕様ファイルはない。

## グローバル制約

- Python 3.9互換を維持し、依存関係を追加しない。
- 日本語の公開CLI説明・docstringを更新する。
- 通常CLI/USI、評価ロジック、着手単位チェックポイント、自動時間停止を変更しない。
- テストは独立した期待値を持ち、red確認・検出力・全体検証を記録する。

## レビューフォーカス

- 保存済み局面と異なるコードで再開を要求したとき、対局を一局も始めず拒否する。
- 完成局と未完了局が混在するとき、完成局JSONを保持し同じseedで未完了局だけを実行する。
- 壊れた局JSONや予定外ファイルがあるとき、黙って除去・再実行せず拒否する。
- 同じ出力先を別プロセスが使用中のとき、二重投入を防ぎ、異常終了時の残存ロックを安全に扱う。
- 古いsummaryや強制終了による時間欠落があるとき、結果を重複計上せず時間の限界を示す。

## 合意済み

- 6局面各340組、計2,040組・4,080局、各局512手、4worker。
- 本人が端末から長時間実行し、完了後に知らせる。
- 局単位で再開。未完了局は同じseedで開始局面から実行する。
- 同じコードでのみ再開する。
- 元のコマンドに `--resume` を追加する。

## 承認対象の設計

1. 通常実行は新しい出力先を要求する。再開は既存の比較出力先を要求する。書込みと対局開始の前に全入力と既存記録を検証する。
2. 比較方式・評価重み・局面入力の内容・seedまたはseed一覧・全予定・組数・手数上限・worker数を照合する。Pythonの版と実装、OSと機械種別も一致を要求する。
3. 同じコードかは既存のsource_sha256（パッケージ内Pythonソースのパスと内容）で判定する。文書だけのコミットでHEADが変わっても受理する。同HEADでもソース指紋が違えば拒否する。
4. 元conditions.jsonのバイト列とハッシュは保持する。再生成して上書きしない。不一致は出力を変更せず入力エラーとして終了する。
5. 局JSONを予定ID・条件ハッシュ・合法手順・終局判定まで既存readerと共通の処理で検証する。正常な終局結果（手数上限等の未決着を含む）は保持する。欠落局と正常に記録されたERROR/INTERRUPTED局は再実行する。破損JSON・予定外局・条件不一致は黙って捨てず拒否する。
6. summaryを完了局の正本にしない。欠落・古いsummaryは検証済み局JSONから再集計する。完成局のJSONは書き換えない。
7. 完成結果を実行器の初期値とし、未完了予定だけを投入する。全局完成なら対局せず正常終了する。中断を繰り返してもgame_idごとに一度だけ集計する。
8. Ctrl-Cは新規投入を止め、実行中局の終了を待つ既存動作を維持する。強制終了で保存されなかった局は局頭から再実行する。保存途中の一時ファイルは結果に含めない。
9. 同じ出力先への同時実行を排他ロックで拒否する。正常終了・通常Ctrl-C・例外時に解放する。強制終了後の残存ロックは自動解除せず、他プロセスが停止していることを確認して解除する端末手順を案内する。
10. 保存済みの各局の計測時間を保持する。バッチ時間は実行区間を累積し停止中を除く。強制終了した区間の保存前の時間は復元できないため、欠落し得る下限値と明示する。必要な保存形式の変更は分析readerへも接続する。

通常CLI/USI、評価ロジック、手ごとの保存点、総時間による自動停止は対象外。再開後は連続実行と棋譜・終局・勝敗・得点の一致を確認し、処理時間の一致は要求しない。追加前のpilotはコード指紋が変わるため新コードから再開できない。

## TDD手順

各タスクでテスト作成→振る舞いのRed確認→最小実装→Green確認→Refactor要否確認を行う。読込失敗だけをRedと扱わない。既存処理で初回Greenの場合はその事実を記録する。

### タスク 1: 入力・条件照合

- [x] 通常時の既存先拒否、再開時の存在しない先拒否、同条件受理をテストする。
- [x] 方式・seed・局面内容・上限・worker・実行環境・コード不一致を個別に拒否するテストを作る。文書だけのHEAD変更は受理、同HEADのソース変更は拒否とする。
- [x] 対象テストで意図したRedを確認する。
- [x] 最小実装、Green確認、Refactor要否点検を行う。

### タスク 2: 保存局検証・復元

- [x] 手書きの4局予定に完成2局・欠落1局・中断1局を与え、完成ID集合と実行対象ID集合を独立期待値とする。先頭/末尾の完成、片側だけ完成した組、ERROR、正常未決着も確認する。
- [x] 破損JSON・誤ハッシュ・予定外ID・違法手・不正終局を拒否し、古い/欠落summaryから復元するテストを作る。
- [x] 意図したRed確認後、既存検証の共通化と復元を最小実装しGreenを確認する。
- [x] 完成バッチreaderの従来テストを確認し、Refactor要否を点検する。

### タスク 3: 実行・排他・中断・集計

- [x] 逐次/4workerで、完成局の実行ゼロ・既存JSONバイト列保持・同seed使用・重複集計なし・再中断後の再開をテストする。
- [x] 二重起動拒否、例外時のロック解放、残存ロック拒否、全完了時の対局ゼロを確認する。
- [x] 保存失敗と原子的書込み前後の中断を代表点として選び、条件ハッシュ保持、時間欠落の表示を確認する。
- [x] Red確認後、実行器へ最小実装を接続してGreenを確認する。
- [x] 小規模な実対局で逐次・4workerの連続実行と中断後の再開結果を比較し、棋譜・終局・勝敗・分析得点・summary v3下限時間表示を検証する。実端末Ctrl-Cではなく欠落局を作って再開経路を確認し、Ctrl-C経路はテスト注入で検査した。
- [x] Refactor要否を点検し、結果順・保存局の不変性・逐次/並列の共有経路を確認した。追加分割は不要と判断。

### タスク 4: 検出力・検証・独立レビュー・記録

- [x] 隔離コピーへ「全予定を再投入」「条件照合を省略」「conditionsを再生成」「完成局を重複加算」を代表誤りとして注入し、対応アサーションの失敗と復元後成功を確認する。
- [x] Ruffのimport整理・format・check、差分確認後、`python3 scripts/run_tests_parallel.py` を実行する。共有状態や順序依存の疑いがあれば逐次実行を併用する。
- [x] Refactor変更の有無にかかわらず独立コードレビューを行い、Critical/Importantを解消して再検証・再レビューする。
- [x] 対象契約・代表ケース・検出対象・既存テストによる補完・未検証事項を学習記録へ残す。実端末Ctrl-C/強制終了で実施した範囲を区別する。
- [x] 文書・リンク・差分を確認し作業ブランチへコミットする。main統合は本人の承認後に行う。

#### Task 4 実績

- 独立レビュー初回はCritical 0 / Important 2 / Minor 1。逐次payload再構築、親SIGINTとFuture内例外の識別、lock assertion位置を修正した。新しい二つの割込み挙動テストは修正前Red・修正後Green。Future内KeyboardInterruptの対称ケースは既存分岐を保つため初回Greenとなり、親割込みと両側の挙動を確認した。
- 再レビューはCritical 0 / Important 0 / Minor 1。Future自身が保持するKeyboardInterruptを直接検査するケースを追加後、最終再確認でCritical 0 / Important 0 / Minor 0。
- 全体検証は `python3 scripts/run_tests_parallel.py` で851 tests / 56 modulesが成功。比較関連4モジュールは78 testsで成功。Ruff import整理・format・check・format確認、`git diff --check`、文書リンク確認も成功。
- 実端末からのSIGINT配送、複数回連続Ctrl-C、SIGKILL・停電、2,040組の実行と棋力評価は行っていない。計画記録時点では作業ブランチへのコミットまで完了し、main統合前だった。その後、2026-10-25に本人承認を受けてローカルmainへfast-forward統合し、統合先の全体851テスト・56モジュールが成功した。詳細は[C1学習記録](../learning/c1-rook-mobility-evaluation.md#c1比較cliのmain統合2026-10-25)を参照する。

## 限界と主線への帰還

停電・ディスク故障・外部からの同時ファイル改変への完全な耐性は証明しない。棋譜検証は合法性と記録整合性を確認し、各手が当時の方策で選ばれたことまで再探索して証明しない。強制終了で保存されなかった時間と対局途中の進行は復元できない。

再開機能は比較を継続するための補助である。実装・検証・統合後、本人が確認比較を実行し、結果からB1の強さを判断する。独立seed一覧生成と長時間比較はまだ行わない。
