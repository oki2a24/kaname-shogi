# 駒の連携評価を通常CLI・USIへ接続する設計案

## 状態

2026-10-31作成。brainstorming後、本人が設計全体を明示承認し、実装計画全体とネイティブ実行も承認した。実装・操作確認・最終検証・独立レビューまで完了し、現在は学習記録と知識メモの本人確認後の通常コミット待ち。実績と未検証事項は[学習記録](../learning/undefended-piece-coordination-evaluation.md)と[実装計画](2026-10-31-undefended-piece-normal-cli-usi-implementation-plan.md)に記す。

## 意図と背景

本人は、指定した5登録局面・比較条件で初めて改善が支持された駒の連携評価を、通常CLIとUSIから選べる候補として試したいと確認した。その後、通常CLIのコンピューター対コンピューター対局で先手・後手に異なる方式を選び、方式の差を見やすくしたいと希望した。

前段の比較は基準10M対候補10M+U、2035組・4070局で完了し、候補平均得点0.908845、95%区間[0.878739, 0.938951]だった。これは指定条件での改善支持であり、一般的な棋力向上の証明や既定採用の根拠ではない。詳細は[比較学習記録](../learning/undefended-piece-coordination-evaluation.md)と[比較設計](2026-10-30-undefended-piece-comparison-design.md)を参照する。

## 設計時点の変更前動作（2026-10-31）

この設計を作成する直前の通常CLIは、コンピューターが参加する対局で一度だけ一手選択方針を尋ね、その同じ方針をコンピューターの全手番へ渡していた。CVCでも先手・後手は同じ方針を使用。候補はランダム、一手駒得、二手先読み（駒得）、全幅読み（最大4手）、αβ枝刈り（最大4手）の5方式で、空入力はランダムだった。

USIはDifficultyのcombo optionで同じ5方式を通知していた。未設定時の値はRandomで、最初のgoで方式を局内固定し、setoptionで変えた値は次のusinewgame以降の局で有効。未知の値は無視して直前の有効設定を保っていた。

10M+U評価と一手選択方針は内部・比較CLIに実装済みだが、この時点では通常CLIの候補表とUSI Difficulty optionには未接続だった。既存のU重み0方式は比較専用であり、通常CLIの公開候補には加えない。

## 採用する方向

### 検討した案

| 案 | 扱い |
| --- | --- |
| CVCの両側へ一つの方式を適用する | 現行方式を保つが、本人が希望した先手・後手の方式差を見せられないため採用しない。 |
| CVCで先手・後手が別々に方式を選ぶ | 本人が選択。両側の方式を直接見比べられる。対象は現行の公開5方式と10M+Uに限る。 |
| 比較専用の内部方式も通常CLIへ公開する | 本人は選ばず、今回のテーマに自動追加しない。 |

### CLIでの選択

- 人間同士では方式を尋ねない。
- 人間対コンピューターでは、現在の担当どおりコンピューター側の方式を一度尋ねる。
- CVCでは同じ候補表を二度表示し、先手、次に後手の方式をそれぞれ選ぶ。
- 候補は現行の通常CLI 5方式に10M+Uを加えた6方式。比較専用の内部方式は含めない。

| 番号 | 表示名 | 内部方針 |
| ---: | --- | --- |
| 1 | ランダム | RANDOM |
| 2 | 一手駒得 | MATERIAL |
| 3 | 二手先読み（駒得） | TWO_PLY_MATERIAL |
| 4 | 全幅読み（最大4手） | FOUR_PLY_FULL_WIDTH |
| 5 | αβ枝刈り（最大4手） | FOUR_PLY_ALPHA_BETA |
| 6 | 一手駒得＋支えのない狙われた駒 | MATERIAL_UNDEFENDED_PIECE |

各側の空入力は独立にRandomを選ぶ。不正番号は再入力を求める。対局開始前に先手・後手それぞれの選択名を表示し、選択した方式と実際の着手方針の対応を確認できるようにする。CLIの各側の選択は一局中固定する。

### 評価とUSI

CLIの新候補は既存の10M+U評価を使う。Uは相手の利きがあり味方の支えがない盤上の駒の差であり、候補方式は一手評価と一手詰み優先を保つ。新方式に強さを保証する表現を付けない。

USIでは既存のDifficulty optionにMaterialUndefendedPieceを追加し、通常CLIと同じ10M+U候補へ対応づける。値の大小文字を区別せず、未知値は既存どおり無視する。USIエンジンの一つのプロセスでは一つのDifficultyを設定する。USIに先手・後手の二欄選択は追加しない。

### 既定値と設定寿命

- CLIでは従来どおり空入力の既定をRandomとする。CVCでは先手・後手それぞれに適用し、人間対コンピューターではコンピューター側に適用する。
- USIではDifficulty未設定時の既定Randomを維持する。10M+Uを暗黙の既定にはしない。
- CLIの方式は一局中固定し、次回のCLI起動時に再選択する。
- USIの設定値はエンジンプロセス中保持し、各局の方式は最初のgoからusinewgameまで固定する。局中のsetoptionは次局から反映する。

## 確認方法と検出範囲

### 自動テスト

振る舞いごとに契約・代表ケース・想定誤りを確認する。期待値は独立に定め、テスト件数や成功だけで十分性を主張しない。

| 契約 | 代表ケース | 検出したい誤り |
| --- | --- | --- |
| 番号が6方式へ対応する | 1〜6を個別に選択 | 番号と内部方針の対応違い、新候補の欠落・取り違え |
| 空入力はその側だけRandom | CVCで一方だけ空入力、両側空入力 | 一方の既定値が他方へ漏れる、新候補を既定にする |
| CVCでは先手・後手の方式を独立に使う | 異なる二方式を指定し、両側を一度ずつ探索。割当を入れ替えたケースも確認 | 先手・後手への割当逆転、両側への同一方針流用 |
| 対局形式ごとに必要な方式だけ尋ねる | 人間同士、人間対コンピューター、CVC | 不要な選択を求める、コンピューター側の選択漏れ |
| 表示が実際の割当と一致する | 二方式を選んだ後の開始前表示 | 表示名と内部方針が食い違う |
| USIが新値を通知・受付する | usi応答、MaterialUndefendedPiece設定後のgo | 通知漏れ、誤った内部方針への対応、大小混在の受付漏れ |
| USIの設定寿命を保つ | 局中変更、usinewgame後のgo、未知値 | 早すぎる設定変更、次局への反映漏れ、無効値による設定消去 |

TDDでは各振る舞いについて実装前の失敗理由を確認する。読み込みエラーだけをRed確認と扱わない。代表的な誤実装を隔離コピー等へ注入し、意図したassertion failureと復元後の成功を確認する。単独テストが検出する誤りと既存テスト全体が補う誤り、未検証範囲をレビューと学習記録に残す。

### 通常CLIでの操作確認

実装・計画の承認後、通常CLIでMaterial対10M+Uを先後入れ替えた2局実行する。開始局面と時計は通常CLIの既定条件を使い、開始前の両側表示、選択方針に応じた実着手、終局までの操作を確認する。2局の勝敗は操作例の観察として記録し、強さや一般的な棋力向上の証拠とは扱わない。これは長時間比較CLIの再実行ではない。通常CLIのMaterial方式は、新候補と同じ一手詰み優先の選択経路ではないため、この対戦はUだけの差を分離しない。Uの比較根拠は、同一経路で10Mと10M+Uを比べた前段の比較結果と区別する。

brainstorming中には既存CLIでRandom対RandomとMaterial対Materialの自己対局がそれぞれ終局した。TwoPlyMaterial対TwoPlyMaterialは約30秒でCtrl-C停止し、終局していない。いずれも両側が同じ方針の自己対局であり、方式差の比較ではない。操作出力は保存していない。
