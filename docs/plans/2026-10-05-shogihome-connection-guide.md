# ShogiHome接続手順書・リポジトリスキル 実施計画

> **AIエージェントへの指示:** REQUIRED SUB-SKILL: この計画をタスクごとに実装するには、`subagent-driven-development`（推奨）または `executing-plans` スキルを起動して使用してください。ステップには追跡用チェックボックス (`- [ ]`) を使用します。実装は本人の明示承認後に開始し、ドキュメントとスキルを独立レビューします。

**目標:** 人間が使えるShogiHome接続手順書と、Codexが接続依頼時に適用できるリポジトリスキルを整備する。

**アーキテクチャ:** 詳細な操作手順と根拠リンクは `docs/shogihome-connection-guide.md` に置く。`.agents/skills/shogihome-connection/SKILL.md` は発動条件・判断境界・停止条件を持ち、手順書を参照する。履歴資料は成果物の参照先にせず、歴史的観察を確認するための執筆時根拠としてのみ使う。

**技術スタック:** Markdown、Codex repository skills (`.agents/skills`)、Git。

**仕様 (Spec):** [2026-10-05-shogihome-connection-guide-design.md](2026-10-05-shogihome-connection-guide-design.md)

**グローバル制約 (Global Constraints):**
- 学習は一回一テーマで進める。
- 学習記録・知識メモは内容を確認してからGitにコミットする。
- 確認には公式情報などの一次資料を優先し、文書内に出典リンクを添える。
- 説明・学習記録・知識メモは日本語で書く。
- 実装計画を文書として作成・更新した後は、計画内容を提示して本人の明示的な承認を待つ。承認前にTDD、コード・テストの変更、実装の開始へ進まない。
- 実装後は、変更に見合う検証を行ってからコミットする。
- 設計・実装の文書は、記録に抜け漏れがなく、後から経緯を振り返れるようにする。
- 一テーマの実装・検証・レビュー・記録が揃った時点で、元の作業ディレクトリへの取り込み状況を確認する。必要な承認を得て取り込み、取り込み先で検証する。

## レビューフォーカス

- 接続対象や対局条件が依頼文から特定できないとき、開始前に確認し、推測で対局を始めない。
- KIFの対象手が曖昧、または盤面と選択手が一致しないとき、再開を止めて対象局面を確認する。
- ログ採取を依頼されていないとき、永続設定を変更せず通常手順を案内する。
- ログ設定を変更したとき、変更前の値を記録し、採取後に同じ値へ戻して再起動・復帰確認する。
- 対局終了ログの一例を全対局の必須通信として扱わず、`bestmove resign`、`gameover lose`、その後の別コマンド `quit` の関係を混同しない。
