# CLI比較テストの時計表示を決定的にする実装計画

> **AIエージェントへの指示:** REQUIRED SUB-SKILL: この計画を実施する前に `superpowerssuperpowers:executing-plans` スキルを使用し、各ステップのチェックボックスを更新する。

**目標:** 2件のCLIテストへ固定時計を注入し、実時間の揺れを除きながら棋譜・表示の比較を維持する。

**アーキテクチャ:** `tests/test_cli.py` の比較対象となる全4回の `cli.run_game(...)` に `now_ns=lambda: 0` を渡す。乱数・棋譜・出力の既存アサーションを残し、製品コードとテストランナーは変更しない。

**技術スタック:** Python 3.15、標準 `unittest`、Ruff 0.16.10。

**仕様 (Spec):** [テストの検出力と範囲の点検](../knowledge/test-coverage-review.md)、対象テストのdocstringとアサーション、および2026-10-21に本人が承認した「比較する各対局に同じ固定時計を渡す」方針。

## グローバル制約

- テストを削除せず、既存アサーションも弱めない。
- テスト名は英語、日本語docstringは確認する振る舞いと検出したい誤りを説明する。
- 変更範囲は対象テストと必要な記録に限り、製品コードと並列ランナーは変更しない。
- Ruffの固定版・既存フック設定を維持し、検査を回避しない。

## レビューフォーカス

1. 固定乱数種によるコンピュータの指し手と棋譜の一致を引き続き比較する。
2. 既定モードと明示した人間対コンピュータモードの棋譜・全出力の一致を引き続き比較する。
3. 比較する各対局へ同じ固定時計を設定し、片方だけ実時計が残る漏れを防ぐ。
4. 注入した時刻に基づく経過時間・残り時計・時間切れ境界は既存の時計制御テストで引き続き検出する。
5. 乱数やモードの誤りが時刻固定によって隠れないことを、既存の棋譜・出力アサーションで確認する。

## テスト範囲の判断

| 契約 | 代表ケースと独立期待値 | 検出対象 | 既存テストの補完 | 未検証 |
| --- | --- | --- | --- | --- |
| 固定乱数種の対局は同じ指し手・棋譜・表示を再現する | 同じseedで2局を実行し、`record.moves` と出力全体を比較 | 乱数生成器の扱いなどで指し手・表示が変わる誤り | 時刻の具体値は `test_cli_time_control.py` の固定経過テストが確認 | 実時計の進み方 |

今回の変更は比較テストの時計入力を固定するだけで、新しい振る舞いテストは追加しない。変更前には全件実行で1件の時間表示差を確認し、当該テストを同一プロセス内で100回実行して11回の失敗を観測済み。並列計測では別の出力比較テストにも同じ種類の差が現れた。

## 実施結果

### 変更

対象2テストの4回の `cli.run_game(...)` 呼び出しすべてに `now_ns=lambda: 0` を渡した。既存の棋譜比較・全出力比較、乱数種、対局入力、モード指定は変更していない。製品コード、テスト件数、テストランナーにも変更はない。固定時計により、この2つの比較テストでは探索にかかった実時間による表示差がなくなる。

### 環境と検証

- `scripts/setup_dev.py` は別worktreeでの実行を明示的に停止した。元cloneの固定済み `.venv` をworktreeの `.venv` として共有し、Ruff 0.16.10、Python 3.15.0、`core.hooksPath=.githooks` を確認した。
- 修正前100回実行では、`test_fixed_rng_reproduces_computer_move` が22回、`test_explicit_human_vs_computer_matches_default_mode` が6回失敗した。差は「消費時間」と「後手の残り持ち時間」の表示だけだった。
- 修正後は対象2テストを個別に実行して成功し、それぞれ100回の繰り返しも200/200成功した。
- 検出力を確認するため、隔離した実行時の変異として2回目の乱数種を変えたところ棋譜比較が失敗し、明示モードの動作を人間対人間へ変えたところも棋譜比較が失敗した。実ファイルは変更していない。
- `.venv/bin/ruff format .` は74ファイルを変更なしと報告し、`ruff check .` と `git diff --check` は成功した。
- 全体テストは、worktreeに仮想環境がない状態ではUSI起動テスト3件が実行環境パス不足で失敗した。worktreeから元cloneの仮想環境を参照した後に2回再実行し、623件すべて成功した（49.959秒、最終確認51.281秒）。

### 検出力・未検証範囲

- 契約と代表ケース: 同じ乱数種なら棋譜・表示が一致すること、既定モードと明示した人間対コンピュータモードなら同じ入力で棋譜・表示が一致することを、それぞれ比較する。
- 検出する誤り: 乱数種の扱いによる指し手差、既定値と明示モードの分岐差、棋譜や表示内容の差。修正後も棋譜と出力全体の比較を維持し、2種類の実行時変異で比較が失敗することを確認した。
- 既存テストによる補完: `tests/test_cli_time_control.py` は注入した時刻に基づく経過時間・残り時間の具体値・時間切れ境界を検証する。全体623件も成功した。
- 未検証: この2件自体ではシステム実時計の進み方や性能を測らない。今回の変更は比較テストの時計入力だけを固定する。

### Refactor

Refactorは不要と判断した。4箇所へ同じ固定時計を追加する以外に、共通化や抽象化で得られる利点はなく、変更範囲をそのまま保つ。
