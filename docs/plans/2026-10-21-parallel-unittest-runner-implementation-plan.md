> **承認:** 本人が2026-10-21に計画を承認。承認された範囲で実装・検証を進める。
> **AIエージェントへの指示:** `superpowerssuperpowers:executing-plans` を使用し、タスクごとにチェックボックスと実施結果を更新する。

**目標:** 既存623件のユニットテストを一つも削らず、追加依存なしで複数プロセスから実行する手段を用意する。現在の約50秒の逐次実行を短縮しながら、標準 `unittest` の逐次実行も残す。

**提案する構成:** `scripts/run_tests_parallel.py` が標準discovery相当の有効な `test*.py` とpackageを検出し、各モジュールを標準 `unittest` の別プロセスとして最大4個同時に実行する。package自身も対象に含め、`__init__.py` のテストやimport失敗を落とさない。worker起動時はtestsディレクトリをimport検索の先頭に置き、作業ディレクトリはリポジトリ直下に保つ。結果と失敗出力を集約し、標準ライブラリだけを使う。READMEに並列・逐次の両コマンドを載せる。

**技術スタック:** Python 3.14以上、標準 `unittest`、`subprocess`、`concurrent.futures`、Ruff 0.16.10。

**範囲:** テストランナー、ランナー専用テスト、READMEのテスト実行案内、文書索引、学習・実施記録。製品コード、CI、テストの意味や件数は変更しない。

## 事前調査と実測

- `README.md` の正式な全体テストは `python3 -m unittest discover -s tests -v`。`requirements-dev.txt` はRuffだけを固定し、pytest・pytest-xdist等は導入されていない。現在のPython 3.15.0の `unittest --help` に並列実行オプションはない。
- mainへの修正取り込み後、逐次全体テスト623件は49.689秒で成功した。別の全体プロファイル実行も623件成功し、実探索・プロセスを使う複数テストが実行時間の大部分を占めた。
- 計測専用の一時スクリプトで40個の `test_*.py` を各独立Pythonプロセスで実行した。4ワーカーで3回実行し、毎回623件すべて成功、所要時間は17.147秒、17.337秒、17.894秒だった。逐次実行の一回測定と比べて約2.8〜2.9倍、経過時間を約64〜65%短縮した。計測スクリプトやランナー変更はリポジトリに残していない。
- これは一台・一環境での予備計測で、他OSやCPU数で同じ速度になる保証ではない。モジュールごとの別プロセス化は、モジュール間に暗黙の共有状態がある場合に逐次実行と振る舞いが異なる可能性があるため、逐次コマンドを残して比較可能にする。

## グローバル制約

- テストを削除・skip・filterせず、すべての発見済みモジュールを一回ずつ実行する。
- 各ワーカーは標準 `unittest -v` を使い、日本語docstringを含む失敗情報を隠さない。
- 追加のパッケージを導入せず、標準 `unittest` の逐次コマンドをREADMEから削除しない。
- 実装前にランナーのテストを作成し、正の実行と失敗の伝播を検証する。読み込み失敗だけをRed確認と扱わない。
- Python変更はRuff import整理・format・check、差分確認、変更に見合う全体テスト、独立レビューを行う。Critical / Importantがあれば修正して再検証・再レビューする。
- 作業は `codex/parallel-unittest-runner` で行う。mainへの統合は完了後に別途本人の承認を得る。
