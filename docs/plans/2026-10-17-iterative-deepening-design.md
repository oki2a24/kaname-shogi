# 反復深化と開発用比較の設計

## 状態・目的

2026-10-17作成。同日の草案全体の確認依頼に本人が「yes」と回答し、補足境界条件を含む文書全体を承認した。[実装計画](2026-10-17-iterative-deepening-implementation-plan.md)は承認後に実行し、実装・検証・独立レビューを完了した。本人の別承認後、main統合と取り込み先検証を完了した。本文の「草案での補足」等は、個別対話から文書へ具体化した経緯を示す。本人回答と補足は[学習記録](../learning/iterative-deepening-design.md)を参照する。

反復深化の目的を説明できる小さな段階として、同じ開始局面で深さを増やし、最後に完了した結果を保持する。前回の最善手を開始局面で先に調べ、その効果と反復の追加費用を開発用に比較する。土台は[既存探索比較の設計](2026-10-17-engine-search-comparison-design.md)と[知識メモ](../knowledge/search-comparison.md)。性能改善自体を合格条件にしない。

- 選択したA案：完了結果の保持に、前回最善手を根で優先する処理を加える。
- 見送ったB案：完了結果の保持だけを行い、手順序変更を後回しにする。
- Random（最弱・既定）、一手駒得、現行二手先読みは選択肢に残す。
- 時間制御、通常対局・USIへの接続、実際の着手後の再利用、置換表、途中局面の手順序変更、評価改良は対象外。
- SOLID・DRYの希望に沿い、反復の段取り、指定深さ探索、比較入出力を分離する。再帰探索は既存の共有本体を使い、将来機能のためのクラス階層や汎用設定基盤は追加しない。

## 探索と完了の契約

1. 同じ開始局面から深さ1、2、…、上限の順にαβ探索する。仮想的な探索によって開始局面を実際に指し進めない。
2. 各深さの評価はその深さで求め直す。前回の評価を今回の評価として流用せず、前回の最善手だけを順序変更に使う。
3. 一つの深さが正常に完了したときだけ、深さ・探索結果・累計をまとめて公開する。正当なαβ枝刈りを伴う完了も完了である。
4. 最新結果は評価の大きさではなく完了深さで更新する。探索途中の候補・境界値では上書きしない。
5. 開始局面に合法手がなければ深さ1の結果を一件返して終了する。詰みは負け、その他の手なしは駒得という既存評価を維持する。
6. 同点では実際に探索した順序で最初の最善手を残す。優先順序により全幅や前回と別の同点手になってよい。
7. 各回の訪問回数は開始局面も含む既存の定義を維持する。累計は完了した反復の訪問回数の和で、確認用探索や中断した反復の訪問を含めない。

## 公開するデータと操作

英語名の意味：`SearchResult`は一つの指定深さの探索結果というデータ、`IterationResult`は反復の一回の完了記録というデータ。`search`は探索を行う操作、`preferred_move`は優先する指し手という入力データである。

### 完了記録

`result.py`にイミュータブルな`IterationResult`を置く。以下のフィールド名は草案での具体化案。

| フィールド | 意味 |
| --- | --- |
| `depth: int` | 完了した深さ |
| `result: SearchResult[M]` | 今回αβが返した既存の結果オブジェクト |
| `total_visited_nodes: int` | 完了した深さまでの累計訪問回数 |

既存`SearchResult`と同様に`frozen=True`とする。各深さで探索結果と外側の完了記録を新規作成し、最新を指す参照だけを切り替える。外側は今回の結果をコピーせず内包する。過去の記録は変更しない。

`frozen=True`は入れ子の値を自動凍結しない。既存の将棋用`BoardMove`・`DropMove`もfrozenデータである。汎用の手型`M`については呼出し側も値を変更しないことを前提にし、任意型の深いコピー・凍結は行わない。

### 反復深化の入口

`iterative_deepening.search(node, max_depth, operations)`が、`IterationResult`を順に返すイテレーターを返す。`node`は開始局面のデータ、`operations`は既存の局面調査・遷移・評価の操作セット。

- `max_depth`はboolを除く1以上の整数。不正値は呼出し時点で`ValueError`とする。
- 実際の局面調査・探索は、最初の結果を要求してから始める。呼出し時の検査と、内部のジェネレーターによる反復を分ける。
- 次の結果を要求すると一つの深さを探索し、完了記録を渡して待つ。裏で次の深さを並行探索しない。
- 前回最善手・累計はこの反復処理が保持する。入力局面を変更せず、操作の例外は原因を保って伝える。
- 手なしまたは上限完了後は終了し、Ctrl+C後の探索再開は保証しない。
- `yield`の箇所に、Pythonのジェネレーターによる状態保持であることと、他言語では状態を明示するIteratorなどで同じ役割を実現できる旨の日本語注意コメントを付ける。

### αβの優先手

既存`alpha_beta.search`へキーワード引数`preferred_move=None`を追加する。既存呼出しはそのまま使える。

- 未指定なら従来順序。指定時は根の手を照合し、その手だけを先頭へ移す。他候補の相対順を保ち、入力の手一覧を変更しない。
- 例：元A→B→C→D、優先CならC→A→B→D。次回優先Bなら元の順序を基準にB→A→C→D。
- 子局面は従来順序。前回手以外を候補から除外しない。
- 指定手が根の合法手にない場合は`ValueError`。根を調査・照合してから、子局面へ進む前に検出する。調査の二重実行を避ける。
- 共有再帰本体`core.search`へ根の優先指定を伝える。全幅の公開入口は変更しない。

草案で補足する境界条件：既存αβの深さ0は維持する。優先指定があれば深さ0でも根の手一覧と照合し、合法でも着手を選ばず従来の深さ0評価を返す。手なし局面への非None指定は不正とする。`None`は指定なし専用で、手の値として使わない。

## ファイルと依存関係

すべて`kaname_shogi/search/`内。

| ファイル | 責務 |
| --- | --- |
| `iterative_deepening.py`（新規） | 深さ反復、前回最善手、完了記録、累計。既存αβと結果データに依存 |
| `result.py` | 既存結果と新しい完了記録のデータ定義 |
| `alpha_beta.py`・`core.py` | 優先手を受け取り、共有の指定深さ探索で根だけ並べ替える |
| `comparison.py`（新規） | SFEN入力の共通処理、指し手・評価の整形、結果一致判定 |
| `compare_iterative.py`（新規） | 新コマンドの探索順、出力、中断状態、終了コード |
| `compare.py` | 既存の深さ2・3・4の比較動作を維持し、共通処理を利用 |

探索本体は比較モジュールや標準出力へ依存しない。共通化は現に共用する処理に限り、方式ごとに異なる実行ループや中断状態まで抽象化しない。既存テストが参照する`compare.format_move`・`compare.results_match`は、共通定義のインポートで参照を維持する案。共通ヘルパーの細かな引数は実装計画で具体化する。

## 開発用コマンド

未実装の呼出形式：

```sh
.venv/bin/python -m kaname_shogi.search.compare_iterative --sfen "8k/9/9/9/9/9/9/9/K8 b - 1"
```

上限4を一か所で管理し反復処理へ渡す。現在は深さ指定オプションを追加しないが、将来その入力を接続しやすくする。

各深さの実行順は、反復深化の完了記録を受け取って即座に保持 → 同じ根・深さの全幅探索 → 元の手順序による単独αβ → 比較・表示 → 次の反復結果を要求、の順。

表示内容：入力SFEN・開始側視点、深さ、反復深化の評価・選択手（USIと日本語）、全幅との評価一致・最善候補所属、単独αβの訪問回数・反復今回分・反復累計。累計には「完了した深さまで」と明記する。完了行は逐次表示する。

反復深化と全幅の評価が等しく、反復深化の手が全幅の最善候補集合に含まれれば一致。手なしは既存の一致判定に従う。単独αβは訪問回数の比較基準で、既存の正しさ検証も回帰確認に使う。訪問回数削減は一致条件ではない。

不一致でも残りの深さを続け、最後に失敗を返す。開始局面の手なしでは深さ1の比較を行って終了し、全4深さを実行したように表示しない。

### 中断とエラー

- 反復探索途中のCtrl+C：作業中の深さは未完了、最後の反復完了結果を表示する。深さ1完了前なら「完了結果なし」。
- 確認用全幅または単独αβ途中のCtrl+C：反復の完了深さと、その深さの比較未完了を分けて表示する。保持済み反復結果は失わない。
- 未完了反復の訪問数を回収せず、累計は実際に費やした全作業量ではないと分かる表示にする。
- 中断位置と直近の比較完了深さも管理し、探索完了と比較完了を混同しない。

| 終了コード | 条件 |
| --- | --- |
| 0 | 実行対象の比較がすべて一致。手なし終了・ヘルプも含む |
| 1 | 比較不一致があり、通常の比較処理を終えた |
| 2 | SFENやコマンド引数の入力誤り |
| 130 | Ctrl+Cによる中断 |

草案での補足：不一致の後に中断した場合は130を優先し、既に出した不一致表示は残す。内部の予期しない故障は入力誤りへ変換せず例外を伝える。比較コマンドはSFEN変換の範囲だけ入力の`ValueError`を扱い、探索全体を一括捕捉しない。固定上限・内部優先手の不正も内部故障として表に出す。

## 確認方法と検出対象

以下は設計上の確認方針。テスト作成・実行・誤り注入はまだ行っていない。[検出力点検方針](../knowledge/test-coverage-review.md)に従い、具体的なテスト配置・実行順・代表的な誤り注入は実装計画で提示する。

| 契約 | 代表例・期待値の根拠 | 検出したい誤り |
| --- | --- | --- |
| 深さで最善手を更新 | 手計算：深さ1 A=5/B=3、深さ2 Aの応手1/−2、Bの応手2/1。深さ1 A=5、深さ2 B=1 | 前回の手・高い浅い評価を固定、相手手番をmaxにする |
| 根だけ順序変更 | A/B/C/Dに優先C、次回優先B。子のX/Y/Zは不変。呼出し履歴を観察 | 他候補除外、残りの順序変更、子への優先伝播、元データ変更 |
| 同点と境界 | 真の同点、境界同値で打ち切る枝、max/min両側、枝刈りなしの木 | 境界値を新しい最善手として上書き、厳密同点の扱い変更 |
| 完了記録と累計 | 手計算の上記木で深さ1は3訪問、深さ2は7訪問、累計10（全枝が調査される順序）。過去記録を保持 | 累計を今回分で置換、確認用探索の加算、過去記録の書換え |
| 結果の遅延取得 | 呼出し時は探索なし、最初の取得で深さ1だけ、次で深さ2 | 上限まで先に計算、入力エラー通知の遅延 |
| 入力境界 | 上限1・4、0・負数・小数・bool、合法優先手の先頭/中間/末尾、不在手、深さ0 | 境界検査漏れ、未指定の回帰、不要な子探索 |
| 中断と比較順 | 深さ1途中、深さ3途中、反復完了後の全幅/単独αβ途中に中断を模擬 | 未完了を完了表示、最後の結果消失、比較未完了を成功扱い |
| コマンド | 各深さ一致、不一致後も継続、入力不正、内部例外、手なし、実プロセス入口 | 終了コード混同、内部エラー隠蔽、累計ラベルや表示欠落 |
| 将棋への接続 | 玉だけ・駒取り・成り・打ち・詰み・手なし、開始側先後、元局面不変 | 接続・視点・評価・終端の回帰 |

同じ再帰本体を使う全幅とαβが同時に誤る可能性があるため、全幅との比較だけでなく手計算木を独立した根拠にする。既存のminimax/alpha_beta/shogi/compareテストは基礎契約を補完するが、優先手・反復累計・新コマンドの状態遷移は新しい確認が必要。

訪問数の改善例・悪化例の実測は実装後の観察とする。OSからの実際のSIGINT配送、全局面への正しさ・速度、棋力、履歴による終局、通常対局への接続はこの確認で証明しない。

## 一次資料の事実と設計判断

2026-10-17の対話で確認した資料：

- [Python公式のジェネレーター](https://docs.python.org/3/tutorial/classes.html#generators)：`yield`で値を渡し、次の要求でローカル状態を保って再開する。これを完了記録の受け渡しに使うのは本プロジェクトの判断。
- [Rust公式Iterator](https://doc.rust-lang.org/std/iter/trait.Iterator.html)：独自型に`next`操作を実装できる。深さ・前回手・累計を明示保持して同じ役割を作れると判断した。言語移行や速度向上を今回保証するものではない。
- [Rust公式の実験的コルーチン](https://doc.rust-lang.org/beta/unstable-book/language-features/coroutines.html)：確認時点で実験的機能として説明される。今回の移植可能性はこの機能に依存しない。
- [Stockfish公式探索実装](https://github.com/official-stockfish/Stockfish/blob/master/src/search.cpp)：深さを増やす実装例を参照した。時間制御や強さ・効率の特性を本プロジェクトへそのまま当てはめない。
