# 支えのない被攻撃駒の価値を比較CLIへ接続して比較する：設計案

## 状態と目的

2026-11-02作成。本人は比較指標の範囲として「組得点＋固定局面の作用確認」を選択し、worker 4で実施するよう依頼した。同日、本設計案と実施計画案に沿った比較CLI接続・検証・pilot・独立confirmation・分析を進める指示を受けた。main統合とpushは対象外で、それぞれ別途承認を待つ。

目的は、既存の駒得・駒脅威評価でU（支えのない被攻撃駒の枚数差）を使う方式と、Uを参考価値の合計差へ置き換える方式を、比較CLIの同じ一手選択経路で比べること。対象は評価項目の置換による指定局面群での対局得点差であり、一般局面の棋力を証明することではない。

従来方式は **10 × M（駒得）+ U（支えのない被攻撃駒の枚数差）+ V（支えあり低価値駒脅威の枚数差）**。候補方式は **10 × M（駒得）+ 1 × 支えのない被攻撃駒の価値合計差 + V（支えあり低価値駒脅威の枚数差）**。Mは視点側の駒価値合計−相手側、U・Vは相手側の対象枚数−視点側の対象枚数、価値合計差も相手側の危険価値−視点側の危険価値である。いずれも正の通常点を視点側有利とする。

## 既存評価との関係と改善仮説

- M（駒得）は実際に盤上・持ち駒へ現れた価値差を表す。新しい価値合計差は、まだ取られていない支えのない被攻撃駒の危険を表す。取られる前後では両方の項が動くので、危険度を実際の損失額や合法な交換損得とはみなさない。参考価値合計に係数1を置き、Mの係数10より小さく扱う設計も棋力上の適正を保証しない。
- V（支えあり低価値駒脅威の枚数差）は、支えのある対象駒がより低価値の相手駒に狙われる状態を数える。新しい項は支えのない対象を数えるため、一つの局面で対象条件は重ならない。ただし支えの変化でU対象からV対象へ移る場合がある。比較両側でVの定義・係数1を固定し、その相互作用を代表ケースで確認する。
- 改善仮説は「枚数が同じでも高価値駒の危険を大きく扱うことで、等しい一枚数だけを見る方式より危険な選択を避け、登録局面群の候補側組得点が上がる」。この仮説は外れる可能性を含む。危険駒の捕獲回数などを比較結果へ新たに集計せず、既存分析CLIの組得点を主判定にする。固定局面での点数と選択手は作用確認に使う。

## 手法の比較と採用案

| 案 | 比較 | 評価 |
| --- | --- | --- |
| 旧統合評価と新統合評価を直接比較 | 10M+U+V 対 10M+価値合計差+V | 今回知りたいUの置換を直接測れる。M・V、一手選択、詰み優先をそろえられるため採用する。 |
| 価値合計差の係数0対1 | 10M+V 対 10M+価値合計差+V | 新項を足す効果は測れるが、既存U方式から置き換える効果を答えないため採用しない。 |
| 通常CLI/USIの既存方式と新候補を対局比較 | 経路・時計・一手詰み優先などを含む方式全体 | U置換以外の差が混ざるため採用しない。通常CLI・USIへの新候補公開も今回の対象外。 |

## 接続範囲

比較CLIだけに新方式を追加する。旧方式は既存識別子の material-piece-threat-v1 を使い、重みを PieceThreatWeights(material=10, undefended=1, supported_threat=1) とする。新方式の識別子案は material-piece-threat-value-v1、重みは PieceThreatValueWeights(material=10, undefended_value=1, supported_threat=1) とする。後者の条件JSONでは旧Uと混同しないキー undefended_value を保存し、両方式とも mate_priority=true とする。

二方式とも比較CLIの既存一手選択器を通し、一手詰みを通常点より優先する。新方式は evaluate_material_piece_threat_value（M・支えのない被攻撃駒の価値合計差・Vを合成する読み取り操作）へ委譲する。MoveSelectionPolicyの新しい値は比較用の選択方式を表すデータである。通常CLIとUSIの方式選択肢、旧方式の挙動、既存の条件・局・summary・analysis形式を保つ。新しい方式名・実効重みは条件、保存結果、読込検証、summary計時へ一貫して残す。

## 独立期待値と代表局面

期待値は製品評価や比較CLIの出力から作らない。既存の確定値表は参考価値の入力に限り、局面ごとのM/U/価値合計差/Vと合成点は手計算しテストへ固定する。

既存の合成テストA〜Eは引き続き式の独立検算に使う。特にAは従来点99、候補点85、Bは99/99、Cは179/179、Dは308/294、Eは20/13であり、Uの二重加算・符号誤り・Vの脱落を検出する。これは対局比較の開始局面群とは別の式検査である。既知の「支えのない銀一枚（価値8）対支えのない歩二枚（価値合計2）」では、他項を固定すると枚数差は+1でも価値合計差は−6になる。これを旧Uと新項の順位逆転を説明する手計算例にする。

比較policyの選択接続では、前テーマの固定合法候補例を独立値で再確認する。従来点は支える手・支えない手とも230で同点、新点は230対216で支える手を選ぶ。これは二候補間の作用確認に限り、全合法手の最善性や棋力の証明にはしない。

対局比較には既存U比較の5局面、V比較の6局面、C2局面、合成テストA〜Eを流用せず、新しい7局面セットを作る。各局面は初期局面からの合法なUSI指し手列で再現し、先後・材料・対象の価値・支え・Vを手計算した表を設計・学習記録へ残す。新セット内での一意性に加え、旧U・V pilot/confirmation・C2の追跡済み開始SFENとの非重複もテストで固定する。

| 局面の役割 | 見る内容 |
| --- | --- |
| 無対象の対照 | 先後の端香を一手ずつ進めた独立局面を使い、M・U・価値合計差・Vが0で候補差が生じないこと。標準初期局面は旧U・C2セットにも含まれるため再利用しない。 |
| 低価値対象と高価値対象 | 対象枚数が同じでも参考価値合計差が異なること。 |
| 両側の同数・異価値 | 旧Uが同点でも価値合計差がゼロでないこと。 |
| 枚数と価値の順位逆転 | 銀一枚と歩二枚のように、Uと価値合計差で符号が逆転すること。 |
| 両側複数対象 | 各側の価値を一枚ずつ加算し、視点反転で符号が反転すること。 |
| Vだけが働く対照 | 固定評価は既存のV実装単体テストで確認し、比較開始局面は追加しない。7局面群にはU/V混在局面を含め、以前のV比較局面・条件・seedを流用しない。 |
| UとVの混在 | 支えのない対象だけを価値合計へ、支えあり対象だけをVへ反映すること。 |

比較開始局面は、無対象、低価値対象、高価値対象、両側の同数・異価値、枚数と価値の順位逆転、両側複数対象、U/V混在の7局面とする。Vだけが働く対照は既存の固定評価テストで確認し、対局開始局面としては追加しない。各開始局面の対象値は手書きの独立期待値と照合し、同じ局面を重複登録しない。開始側を先後で均等化し、同一局面は方式の先後交換一組で評価する。局面群はこの7局面の等重み分布であり、一般的な実戦局面を代表する標本とは扱わない。

## 比較・判定方法案

pilotは7局面各2組、計14組・28局、1局512手上限、worker 4を提案する。新規の pilot seed一覧を使い、接続、保存、分析、処理時間、上限未決着の有無を確認する。pilotの得点は確認比較に合算せず、改善・悪化の判定に使わない。

独立confirmationは別の confirmation seed一覧を用い、各局面291組、合計2037組・4074局、1局512手上限、worker 4を提案する。組ごとに同一局面で先後を交換した二局を行い、各局で同一方式のseedを保つ。候補の組得点は勝ち1、負け0、通常千日手0.5の二局平均とする。手数上限の未決着や双方連続王手の未裁定は既存分析CLIどおり区間の上下限0〜1に残す。

主判定は候補側の平均組得点と互角境界0.5の比較である。95% Hoeffding区間の下端が0.5を超えればこの固定条件で改善を支持、上端が0.5を下回れば悪化を支持、それ以外は判断不能とする。計画上の検出目標を55%（互角境界から5ポイント）・検出力80%と置くと、既存分析CLIの区間式と独立組の仮定から必要数は n > (√ln(40)+√ln(5))²/(2×0.05²) = 2034.304... 組となる。7局面を等配分できる最小値として7×291=2037組を計画する。これは統計上の計画仮定で、必要最小数・効果保証・一般棋力の保証ではない。

局面、種、組数、上限、worker、出力先を事前に固定し、pilotとconfirmationは独立させる。比較・分析CLIの既存保存・再開契約を使う。ここに示す組数と上限は新テーマの提案値で、過去のU/V比較条件のコピーではない。実行時間は未測定で、pilotが予測を保証しない。
