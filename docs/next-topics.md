# 手番と所有者の照合後：次のテーマ候補

更新日：2026-09-22。第23回「手番に合う駒だけを移動できること」の学習・実装・理解確認まで完了した現在地から整理した。候補の順序は固定せず、各テーマの学習・設計合意後に見直す。

## 現在地

- 玉・歩・金・銀・桂・香・飛車・角について、盤面から移動先候補を計算できる。
- `apply_move` は、手番と出発駒の所有者が一致する場合だけ、空いている到着マスへ駒を動かし、手番を交代する。
- ただし、出発駒の動き方や候補生成結果を照合しないため、手番に合う駒を任意の空マスへ移動できる。

## 候補の比較

| 候補 | 学ぶ内容・最小範囲 | 規模 | 前提・留意点 |
| --- | --- | --- | --- |
| 移動先候補に合う空マスへだけ移動できること | `apply_move` が出発駒の候補に含まれる空マスだけへ移動を適用し、候補外は局面を変えず拒否する | 中 | 既存の候補生成を移動適用へつなぐ。相手駒の候補マスへの駒取りは扱わない |
| 駒取りと持ち駒の基礎 | 相手駒を取って所有者を変え、持ち駒として局面へ保持する | 大 | 局面の状態表現を広げ、駒取りと持ち駒を分けずに扱う必要がある |
| 成り・不成の基礎 | 敵陣、成りを選ぶ条件、成った駒の表現 | 大 | `Piece` の状態表現と移動適用の設計を見直す |
| 王手と合法手判定 | 玉が取られる状態、王手放置の禁止、候補手と合法手の区別 | 大 | 駒の移動適用・玉の扱い・盤面の仮適用が必要になる |
| CLIでの指し手入力と対局進行 | 筋・段を入力し、局面の表示と一手の適用を繰り返す | 中〜大 | 指し手の検証範囲と終局条件を先に限定する必要がある |
| 評価・探索、USI/SFEN | 局面評価、探索、外部GUIとの接続 | 大 | 一貫した対局進行と局面表現の後に扱う |

## 採用した次テーマ

次回は「移動先候補に合う空マスへだけ移動できること」を扱う。現在の `apply_move` に最も近い未実装範囲であり、既に学習した各駒の候補生成を使って、任意の空マスへ移動できる穴を一つだけ埋められるためである。

初回の範囲は、手番と所有者が一致する駒について、既存の候補に含まれる空マスだけを移動できることに限る。候補に含まれる相手駒のマスへの駒取り、持ち駒、成り、王手、合法手の確定は別テーマにする。

## 全体ロードマップとの対応

プロジェクトの方向性で示した「CLIで動く最小の対局プログラム」へ向け、まず候補生成、手番・所有者照合、移動方向の照合、駒取りと持ち駒、成り、王手を含む合法手、CLIの反復進行を小さく積み上げる。その後に評価・探索、USI/SFEN、GUI対局へ進む。
