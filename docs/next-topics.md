# 合法手列挙と弱い一手選択の後：次のテーマ

更新日：2026-09-26。第38回「弱い自動指し手のための合法手列挙と一手選択」は、実装・検証・独立レビュー・main取り込み・最後の理解確認まで完了した。

## 現在地

- `BoardMove`、`DropMove`、`Move` は、局面を変更しない中立な一手データである。
- `legal_moves(position)` は、既存の `apply_move` / `apply_drop` を複製局面へ試し、現在実装済みの規則で指せる全手を固定順のタプルで返す。
- `choose_weak_move(moves, rng)` は、その一覧から注入された `random.Random` で一様に一手を選ぶ。空一覧なら `None` を返すが、終局・投了・勝敗を判断しない。
- CLIは依然として先手・後手とも人が入力する。人間対コンピュータの手番、表示、終局の進行は未実装である。
- 独立レビューはCritical・Important 0件だった。Minorとして、駒打ちの種類順を列挙型の宣言順に暗黙依存している点と、その順序テストを拡張できる点を申し送っている。
- SFEN、USI、評価、探索、千日手、持将棋、入玉、時間切れ、反則勝敗は未実装である。

## 次の候補

| 候補 | 学ぶ内容・最小範囲 | 規模 | 前提・留意点 |
| --- | --- | --- | --- |
| 人間対コンピュータのCLI進行 | 人の入力と弱い自動指し手を、決めた手番で交互に対局ループへ接続する | 中 | 第38回の `legal_moves` と `choose_weak_move` を使う。乱数生成器の寿命、表示時機、`None` と終局判定の役割を設計する。 |
| 駒打ち順の保守改善 | 駒種順を明示定数にし、全駒種・端のマスを確認するテストを加える | 小 | 第38回レビューのMinorを解消する。機能は増えない。 |
| SFENの局面変換 | `Position` を標準的な局面文字列へ変換し、文字列から局面へ戻す | 中 | 盤面・手番・持ち駒・手数の表現を一次資料と仕様で確認する。CLIの対局機能には直結しない。 |
| CLIでの明示的な保存・読込 | `save <path>` / `load <path>` で対局を中断・再開する | 中 | 入力形式、読込後の表示、失敗時の再入力、終局状態を決める必要がある。 |

## 推薦

第1候補は「人間対コンピュータのCLI進行」である。今回できた合法手一覧と弱い選択器をそのまま使い、最初の目標である「弱くても対局できるCLI」へ進めるためである。

ただし、レビューMinorを先に小さく解消してからCLIへ進める選択もある。順序を公開契約としてより明示的に保守したい場合はこちらを選べる。

## 第38回の理解確認後

最後の理解確認では、本人が「今回は合法手からランダムで選ぶだけなので不要な `Position` は受け取らない。将来強い将棋エンジンや他の将棋エンジンに切り替える場合は必要になる可能性が大きい」と回答した。選択器を抽選だけに限定し、評価・探索・外部エンジン接続は必要になった時点で別のインターフェースとして設計できることを確認した。

次テーマを選んで新しいセッションで進める場合は、引き継ぎ文書と `docs/resume.md` を更新してコミットしてから開始する。
