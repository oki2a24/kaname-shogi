# 空マスへの移動適用後：次のテーマ候補

2026-09-21に、空マスへの移動適用までの実装と振り返りを確認して更新した。以下はアシスタントの提案であり、実装の合意や固定された開発順序ではない。規模は現在地との相対的な目安。

## 候補の比較

| 候補 | 学ぶ内容・最小範囲 | 規模 | 今選ぶ利点・留意点 |
| --- | --- | --- | --- |
| 玉の移動先候補 | 周囲8方向へ1マス。先後で移動方向の集合が変わらない | 小 | 先後反転を使わない駒を学べる。ただし王手・合法手は別テーマ |
| 空マスへの移動の適用 | 出発・到着の組を表し、出発点を空にして到着点へ駒を置く | 中〜大 | 候補生成から盤面変更へ進める。まず駒取りや手番更新を含めず、失敗時に盤を壊さない設計を学ぶ |
| 成りの基礎 | 敵陣、成り・不成、成った駒の表現 | 中〜大 | 既存の候補生成に関係するが、状態表現の設計が必要。移動適用の後が望ましい |
| 合法手判定の基礎 | 王手、王手放置、候補手と合法手の違い | 大 | 将棋プログラムの重要な段階だが、盤面変更・王の扱いを先に整理する必要がある |
| 手番更新 | 移動後の先手・後手の交代、BoardとPositionの責務 | 小 | 今回の移動適用の次に学ぶ内容として小さく分けやすい |

## 推奨

次の一回は「手番更新」を推奨する。今回追加した `move_piece` は盤面だけを変更し、`Position.side_to_move` は変更しない設計であるため、盤面と手番の責務を分けたまま、移動後に手番を交代する処理を小さく学べる。移動の成功時だけ手番を更新し、不正入力時は盤面と手番の両方を変更しない範囲から始める。

その後は、駒取り、持ち駒、成り、CLIでの指し手入力、合法手判定、不変な盤面・局面、評価・探索の順が候補になる。候補生成、盤面変更、手番更新、駒の状態変更を一つのテーマに詰め込まず、責務を分けて学ぶ。

次回の導入では、既存の `Position`、`Board`、`move_piece` を実際に読みながら、盤面と手番の違い、成功時と失敗時の状態変化を説明する。その後に手番更新の学習へ進む。確認問題は一問ずつ出し、本人の回答を待つ。

成り、駒取りと持ち駒、王手と合法手、探索も将来の候補だが、状態表現や複数の規則にまたがるため、今の小さな候補生成の次に一括実装することは勧めない。
