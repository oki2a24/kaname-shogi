# 第40回「駒打ち順の保守改善」の後：次のテーマ

更新日：2026-09-26。第40回「駒打ち順の保守改善」は、設計合意、TDD、独立レビュー、全検証、main取り込み、最後の理解確認まで完了した。

## 現在地

- `python3 -m kaname_shogi` は、人間が先手、コンピュータが後手を担当する。
- 人間の成功手の後、コンピュータは `legal_moves` と `choose_weak_move` を使って一手を選び、表示後に `GameRecord` へ記録・適用する。
- 乱数生成器は一局につき一つ。`run_game(rng=...)` で注入すれば、同じ乱数種の進行を再現できる。
- `choose_weak_move` の `None` は終局ではない。詰みは `is_game_over` で判定し、詰みでない合法手空一覧は勝敗なしの異常として終了する。
- `legal_moves` の駒打ち順は、飛・角・金・銀・桂・香・歩で固定する。`BasicPieceType` の宣言順には依存せず、固定種の乱数選択を再現可能にする公開API契約として `movegen.py` の非公開定数で表す。
- 人間対人間・コンピュータ対コンピュータへの切替、評価・探索、USI、SFEN、千日手、持将棋、入玉、時間切れ、反則勝敗は未実装である。

## 次の候補

| 候補 | 学ぶ内容・最小範囲 | 規模 | 前提・留意点 |
| --- | --- | --- | --- |
| 対局モードの選択 | 人間対人間・人間対コンピュータを明示的に選ぶ最小のCLI設定を設計する | 中 | コンピュータ対コンピュータを先取りせず、担当者と入力・自動手の責務を保つ。 |
| CLIでの明示的な保存・読込 | `save <path>` / `load <path>` で対局を中断・再開する | 中 | 入力形式、読込後の表示、失敗時の再入力、終局状態を決める必要がある。 |
| SFENの局面変換 | `Position` を標準的な局面文字列へ変換し、文字列から局面へ戻す | 中 | 盤面・手番・持ち駒・手数の表現を一次資料と仕様で確認する。 |

## 推薦

第1候補は「対局モードの選択」である。すでに人間対コンピュータの責務境界があるため、人間対人間への切替を最小範囲で追加できる。評価・探索・コンピュータ対コンピュータは先取りしない。
