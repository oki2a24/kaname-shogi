# 棋譜・局面のファイル保存の後：次のテーマ候補

更新日：2026-09-24。第37回「棋譜・局面のファイル保存」は実装・検証・独立レビュー・main取り込み・最後の理解確認まで完了した。

## 現在地

- GameRecord は開始局面、成功した move / drop の履歴、現在局面を保持し、position_at で任意手数の局面を再現する。
- GameRecord.save(path) は開始局面と成功手を kaname-shogi-game-record-v1 のJSONへ保存する。現在局面は保存しない。
- GameRecord.load(path) はJSONの構造・値を検証して新しい記録を作り、既存の apply_move / apply_drop で履歴を再適用する。不正内容・不合法な履歴は ValueError、ファイル入出力失敗は OSError とする。
- CLIは run_game の終了時に GameRecord を返すが、自動保存や対局中の save / load コマンドは持たない。
- SFEN、USI、時間記録、千日手、持将棋、入玉、時間切れ、反則勝敗、評価、探索は未実装である。

## 次の候補

| 候補 | 学ぶ内容・最小範囲 | 規模 | 前提・留意点 |
| --- | --- | --- | --- |
| SFENの局面変換 | Position を標準的な局面文字列へ変換し、文字列から局面へ戻す | 中 | 盤面・手番・持ち駒・手数の表現を一次資料と仕様で確認する。JSON保存とは別形式として扱う。 |
| CLIでの明示的な保存・読込 | save <path> / load <path> により対局を中断・再開する | 中 | 入力形式、読込後の盤面表示、失敗時の同じ手番での再入力、終局状態を決める必要がある。 |
| USIの position | GUI・USIクライアントから局面や手順を渡せるようにする | 大 | SFENとUSIの通信仕様を同時に扱うため、上記より範囲が広い。 |

## 推薦

次は **SFENの局面変換** を推薦する。今回のJSON保存で、開始局面・盤上駒・持ち駒・手番を明示的に保存する経験を得たため、同じ局面情報を外部標準の文字列へ対応付ける学びにつなげやすい。CLIの保存・読込は便利だが、対局ループの中断・再開という別の責務が増えるため、その後の候補にする。

## 第37回の理解確認後

最後の理解確認では、本人が「開始局面と成功手があれば現在局面は作れるから」と回答した。開始局面と成功手の履歴を既存規則で再適用することで、現在局面の二重保存を避け、不合法な履歴も読込時に検出できることを確認した。

本人が次テーマを選ぶまで、新しい学習・実装は開始しない。新しいセッションで進める場合は、選定後に引き継ぎ文書と docs/resume.md を更新してコミットしてから開始する。
