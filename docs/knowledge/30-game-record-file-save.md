# 棋譜・局面のファイル保存：参照メモ

更新日：2026-09-27

## 一次資料

日本将棋連盟の対局規則第12条は、公式棋戦で記録係または自動記録による採譜を行い、棋譜と時間を正確に記録すると定める。棋譜利用のガイドラインは、指し手進行を再現した盤面図と指し手順の文字情報を棋譜と説明する。

出典：[日本将棋連盟「対局規則」](https://www.shogi.or.jp/match/taikyoku_rules/)、[日本将棋連盟「棋譜利用のガイドライン」](https://www.shogi.or.jp/kifuguideline/)

## 保存形式

- 形式識別子は `kaname-shogi-game-record-v1`。
- JSONには開始局面（盤上の駒、双方の持ち駒、手番）と、成功した `move` / `drop` の履歴だけを保存する。
- 現在局面は保存せず、読込時に開始局面へ履歴を再適用する。
- 駒種・所有者・手番は固定文字列で表し、`Enum.auto()` の内部整数やSFENを使わない。
- CLIは自動保存しないが、人間担当の手番で `save <path>` / `load <path>` を受け付ける。時計がなければ従来の棋譜v1、人間対コンピュータ等で時計があればCLIセッション形式を使う。親ディレクトリは作らず、保存・読込の成功イベントは棋譜履歴に残さない。
- CLIセッション形式`kaname-shogi-cli-session-v1`は、`game_record`に既存v1棋譜全体、`clock`に初期条件と先後別の残りnsを持つ。計時原点・探索制御・経過中の時間は保存しない。人間同士で時計つきファイルを開いた場合も時計値を保持し、再保存時に同形式を使う。
- CLIは時計つき形式と既存棋譜v1の両方を読み込む。コンピュータ参加時に時計なしv1を読むと、そのCLI起動時に入力した初期条件から双方の時計を作る。人間同士では時計を作らない。保存・読込・人間の待ち時間を時計から差し引かない。

## 公開操作とエラー

- `GameRecord.to_payload/from_payload` は既存v1形式の変換と検証済み履歴の再適用を行う公開操作。`GameRecord.save/load`もこの本体へ委譲する。
- `CliSession.save/load` は棋譜v1とCLIセッションの保存単位を扱う。時計つきセッションでは棋譜・外側形式・時計値すべてを検証してから新しいセッションを返す。CLIは成功後に現在状態を置き換える。
- `GameRecord.save(path)` はJSON値への変換を先に終えてからファイルへ書き込む。保存先の不存在・権限・書込み失敗は `OSError`。
- `GameRecord.load(path)` は検証済みの開始局面から新しい `GameRecord` を作り、`apply_move` / `apply_drop` で履歴を順に再適用する。時計つき外側形式の読込はCLIの`CliSession.load`を使う。
- 不正JSON、形式識別子・キー・型・座標・列挙値・持ち駒枚数の不正、重複マス、不合法な履歴は `ValueError`。
- 読込失敗時に、呼び出し側がすでに持つ記録は変更しない。
- CLIの読込は完全に成功したときだけ対局中の `GameRecord` を新しい記録へ置き換え、読込局面を表示して、その手番の担当へ進む。失敗時は既存記録を保ち、同じ人間手番で再入力する。

## 今回の対象外

SFEN、USI、時計の計時原点・終了時刻、自動保存、新しいプロセス起動時の自動再開、原子的ファイル置換、複数形式の後方互換、公式棋譜の配布・利用は扱わない。時計つきセッション形式を旧版の`GameRecord.load`で直接読める保証はなく、CLIの`load`窓口を使う。
