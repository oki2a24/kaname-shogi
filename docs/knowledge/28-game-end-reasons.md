# 終局理由の拡張：参照メモ

更新日：2026-09-23

## 将棋の規則

日本将棋連盟の対局規則第6条第1項は、対局が詰みまたは相手の投了によって終了すると定める。第2条第4項は、相手の玉を詰ました対局者が勝利し、詰まされた対局者が敗北することを定める。公式の規則では、投了は詰みを待たずに敗北を認める終局である。

出典：[日本将棋連盟「対局規則」](https://www.shogi.or.jp/match/taikyoku_rules/)、[日本将棋連盟「王手と詰み」](https://www.shogi.or.jp/knowledge/shogi/04.php)

## 第35回のCLI仕様

- `resign` だけを、半角ASCIIの投了入力として受け付ける。
- 投了時点の `Position.side_to_move` を投了側とし、相手を勝者として表示する。
- 先手なら `先手が投了しました。後手の勝ちです。`、後手なら `後手が投了しました。先手の勝ちです。` と表示する。
- 投了は局面、手番、持ち駒を変更せず、局面の再表示や次の入力を行わず終了する。
- 入力前に詰みを確認する。詰みなら投了入力を受け付けず、詰みの勝者表示を優先する。
- EOF（Ctrl-D）とCtrl-Cは投了ではなく、勝敗なしで `入力を終了しました。` と表示する。

## 実装上の境界

`_ResignCommand` は投了入力を表すCLI内部のデータであり、盤面を変更する操作ではない。`parse_command` は文字列を指示へ変換し、`run_game` は詰み確認・入力・投了表示・既存の合法手適用・再入力を担当する。`is_game_over(position)` は局面から判定できる詰みだけを返し、投了を `Position` や `movegen.py` に混在させない。

千日手、持将棋、入玉、時間切れ、反則勝敗、待った、履歴、棋譜、USI/SFENは対象外である。
