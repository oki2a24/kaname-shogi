# CLIでの指し手入力と対局進行：参照メモ

更新日：2026-09-23

## 今回の入力形式

- 盤上移動は `move <元の筋> <元の段> <先の筋> <先の段> [ + ]` とする。例：`move 7 7 7 6`。
- 成る場合だけ末尾に半角 `+` を付ける。強制成り・成れない成りは `apply_move` が判定する。
- 駒打ちは `drop <歩|香|桂|銀|金|角|飛> <筋> <段>` とする。例：`drop 歩 5 5`。
- 操作語と `+` は半角ASCII。区切りには半角・全角を含むPythonのUnicode空白、筋段には半角・全角数字を使える。
- USIの `7g7f` や `P*5e` は今回採用しない。USIは将来の接続テーマで扱う。

## 対局進行

- `run_game` は初期局面を表示し、入力を一手ずつ解析する。
- 解析後の盤上移動は `apply_move`、駒打ちは `apply_drop` へ委譲する。CLIで合法性を重複判定しない。
- 形式エラーと既存操作の `ValueError` は、理由を表示して局面を変えず同じ手番で再入力する。
- 成功した手の後に局面を表示し、`is_game_over` が真なら詰みと勝者を表示して入力を止める。
- EOFとCtrl-Cは勝敗や投了ではなく、「入力を終了しました。」を表示して正常終了する。
- 今回の終局対象は詰みだけで、投了・反則勝敗・千日手・持将棋・入玉・時間・履歴は対象外である。

## 規則との関係

日本将棋連盟の対局規則は、対局を先手から交互に進め、詰みまたは投了で終了すると定める。
二歩、行き所のない駒、打ち歩詰め、王手放置などの反則は公式戦では反則者の即負けである。
今回のCLIは、駒を動かす前に合法性を検証できる学習用入力画面として、拒否した入力を反則勝敗に
せず再入力へ戻す。この判断は将来の反則勝敗テーマと分離する。

出典：[日本将棋連盟「対局規則」](https://www.shogi.or.jp/match/taikyoku_rules/)

## 実装上の境界

- `parse_command` は文字列を内部の `_MoveCommand` / `_DropCommand` へ読むデータ操作で、局面を変更しない。
- `run_game` は表示・入力・再入力・終局停止を担う対局進行の操作である。
- `render_position` は14種の盤上駒を表示する。成駒6種は `と`、`成香`、`成桂`、`成銀`、`馬`、`竜` とする。
- 汎用 `Move` 型、棋譜履歴、評価、探索、USI/SFENは先取りしない。
