# 棋譜・局面の保存：参照メモ

更新日：2026-09-23

## 一次資料

日本将棋連盟の対局規則第12条は、公式棋戦で記録係または自動記録による採譜を行い、棋譜と時間を正確に記録すると定める。棋譜利用のガイドラインは、指し手進行を再現した盤面図と指し手順の文字情報を棋譜と説明する。

出典：[日本将棋連盟「対局規則」](https://www.shogi.or.jp/match/taikyoku_rules/)、[日本将棋連盟「棋譜利用のガイドライン」](https://www.shogi.or.jp/kifuguideline/)

## 第36回で確定した保存モデル

- `GameRecord` は開始局面、現在局面、成功した指し手列を持つ可変の対局記録である。
- `RecordedMove` は出発 `Square`、到着 `Square`、成り指定を持つ不変の盤上移動データである。
- `RecordedDrop` は基本駒種と到着 `Square` を持つ不変の駒打ちデータである。
- 合法性は既存の `apply_move` / `apply_drop` に委譲し、成功した後だけ履歴と現在局面を更新する。
- 失敗した操作、入力形式エラー、投了、EOF、Ctrl-Cは指し手履歴へ追加しない。
- 開始局面・現在局面の公開値は独立複製を返す。`position_at(move_count)` は開始局面から先頭の指定手数を再適用して新しい局面を返す。
- `run_game` は詰み・投了・EOF・Ctrl-Cのいずれでも `GameRecord` を返す。

## 今回の対象外

ファイル保存・読み込み、時間記録、履歴表示コマンド、SFEN、USI、千日手、持将棋、入玉、時間切れ、反則勝敗、探索、評価は扱わない。外部形式への変換は、内部の保存モデルを理解した後の別テーマとする。
