# 通常対局CLIの進行：参照メモ

## 担当・開始時計

`python3 -m kaname_shogi`は対局形式を選び、人間対コンピュータでは先手が人間、後手がコンピュータとして開始する。コンピュータ参加時だけ、一手選択方針、初期持ち時間（分）、秒読み（秒）を対局前に決める。空欄の初期値は10分・30秒で、持ち時間と秒読みの両方を0にはできない。人間同士には時計や探索予算JSONを求めない。

コンピュータ側の先後別残り時間はCLIがnsで保持し、各手の探索予算へ渡す時だけmsへ切り捨てる。探索の開始は思考中表示の後、予算作成と探索用局面取得の前。終了時刻は探索が返った直後に読む。人間の入力、棋譜保存・読込、探索結果の表示、着手適用にかかった時間は差し引かない。

## 探索・時計・表示

コンピュータの一手はUSIと同じ`game_search.search_move`、公開`calculate_search_budget`、`SearchControl`を使う。CLIは先後別時計の更新と返却後の時間切れ判定を担い、許容時間を超えていれば探索結果の手を適用せず時間切れ負けにする。時間内の`INTERRUPTED`手は通常停止の予備手として使い、`COMPLETE`で手がなければ投了、`SUPPRESSED`は手や勝敗へ変換しない。

コンピュータ手の前にCLI独自の詰み判定や全合法手生成を行わない。人間手番の前は既存`is_game_over`で詰みを確認する。表示する探索状態は「完了」または「通常停止」で、消費時間・担当側の残り時間と返却手を表示する。完了深さ・評価値・手の由来・停止理由は表示しない。停止確認は協調方式のため、期限ちょうどの終了、一定時間内の応答、深さ4の完了は保証しない。

## 保存と読込

人間担当の入力中に`save <path>` / `load <path>`を受け付ける。時計がある棋譜は`CliSession`の`kaname-shogi-cli-session-v1`で棋譜v1と時計値を一ファイルへ保存する。時計なしの新規棋譜・人間同士の棋譜は既存`kaname-shogi-game-record-v1`を維持する。旧v1は読込可能で、コンピュータ参加時はCLI起動時に選んだ初期条件から双方の時計を作り、その旨を表示する。保存済み時計のある棋譜は設定と先後の残りnsを復元し、人間同士で開いた場合もその値を保持する。モード・一手選択方針・予算JSONは読み込んだ棋譜から変更しない。

不正な時計・棋譜・履歴・ファイルを読んだ場合、現在の棋譜と時計を両方保って同じ人間手番へ戻る。終了理由や時計の経過時間は棋譜履歴・セッション保存へ含めない。保存中、読込中、CLI終了中の時間は差し引かない。

## 乱数と履歴

`run_game`は`random.Random`を任意に受け取る。省略時は対局開始時に一個だけ生成し、その局の全自動手で使い回す。固定種を注入すれば、同じ局面と入力に対する自動手列を再現できる。人間・コンピュータ双方の成功した`move` / `drop`だけを手番順に記録し、担当者情報と終局理由は履歴に加えない。
