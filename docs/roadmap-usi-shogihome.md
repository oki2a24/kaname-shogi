# ShogiHomeで対局するためのロードマップ

作成日・本人承認日：2026-10-02。これは複数の学習テーマの順序と到達条件を示す記録であり、各テーマの設計仕様や実装計画ではない。各テーマの対象・表現・検証方法は着手時に確認し、必要な承認を得てから実装する。

## 次の到達点と選定理由

手元のMacでShogiHomeのデスクトップ版を使い、息子が盤面から指す・打つ操作をして、`kaname-shogi` の弱いエンジンと平手から対局できるようにする。最初の実地確認では、人間の着手とエンジンの合法手がGUI上で交互に進み、投了などで対局を終了できることを確かめる。未実装の将棋規則まで、この到達点で完成したとは扱わない。

現在のCLIは対局・保存・読込ができるが、`move` / `drop` の文字入力が煩雑で、息子が気軽に指せる段階に達していない。本人は自作ブラウザUIにも将来挑戦したいと考えているが、次は既存GUIで早く遊べることを優先し、既存のUSIを接続方式として選んだ。評価関数・探索による強化は、最初のGUI対局を試した後に必要性を見直す。

## 現在の土台と一次資料

- `GameRecord` は成功手を保持・再適用し、`legal_moves` と `choose_weak_move` は合法手の列挙と弱い一手選択を行う。CLI固有の文字入力と表示は `cli.py` と `display.py` にある。
- [将棋所のUSI説明](https://shogidokoro2.stars.ne.jp/usi.html)によると、GUIとエンジンは標準入出力で通信する。平手の局面は `position startpos moves ...` で送れ、`go` に対して `bestmove` を返す。
- [ShogiHome公式案内](https://sunfish-shogi.github.io/shogihome/)はmacOSのデスクトップ版とUSIエンジンの利用を案内する。今回の接続先はデスクトップ版とする。
- [ShogiHomeのエンジン登録手順](https://github.com/sunfish-shogi/shogihome/wiki/%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%B3%E7%99%BB%E9%8C%B2%E6%89%8B%E9%A0%86)と[スクリプト起動条件](https://github.com/sunfish-shogi/shogihome/wiki/%E3%82%B7%E3%82%A7%E3%83%AB%E3%82%B9%E3%82%AF%E3%83%AA%E3%83%97%E3%83%88%E3%82%84%E3%82%A4%E3%83%B3%E3%82%BF%E3%83%97%E3%83%AA%E3%82%BF%E5%9E%8B%E8%A8%80%E8%AA%9E%E3%81%A7%E3%82%A8%E3%83%B3%E3%82%B8%E3%83%B3%E3%82%92%E5%AE%9F%E8%A1%8C%E3%81%97%E3%81%9F%E3%81%84%E6%96%B9%E3%81%B8)には、macOSでインタプリタ型エンジンを登録する際のシバンと実行権限が示されている。

## 一回一テーマの順序

各行は独立した学習テーマの候補である。前のテーマの設計・実装・検証・レビュー・記録・理解確認を終えてから次へ進み、実際に観察したShogiHomeの通信に応じて後続の範囲を見直す。

| 順 | テーマ | その回で確かめる到達条件 |
| ---: | --- | --- |
| 1 | ShogiHomeとUSIの接続範囲を確定する | 第54回でMac版ShogiHome 1.28.1の起動・Pythonスクリプト登録と、平手の1手後から投了終了までの通信を実機観測した。必要コマンドと後続の未確認範囲を記録済み。製品コードは変更しない。 |
| 2 | USIの指し手表記を内部の一手と対応させる | 筋・段、成り、駒打ちについて、USIの文字列と既存の `BoardMove` / `DropMove` の対応を確認できる。CLIの入力書式は変えない。 |
| 3 | USIの平手手順から局面を再現する | `position startpos moves ...` を読み、成功手を既存の局面適用処理で順に再現する。手番、盤面、持ち駒が手順どおりになる。ShogiHomeが最初の対局で `position sfen` を送る場合は、必要なSFEN入力を別テーマとしてこの前に追加する。 |
| 4 | USIエンジンとして一手を返す | 起動後の `usi` / `isready` / `usinewgame`、局面通知、`go` / `bestmove`、`gameover` / `quit` のやり取りを、標準入出力で確認する。既存の弱い選択器から合法な一手を返し、合法手がない場合もUSIの応答を返す。応答の改行・flushを含め、プロトコル以外の表示を標準出力へ混ぜない。 |
| 5 | ShogiHomeから実際に対局する | MacでPythonエンジンを登録して平手対局を開始し、盤面のクリック操作、エンジンの応手、投了などによる終了を確認する。起動・登録手順と見つかった互換性上の課題を記録する。 |

## 第1テーマ（2026-10-02）の確認結果

- 使い捨ての実行可能PythonスクリプトをShogiHomeのエンジン設定から登録し、対局用エンジンとして選択できた。
- 実機では `usi`、`setoption name USI_Hash value 32`、`setoption name USI_Ponder value true`、`isready` / `readyok`、`usinewgame` を確認した。
- 先手人間が７六歩を指した後、`position startpos moves 7g7f` と時間付き `go` が送られた。`bestmove resign` を受けたShogiHomeは `gameover lose` と `quit` を送って対局を終えた。
- エンジンが合法な指し手を返すこと、複数手の往復、SFEN局面、先読み・停止系コマンドは未確認。詳細と証拠は[第54回学習記録](learning/54-usi-shogihome-connection-scope.md)に記録する。

## 範囲を決める節目

- 第54回で平手1手後の `position`、時間付き `go`、初期値の `setoption` を実機確認した。合法な応手、複数手の全履歴、SFEN、先読み・停止系は未確認のまま後続テーマへ渡し、仕様にある全コマンドを先回りして実装しない。
- `position startpos moves ...` が使えるなら、任意局面のSFEN相互変換を最初の前提にしない。`position sfen` が必要と判明した場合は、必要な入力範囲を独立テーマにして承認を得る。
- 対局中の時間・先読み・評価値表示は、最初の到達点では必要性を調べて範囲を決める。既存のCLI対局、専用JSON保存、将棋規則を変更する理由にはしない。
- 各実装テーマで、対象の振る舞いをテストし、全体テスト、USIの入出力確認、独立レビューを行う。GUIでの最終確認はテーマ5で実施する。
