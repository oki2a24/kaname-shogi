# 引き継ぎ：最弱モードを残す難易度選択の最小設計

## 最終目標

現行の一様ランダム選択を最弱の選択肢として残し、必要なら別の選択方針を難易度として選べるようにするため、まず最小仕様を設計する。今回選ばれたテーマは設計であり、製品コード・テスト変更やShogiHome実機操作は含まない。

## 完了事項と選定理由

- 第62回「ShogiHome接続手順書とCodexスキルを作成する」は完了し、実証結果・理解確認・完了後の案内更新までローカル `main` にコミットした。
- 本人は候補「最弱モードを残す難易度選択の最小設計」を次テーマとして選び、新しいセッションで始めることを希望した。
- 直前に「駒得評価の最小仕様を設計する」はエンジンを強くする内容か質問があった。回答として、実装すれば駒得を意識する強化方向だが、仕様を設計するだけでは動作は変わらず、強さの向上も保証しないと説明した。
- 本人の希望は、最弱の将棋エンジンを残し、難易度選択などで切り替えられるようにすること。したがって、駒得評価を現行方針の置き換えとして扱わず、追加候補として検討する。
- 難易度を選択する利用面は未決定。候補はShogiHome、端末CLI、両方。直前のアシスタントはプロジェクトのGUI対局目標を理由にShogiHomeを仮推薦したが、本人の選択は得ていない。新セッションでこの点から一問ずつ相談し、推薦を確定事項にしない。
- プロセスは `superpowerssuperpowers:brainstorming` と `superpowerssuperpowers:roadmap-management` を使う。選択面が未決で、USIとCLIの境界に関わる可能性があるため、設計開始時点ではArchitectural design pathと分類した。利用面が決まったら分類を見直してよい。

## 現行コードの物理的な基点

- `kaname_shogi/movegen.py` の `choose_weak_move(moves, rng)` は、合法手タプルから `rng.choice(moves)` で一様ランダムに一手を返す。合法手が空なら `None` を返す。乱数器を渡す設計により、テストの再現性を保つ。
- `kaname_shogi/cli.py` の `GameMode` と `choose_game_mode` は、人間対人間・人間対コンピュータ・コンピュータ対コンピュータの担当形式を選ぶ。これはエンジンの強さ・難易度を選ぶものではない。`_run_computer_turn` は現在 `choose_weak_move` を直接呼び出す。
- `kaname_shogi/usi_engine.py` の `run_usi_engine` は `go` に対して `choose_weak_move` を直接呼び出す。現在 `setoption` は無視され、エンジン側からUSIオプションを宣言していない。ShogiHomeで難易度を選ぶ案はUSI境界にも関係する。
- 現行仕様の要約は[USIエンジンの一手応答](knowledge/usi-engine-response.md)にある。設計では、現行ランダム選択の維持と新方針の責務境界を混同しない。
