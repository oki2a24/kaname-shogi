# 第70回予定テーマ開始時点の引き継ぎ：SFEN手数欄が `4` から `1` になった理由を調べる

## 🎯 最終目標

第69回のShogiHome実機確認で観測された、貼り付け入力の4欄SFENでは手数が `4` だったのに、ShogiHomeから `kaname-shogi` へ送られたUSI `position sfen` では手数が `1` だった差について、どの段階で・なぜ生じたかを根拠に沿って調べる。ShogiHomeの画面貼り付けが受け付けた内容、ShogiHome内部の棋譜・局面、エンジンへ出したUSIコマンドを別々の境界として扱う。

## ✅ 選定理由と背景

本人は次テーマに **「SFEN手数欄が `4` から `1` になった理由を調べる」** を選び、新しいセッションの準備を依頼した。これは第69回完了後の候補2である。

第69回は、画面へ第68回と同じ4欄SFENを貼り付けた後、ShogiHome 1.28.1の時計ありローカル対局を一回行った。画面・棋譜では入力と同じ盤面・後手番・持ち駒なしが保たれ、エンジンの合法手 `9a9b`（☖９二香）が表示された。しかしUSIログの `position sfen` の手数欄は入力の `4` でなく `1` だった。手数欄が変わった場所と理由は調べていない。局面の盤面・手番・持ち駒・着手が一致したことから、手数欄まで保持されたとは推定しない。

## 📌 すでに確認できている事実

- 第69回の入力SFEN：
  `lnsgkgsnl/1r5b1/pppppp1pp/6p2/9/2P4P1/PP1PPPP1P/1B5R1/LNSGKGSNL w - 4`
- 当該セッションのUSIログ：

  ```text
  > position sfen lnsgkgsnl/1r5b1/pppppp1pp/6p2/9/2P4P1/PP1PPPP1P/1B5R1/LNSGKGSNL w - 1
  > go btime 600000 wtime 600000 byoyomi 30000
  < bestmove 9a9b
  ```

- 対象ログの保存場所：`/Users/oki2a24/Library/Logs/electron-shogi/usi-20261008_192440.log`。第69回ではこの一セッションの関連部分だけを読んだ。ログの共有・削除はしていない。
- ShogiHome画面の棋譜では、後手の `☖９二香` が一手目として反映された。入力盤面・手番・持ち駒に対して合法な手だった。
- 第67回コードは `position sfen <SFEN>` と `moves` 付きの形式を解析する。`parse_usi_position` の結果は手数を含むデータだが、USIエンジン状態は `Position` だけを保持する。今回ログに出た手数 `1` は、エンジンの `bestmove` より前にShogiHomeが送信した文字列上ですでに `1` だった。これだけではShogiHomeが値を置き換えた原因や段階までは確定できない。
- 第69回では持ち時間0・秒読み0の開始がShogiHomeに「持ち時間と秒読みが両方とも0です」と拒否された。本人の指示で持ち時間10分・秒読み30秒にして一回開始できた。この値を時計条件の既定値や推奨値とみなさない。
- D69後、USI通信ログをOFFにして保存したが、設定はShogiHome再起動後に反映される。未保存の結果棋譜を残すため再起動を保留した。直近の観察では棋譜が未保存のまま残り、USI稼働数は0だったが、これは現在の状態を保証しない。設定がOFFへ反映される前にエンジンを起動しない。再起動で棋譜が失われるかもしれない状態を無断で保存・削除・再起動しない。
