# プロジェクトの方向性

## 目的と進め方

将棋の内部処理を自分で理解しながら、小さく学び実装する。強さや完成速度より「なぜ必要か」を説明できることを優先し、息子と成長を共有する。[背景](01-project-background.md)と[作業方針](../AGENTS.md)を基準とする。

今後も新しいエンジンの一手選択方式を追加するときは、既存の「一様ランダム」と「一手後の駒得評価」をプレイ時に選べる方式として残す。新方式で既存方式を置き換えない。保持するのは選べる動作であり、適切な命名のために既存方式の名称を改めてもよい。一様ランダムを最弱・既定値とする現行方針も保持する。2026-10-10の本人の継続的な希望として、[次段階設計の学習記録](learning/evaluation-next-stage.md)に根拠を記録した。

盤面・駒・指し手・合法手判定・対局進行・将来の探索は学習の中心として自作する。GUIとの通信はUSI、局面表記はSFENを用い、必要な範囲を段階的に扱う。

現在の機能・未対応は[README](../README.md)、確定仕様と各到達点の根拠は[文書索引](README.md)から確認する。実機確認は特定版・局面の実測であり、全互換性や棋力を保証しない。

## 評価・探索へ進む位置付け

対局できる土台から指し手の改善へ、学ぶ中心を移す節目である。現行のMaterialは一手後の駒得差を比較し、相手の応手は読まない。「一手駒得評価の次段階を設計する」で、自分一手と相手一手を読む設計を承認し、main統合・検証・理解確認まで完了した。駒価値を維持して応手を読む範囲を増やし、改善仮説を検証して根拠が得られた変更を採用する。[設計書](plans/2026-10-10-evaluation-next-stage-design.md)は確定し、通常の二手比較のタスク1を実装・検証・独立レビューした。main取り込みと理解確認が残り、CLI・USIから選ぶ対応と境界の網羅検証、棋力向上の実証はこれからである。

本人はその前に文書整理を選定した。章番号・学習回番号は未決定。過去の第76回予定という表記は当時の記録として保持する。追加の細かな整備を自動的に強化開始の前提へ積み増さない。
