# プロジェクトの方向性

## この段階で決めたこと

`kaname-shogi` は、将棋の内部処理を自分で理解しながら実装していくプロジェクトです。

盤面、駒、指し手、合法手の判定、対局の進行、そして将来の探索などは、学習の中心として自作します。一方で、将来的に既存の将棋GUIと接続できるよう、広く使われているUSIをエンジンとGUIの通信方法として採用する方向です。SFENは局面を文字列で表す標準的な形式として扱います。

これは「インターフェースは既存の標準に合わせ、中身は自分で作る」という考え方です。USIやSFENへの対応は必要になった段階で進め、最初からすべてを実装することは求めません。

## 最初のゴール

最初の実装上の到達点は、コマンドラインで動く非常に弱い将棋プログラムです。

強さやGUI対応より先に、次のような基本を理解しながら形にすることを重視します。

- 将棋の盤面と駒を扱えること
- 駒の動きと基本的な対局ルールを学び、プログラムに反映すること
- 局面を表示し、手を選べること
- 小さくても対局の流れを最後まで動かせること

この段階では、完全な強さや実戦的な指し手は目標ではありません。「なぜその処理が必要か」を説明できることを優先します。

## 段階的な発展の見通し

順番や内容は実装を通して見直しますが、今はおおよそ次の流れを考えています。

1. 将棋のルールを学びながら、CLIで動く最小の対局プログラムを作る。
2. 合法手の扱いと対局の進行を整え、弱くても一貫して指せるようにする。
3. 局面を評価し、簡単な探索を導入して、少しずつ強くする。
4. USIに対応し、既存の将棋GUIから対局できるようにする。
5. 息子と対局したり、成長を比較したりできる形へ育てる。

各段階で立ち止まり、理解・楽しさ・必要性を確かめます。後の段階を理由に、最初のプログラムを必要以上に複雑にはしません。

## 第32回完了時点の見直し

玉が王手を受けているか、手番側に合法手があるか、詰みで終局かを最小範囲で判定できるようになった。次は、既に実装した駒打ちと詰み判定を組み合わせる打ち歩詰めを小さなルールとして扱う。その後にCLIでの指し手入力と対局進行へ進み、終局時に入力を止める流れを作る。

## 第33回完了時点の見直し

持ち歩で解除不能な王手をかける打ち歩詰めを拒否できるようになった。打ち歩詰め確認中の合法手探索は、打ち歩詰め確認だけを無効にする内部経路で循環を避け、二歩・行き所のない駒・王手放置などの既存規則は維持する。次はCLIでの指し手入力と対局進行へ進み、局面を表示しながら終局時に入力を止める流れを作る。

## 第34回完了時点の見直し

独自の `move` / `drop` 形式で入力を解析し、合法手適用、エラー理由の表示と同じ手番での再入力、局面表示、詰み時の勝者表示と入力停止までを、先手・後手とも人間が入力するCLI対局ループとして実装・テストした。実際の標準入力から終局までの人間対人間プレイは、まだ確認していない。公式対局の反則負けを再現するのではなく、学習用に入力を局面変更前に検証できる構成を選んだ。次は詰み以外の終局理由を小さく追加する候補を検討する。

## まだ決めていないこと

以下は、これから検討・設計する事項です。

- 使用するプログラミング言語と開発環境
- 盤面、駒、持ち駒、指し手をどう表すか
- どのルールを最初の対象範囲にするか
- 局面の表示や入力の方法
- テストの進め方
- USIとSFENを導入する具体的な時期と範囲
- 探索、評価、強化の方法
- 公開方法とライセンス

これらは、実装を始める前に必要な範囲で一つずつ決めます。この文書は設計を固定するものではなく、判断の出発点です。
