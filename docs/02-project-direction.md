# プロジェクトの方向性

## 目的と進め方

将棋の内部処理を自分で理解しながら、小さく学び実装する。強さや完成速度より「なぜ必要か」を説明できることを優先し、息子と成長を共有する。[背景](01-project-background.md)と[作業方針](../AGENTS.md)を基準とする。

今後も新しいエンジンの一手選択方式を追加するときは、既存の「一様ランダム」と「一手後の駒得評価」をプレイ時に選べる方式として残す。新方式で既存方式を置き換えない。保持するのは選べる動作であり、適切な命名のために既存方式の名称を改めてもよい。一様ランダムを最弱・既定値とする現行方針も保持する。2026-10-10の本人の継続的な希望として、[次段階設計の学習記録](learning/evaluation-next-stage.md)に根拠を記録した。

2026-10-14の構成調査では、現行三方式のファイル配置を維持することを本人が確認した。本人は、より複雑になると見込む次のレベルの将棋エンジンでは、方式別ファイルへ分けられたらよいと希望した。次のレベルの範囲や具体的な分割境界は未決定であり、今回の確認は構成変更の承認ではない。[調査記録](learning/three-policy-architecture.md)。

2026-10-17の本人希望により、現行の「二手先読み」も選択肢として維持する。次の強化で既存三方式を置き換えない。今回の新探索では、SOLID・DRYを意図した方式別入口・共通探索・将棋接続の分離を合意し、開発用比較まで実装した。既存三方式の全面分割は保留した。[学習・実装記録](learning/engine-improvement-stage-design.md)。

盤面・駒・指し手・合法手判定・対局進行・将来の探索は学習の中心として自作する。GUIとの通信はUSI、局面表記はSFENを用い、必要な範囲を段階的に扱う。

## 評価・探索へ進む位置付け

対局できる土台から指し手の改善へ、学ぶ中心を移す節目である。現行のMaterialは一手後の駒得差を比較し、相手の応手は読まない。「一手駒得評価の次段階を設計する」で、自分一手と相手一手を読む設計を承認し、main統合・検証・理解確認まで完了した。駒価値を維持して応手を読む範囲を増やし、改善仮説を検証して根拠が得られた変更を採用する。[設計書](plans/2026-10-10-evaluation-next-stage-design.md)は確定し、通常の二手比較のタスク1を実装・検証・独立レビューした。main取り込み・取り込み先検証・最後の理解確認まで完了した。承認済み計画タスク2の詰み・境界・枝独立性も実施・main統合・検証・理解確認まで完了した（[枝独立性の記録](learning/two-ply-branch-independence.md)）。CLIの三択対応はmain取り込み・検証・最後の理解確認まで完了（[CLIの記録](learning/cli-three-policies.md)）。USIの三択通知・受付はmain統合・検証・最後の理解確認まで完了（[USI通知・受付の記録](learning/usi-three-policies.md)）。新値固有の局中固定・次局継承もmain統合・取り込み先検証・最後の理解確認まで完了（[実施記録](learning/usi-policy-lifetime.md)）。新値後の未知値保持はmain取り込み・取り込み先検証まで完了し、理解確認完了（[実施記録](learning/usi-invalid-value.md)）。関数境界の実応答の検証記録は[実施記録](learning/usi-function-response.md)を参照する。新方式設定後の実プロセス応答は既存pipeケースで検証した（[実施記録](learning/usi-process-response.md)）。選択時間は教材・平手初期局面の三方式各3回を計測した（[測定条件と結果](learning/selection-timing.md)）。ShogiHomeの平手一例の待ち時間は本人が許容できると判断し、タスク5の最終確認・main統合・最後の理解確認まで完了した（[実施記録](learning/two-ply-final-check.md)）。他局面・秒読み後の時間保証と棋力向上の実証は未実施である。
