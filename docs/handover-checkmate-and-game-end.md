# 第32回「詰み・終局判定」引き継ぎ

作成日：2026-09-23

## 最終目標

第31回で追加した王手判定と自玉の安全確認を土台に、王手を受けた側に王手を防ぐ合法手が一つもない局面を詰みとして判定し、詰みを含む終局判定の最小範囲を設計・実装する。将棋のルール上の詰みと、今回どのAPI・局面状態を終局と呼ぶかを区別して、説明できる小さな実装にする。

## 次テーマを選んだ理由

- 第31回で `is_in_check` と盤上移動・駒打ちの自玉安全確認が実装済みであり、詰み判定へ直接つながる。
- `docs/next-topics.md` の候補では、合法手を全て調べて王手を防ぐ手がないか確認する「詰み・終局判定」が、打ち歩詰めより小さい前提拡張である。
- 打ち歩詰めは、歩を打った結果が詰みかどうかを判定する必要があるため、先に詰み・終局判定を学ぶ。
- CLI入力、履歴、評価、探索、USI/SFENは今回のテーマへ先取りしない。

## 完了した事項と意思決定の背景

- [済] `Board.copy()`、`Hand.copy()`、`Position.copy()` を追加した。
  - **Why:** 盤面、持ち駒、手番は可変状態であり、試し指しが実際の局面を変更しないよう独立コピーを作る必要がある。`Square` と `Piece` は変更不可の値なので共有する設計にした。
- [済] `is_in_check(board, side)` を追加した。
  - **Why:** 既存の14種類の駒候補生成を再利用すれば、成駒・先後・遮蔽・桂馬の飛び越しを別の利き計算として重複実装せずに王手を読める。玉のない部分局面は既存テストとの互換性のため `False` とした。
- [済] `apply_move` と `apply_drop` に複製局面への試し指し・試し打ちを追加した。
  - **Why:** 指した後の局面で自玉が相手の利きに入るかを確認する必要がある。安全なときだけ本物の局面へ一度適用し、反則時は盤面・持ち駒・手番を変更しない。
- [済] 全14駒種、先後、遮蔽、桂馬、隣接玉、玉なし、複数攻撃、局面不変、代表的な合法・反則の決定的テストを追加した。
  - **Why:** 教育目的で再現可能な標準ライブラリのテストを優先した。レビューで追加ケースの余地は確認したが、今回の範囲ではファズテストを導入しない判断を記録した。
- [済] 設計承認前にコード・テストを書かず、TDDのRed → Green → Refactorを実施した。
- [済] タスク単位と累積の独立コードレビューを実施した。
  - **結果:** 実装コードのCritical 0、Important 0。Minorの追加テスト余地は第31回学習記録に記録した。
- [済] `main` へ取り込み、全157テスト、CLI、`git diff --check` を取り込み後に確認した。
- [済] 最後の理解確認で、複製局面を使う理由と、試し指し後に王手なら反則とする判定を本人が説明した。
