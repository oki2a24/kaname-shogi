## ✅ 完了した事項と意思決定の背景

- [済] 第43回「文書構成の棚卸しと入口設計」を完了した。
  - **Why:** READMEが目的、現在地、利用方法、個別API、文書一覧を兼ね、42件の学習記録、
    30件の知識メモ、二系統の設計書、18件の引き継ぎから必要な資料を選びにくく
    なっていたため。
  - **Crucial:** 問題は文書数そのものではなく、現在情報、確定知識、判断経緯、
    過去時点の状態を選び分ける入口がないことである。
- [済] READMEを人間向けの第一入口にすると合意した。
  - **Why:** 初めて訪れた人が、目的、現在できること、実行方法、CLI操作、テスト、
    主要文書へ短く到達できるようにするため。
  - **Crucial:** 個別APIの長い説明や各回の累積履歴はREADMEの中心責務にしない。
- [済] `docs/README.md` を単一の文書索引として新設する設計を承認した。
  - **Why:** ディレクトリ別索引は更新箇所を増やし、自動生成は文書の意味を別管理する
    必要があるため、現在の規模には単一索引が最小である。
  - **Crucial:** 索引は全資料を最初から読むためではなく、目的に合う最小限の資料を
    選ぶための入口である。
- [済] 文書索引はテーマ・学習回を主軸にすると合意した。
  - **Why:** 一つのテーマに対応する学習記録、知識メモ、設計仕様、実装計画、引き継ぎを
    横断してたどれるようにするため。
  - **Crucial:** ファイル番号ではなく題名とテーマを主な識別手段にし、存在しない
    文書種別にはリンクを作らない。
- [済] 既存文書を移動・改名しないと合意した。
  - **Why:** 既存リンクを壊す大きな変更を避け、入口の改善だけを小さく実施するため。
  - **Crucial:** `docs/design/` は初期設計の履歴、`docs/plans/*-design.md` は現在方式の
    設計仕様と説明する。知識メモ番号 `32` の重複も今回は改名しない。
- [済] 古い内容の是正をナビゲーション改善から分離した。
  - **Why:** 入口とリンクの変更に、既存文書の意味を変える修正を混ぜないため。
  - **Crucial:** `docs/02-project-direction.md` の決定済み事項や `docs/next-topics.md` の
    整理は、ナビゲーション改善完了後の別テーマで扱う。
- [済] AI向けの段階的な読み分けを必須要件にした。
  - **Why:** 現在の仕様を知りたいだけのときに、すべての学習記録や過去の引き継ぎを
    読むと、古い状態と不要な経緯が混ざり、コンテキスト汚染につながるため。
  - **Crucial:** 現在仕様は知識メモ、理由は学習記録、実装時は承認済み設計と計画、
    再開時は `AGENTS.md`、README、`docs/resume.md`、現役引き継ぎ、Git状態を読む。
- [済] 設計仕様と学習記録を本人が承認し、最後の理解確認まで完了した。
  - 設計仕様：`docs/plans/2026-09-27-repository-document-navigation-design.md`
  - 学習記録：`docs/learning/43-document-structure-audit.md`
  - **Crucial:** 第43回では設計だけを行い、README、索引、コード、テストは変更していない。
- [済] 次テーマとして「文書ナビゲーションの最小改善」を本人が選んだ。
  - **Why:** 承認済み設計を実際の入口へ反映し、人間の探しやすさとAIの
