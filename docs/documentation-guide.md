# 文書更新ガイド

## 目的と基準

人間とAIが現在地・確定仕様・次テーマへ迷わず到達でき、履歴を現在情報と混同しない状態を保つ。[AGENTS.md](../AGENTS.md)の承認・学習・検証・統合の規則を前提とする。本書を理由に承認や検証を省略しない。

## 情報の置き場所

| 情報 | 主な保存先 | 他の文書での扱い |
| --- | --- | --- |
| 利用可能な機能・制約・実行・開発手順 | ルートREADME | 詳細仕様は知識・設計へリンク |
| 資料を探す目的とテーマ別の参照先 | docs/README.md | 進捗や各回の説明を重複させない |
| 現在テーマ・承認段階・未完了・次の行動 | docs/resume.md | 索引は入口へのリンクに留める |
| 現在の選択・後続候補・保留理由 | docs/next-topics.md | 過去の選択待ちを現在欄に残さない |
| 長期方針・到達点・次の章の位置付け | docs/02-project-direction.md | 作業ブランチや細かな進捗は置かない |
| 確定仕様・前提・制約・根拠 | docs/knowledge/・承認済み設計 | 当時の観察と現在の仕様を区別 |
| 本人回答・補足・承認・変更・検証・レビュー | docs/learning/ | 詳細経緯は入口へ複写せずリンク |
| 開始時の背景・物理状態・再開プロンプト | docs/handover-*.md | 作成時点の情報。現物と照合する |

## 段階ごとの更新

| 契機 | 更新・確認するもの |
| --- | --- |
| セッション再開 | Git状態と再開案内を照合。不一致は現在の実測を優先し、過去の承認・テストを流用しない |
| テーマ選定 | 理解確認後、候補に選定と理由を記録。再開案内へ現在テーマを反映。選定と具体案承認は別扱い |
| 具体案承認 | 学習記録に提示内容と本人の承認を区別して記録。再開案内の承認段階を更新 |
| 変更・検証・レビュー | 実際の変更、実行コマンド・結果・限界、各重大度と対応を学習記録へ。確定仕様が変わる場合だけ知識・設計・利用案内を更新 |
| コミット・main統合 | 記録確認と統合承認の有無、コミット、取り込み先の検証を記録。実施後に再開案内を更新し、理解確認が残れば未完了として示す |
| 最後の理解確認 | 一問ずつ回答を待ち、本人回答と補足を記録。回答内容を確認してからコミット。未回答を完了としない |
| 次テーマへの引き継ぎ | 本人が選定し新セッションを希望したら所定のスキルで準備。本文は新しい引き継ぎに一か所保存し、再開案内はそのプロンプト節を案内。入力前に次テーマを開始しない |

索引の該当テーマ行は文書追加時と完了時に更新する。READMEは機能・制約・使い方・開発手順が変わったとき、方向性は大きな到達点・方針変更時に更新する。テーマ完了のたびに全入口へ長文を追加しない。

## 現在情報を置き換える方法

1. 以前の現在地にある判断・回答・未確認事項が、対応する学習記録や引き継ぎに残っているか確認する。
2. 残っていない固有の情報だけを、出典と時点を付けて履歴へ保存する。今回は整理前本文を `*-history.md` に一括保全したが、毎回入口全体の複製を追加しない。
3. 再開案内の現在欄を新しい状態で置き換える。古い「現在main」「更新中」「コミット前」「次の指示」を末尾へ積み重ねない。
4. 必要な経緯へリンクし、古いプロンプトは現役の案内から外す。引き継ぎ本文は開始時の履歴として残す。

Git状態の記述には確認時点を付ける。コミット前の文書に自分自身の未確定ハッシュを予告せず、開始HEADと作業状態を記す。実測していない検証、未承認の統合、未回答の理解確認は完了扱いにしない。事後整理は事後記録と明記する。

## 履歴・リンクを守る

- 学習記録、設計判断、本人回答・補足、当時の未確認事項を削除・一律現行化しない。現在仕様が変わった場合は現行メモで説明し、過去の記録と結ぶ。
- 文書や見出しを移す前に `rg` で相対パス・見出しリンクの参照元を確認する。移動後は参照元を更新する。既存の見出しリンクがある入口には必要な案内を残す。
- 履歴は保存時点・出典・現在の指示ではないことを明記する。保存本文は原則として不変とし、訂正が必要なら訂正理由と時点を別に示す。
- 章番号・学習回番号を変更する場合は、対応表・影響・案を提示して承認を得る。新しい分類のために一括改番しない。

## 更新後の確認

- [ ] 現在テーマ・承認段階・未完了事項・次に読む資料が再開案内で分かる。
- [ ] 現在情報の重複と矛盾、古い選択待ちや未確定の完了表現がない。
- [ ] 確定仕様は知識・設計、理由は学習記録へ到達できる。索引に新しい文書が載っている。
- [ ] 移動した履歴と本人回答・補足・未確認事項が保持されている。
- [ ] 変更した文書と参照元の相対リンク・見出し参照が通る。
- [ ] `git diff --check` と差分確認を行い、変更に見合う検証と独立レビューを記録した。

文書のみの変更では全体テストの再実行を自動的な必須条件にしない。実行しない検証はその理由を記し、過去のテスト成功を今回の結果へ置き換えない。コード・実行手順の変更を含む場合は、その影響に見合う検証を選ぶ。

## ガイド自体を見直す条件

状態の混在、履歴の欠落、リンク切れ、同じレビュー指摘が再発したとき、実例と原因を確認して規則を修正する。今回の問題は[整理記録](learning/documentation-chapter.md)を参照する。規則追加だけで再発防止が済んだとせず、次の更新でチェック項目が働くか確認する。
