# 第68回予定テーマ開始時点の引き継ぎ：ShogiHome画面へのSFEN貼り付け確認

## 最終目標

ShogiHomeの画面がSFEN文字列の貼り付けを受け付け、指定した盤面を表示するかを、合意した小さな範囲で実機確認する。特に手数欄を省略した入力をどう扱うかは候補の確認事項だが、具体的な入力例・操作・確認条件は新セッションで一問ずつ決める。

このテーマは、画面への貼り付けと盤面表示の確認を中心とする。ShogiHomeから `kaname-shogi` へUSI `position sfen` を送って対局するエンドツーエンド確認は別候補であり、今回の選定に含まれない。コード変更・テスト変更も現時点では承認されていない。

## 選定理由と背景

第67回「SFEN局面変換」では、USI原案を基準にSFENの読込・正規化書出しと、USI `position sfen` の単独指定・指し手付き指定を実装した。最終理解確認後、候補のうち本人は **「①ShogiHome画面へのSFEN貼り付け確認」** を次テーマに選び、新セッションの準備を依頼した。

本人はSFENをShogiHomeでも最低限扱えるようにしたいと以前に希望している。第67回は自動テストでコードのSFEN処理を確認したが、ShogiHome画面への貼り付けは一度も操作していない。そのため、コードがSFENを読めることと、ShogiHomeの画面が貼り付けを受け付けることを区別して確認する。

第67回の最終理解確認に対する本人の回答は「責任を分離を維持するため」。`Position` は盤面・手番・持ち駒を表し、SFEN手数は `SfenPosition` が保持する。JSON棋譜は開始局面と指し手履歴を持つ別形式であり、SFEN形式へ置き換えていない。

## 合意済みの選定と未合意事項

- [選定済み] 次テーマは「ShogiHome画面へのSFEN貼り付け確認」（第68回予定）。
- [候補の最小案] SFENを画面へ貼り付けて盤面が再現されるか確認し、必要なら手数欄省略時の扱いも見る。この候補説明は、個別のSFEN、手順、確認条件を承認したものではない。
- [未合意] ShogiHomeのどの画面・機能へ貼り付けるか、何種類のSFENを試すか、手数欄を省いたケースを含めるか。
- [未合意] 盤面、手番、持ち駒、手数欄のどれを期待結果として確認するか、結果をどう記録するか。
