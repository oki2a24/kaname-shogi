## 最終目標と選定範囲

2026-10-19、前テーマ「小さい局面で全幅とαβの訪問回数を比べる」の完了後に提示した候補2「CLIに探索時間制御を加える案を学び設計する」を本人が選定した。本人は目的が一手の計算時間を短くすることか、設計がShogiHomeの新方式にも反映されるかを確認し、「待ち方の制御」であればCLI限定と考えてよいか確認した。CLI限定であり、探索アルゴリズムの高速化やShogiHomeへの直接反映は含まないと説明した後、本人はこの候補を選んだ。選択の詳しい理由は尋ねておらず、推測しない。

このテーマは**通常対局CLIの探索待ち方を学び、時間制御の設計を考える範囲**である。探索処理そのものを速くするテーマではない。目標時間・上限時間・手動中断などの具体的な方式、利用者への表示、停止時にどの結果を返すかは、既存契約を調べて学習・設計の中で検討する。候補名が選ばれたことを、個別の時間値や動作の承認と解釈しない。

対象は通常対局CLIに限る。USIエンジンやShogiHomeの時計予算・停止動作を変更する設計は範囲外であり、CLIの設計がShogiHomeへ自動的に反映されることもない。既存の探索制御をどう利用できるかは読み取り専用で確認し、共有部品への変更を提案するなら対象範囲を改めて確認する。

製品コード、テスト、設定、実装計画を変更せず、実装を開始しない。学習と設計を進め、学習記録には目的・要点・確認問題と本人回答・補足・振り返り・次回への問いを区別して残す。設計案は対象範囲・表現・確認方法を明記し、設計内容への本人確認を実装許可と扱わない。後続で実装計画を作成する場合はその内容を提示し、本人の明示承認を待ってから実装へ進む。

## 現行仕様として読んだ事項

- READMEは通常CLIを`python3 -m kaname_shogi`で起動すると案内し、通常対局CLIには時計による探索時間制御がないと説明する。
- CLIの時間制御付き反復探索コマンドは`run_controlled_iterative`であり、SFEN・最大深さ・目標ms・上限msを指定できる開発用コマンドである。通常対局CLIへ接続済みの機能ではない。
- USIの`go`は現在手番側の時計などから既存設定を使って予算を計算し、`SearchControl`を探索へ渡す。新方式FullWidth4・AlphaBeta4もUSIではこの既存時計予算と停止制御を使う。これは現在のUSI経路の説明であり、このCLIテーマの設計がShogiHomeへ反映されるという意味ではない。今回そこへ変更を加えない。
- `SearchControl`の確認点では、目標・上限・通常停止・抑制を区別し、単一の複製・利き計算・採点を強制切断しない。停止は実応答時間の保証ではない。停止時に合法予備手または最新完了結果を使う契約があるため、その意味を学んでからCLIへの案を考える。
- 参考資料：[README](../README.md)の「CLIでの対局」「USIエンジン」「時間制御付き反復探索を一回試す」、[探索停止](knowledge/search-stop.md)、[時間予算](knowledge/time-budget.md)、[USI応答](knowledge/usi-engine-response.md)、[探索比較](knowledge/search-comparison.md)。
