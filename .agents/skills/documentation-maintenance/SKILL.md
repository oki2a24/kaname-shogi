# 文書整理と継続保守

本人と生成AIが必要な指示・現在情報・履歴を見つけ、変更後も正確に保てるようにする。本人の依頼、リポジトリの指示と承認条件を優先し、整理を理由に作業範囲を広げない。

1. 最初にGit状態と対象を確認し、利用者・目的・作業規模・保護対象を把握する。既存の未完了計画や承認を再確認し、理由なくやり直さない。
2. 入口と正本をたどり、現在の仕様・記録当時の履歴・未承認の案・未検証事項を分ける。文書だけで判断せず、対象に応じてコードと最新の実施記録を照合する。
3. 本人の要求に目的達成上の改善点があるか評価し、見つかれば根拠を添えて示し、見つからなければその旨を伝える。提案は本人の選択や承認と区別し、未承認の作業を追加しない。
4. 整理前に本人回答・承認・未完了事項・出典・参照元と見出しリンクを確認する。固有情報の保全先を確かめ、安全に移せなければ移動せず時点を明示する。
5. 変更の種類から更新すべき正本・索引・記録を選ぶ。小規模な変更には相応の確認を行い、文書全体の棚卸しや新しい仕組みを無条件に追加しない。
6. 作業後は代表的な利用場面を入口から実際にたどり、関連する内容・参照先・リンク・履歴保全を確認する。自動的なリンク確認と内容の正しさを区別し、未確認範囲を記録する。

このリポジトリ固有の文書配置・更新契機・保護条件は [文書更新ガイド](../../../docs/documentation-guide.md) と `AGENTS.md` に従う。
