# ShogiHome接続

ShogiHomeでの接続・対局依頼を、現在の画面と依頼内容に合わせて安全に進めるためのスキルです。

## 手順書を読む

操作の前に、必ず [ShogiHome接続手順書](../../../docs/shogihome-connection-guide.md) を読みます。通常対局、KIFの指定局面からの再開、依頼された場合だけのUSIログ採取、停止条件、ShogiHome公式資料へのリンクは手順書を基準にします。内容と現在の画面が異なる場合は推測で続けず、差異を伝えて確認します。

操作条件の根拠には、手順書と、そのリンク先にある現行のリポジトリ知識・運用文書および公式資料を使います。学習記録、引き継ぎ、過去セッションなどの歴史資料から操作条件を補わず、それらを成果物の参照先にも加えません。

## 依頼の範囲と事前確認

- 依頼された接続確認または一局だけを対象にします。接続確認を対局へ広げず、追加対局や連続対局も始めません。
- 先後、開始局面、持ち時間・秒読み、対局数、ログ採取の要否を依頼から確定できない場合は、推測せず必要なことを一問ずつ確認します。
- ShogiHomeの版、現在の登録実行パス、現在のチェックアウトにある `kaname-shogi-usi` の実在・実行可能性を照合します。過去に使った絶対パスや別worktreeを現在も有効とみなしません。
- 未保存の棋譜や稼働中セッションがある場合、上書き・破棄・停止をせず、対象と保全方法を確認します。
- 登録先、Ponder、ログ出力などアプリに残る設定を変更する必要がある場合は、変更前の値と具体的な変更内容を示し、実行前にユーザーの明示承認を得ます。接続・対局の依頼だけから設定変更の承認を推定しません。

## 接続と対局

- 現行エンジンは `go ponder` に対応していません。`USI_Ponder` がONならその状態で対局を始めません。PonderをOFFにする具体的変更案を提示し、明示承認を得てから手順書に従います。
- 現行エンジンが受け付ける局面は、平手初期局面から1手以上を含む `position startpos moves <1手以上>` だけです。新規平手対局は人間先手・エンジン後手で始め、初手からエンジンに指させません。初手前、SFEN、駒落ち、平手初期局面以外を必要とする依頼では開始せず、現行制約を説明します。
- KIF再開では、平手初期局面からの指し手履歴があることと対象手が1手以上進んでいることを確認します。ユーザー指定の手数を棋譜上で明示選択し、その手の後の盤面と次の手番が一致してから「現在の局面」を使います。手数が曖昧な場合や盤面・手番・棋譜カーソルが合わない場合は開始しません。
- 開始後に盤面・手番・時計が依頼と違う場合、指し手や追加コマンドを送らず、表示中の状態を確認してユーザーに報告します。棋譜局面へ戻すか現在の局面から続けるかが明確でない場合は選択を待ちます。時計停止、強制終了、設定変更など承認済み範囲外の操作が必要なら、その操作と影響を説明して明示承認を待ちます。
- ShogiHomeのプロンプト欄にUSIコマンドを手入力しません。通信はログで、稼働状態は公式手順の監視機能で読み取ります。

## USIログ

ログ採取は依頼された場合だけ行います。現在値を記録し、必要なログ種別と設定変更を示して明示承認を得た後、手順書に従って有効化・保存・再起動し、必要範囲だけを確認します。採取後は記録した元の値へ戻し、保存・再起動・復帰確認を行います。ログファイルの共有、削除、外部送信は別の操作として扱い、明示依頼がなければ行いません。

通信の説明では、観測記録に含まれる `bestmove resign`、ShogiHomeの `gameover lose`、その後の別コマンド `quit` を区別します。この一例を他の対局で必須の通信列とは扱いません。

## 完了報告

依頼された範囲の接続・対局が終わったら、画面上の結果を確認し、対象セッションの終了と、ログを依頼された場合は設定の復帰を確かめてから報告します。画面・ログ・依頼内容が食い違う場合は、未確認の成功を報告せず、差異と次に必要な確認を示します。
